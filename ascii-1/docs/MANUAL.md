# Ascii–1 매뉴얼

PNG 를 ASCII 아트로 바꾸는 명령형 도구입니다. 소개는 [README](../README.md), 설치 절차는 [INSTALL.md](../INSTALL.md)에 있습니다.

- **창에서 그림 고르기, 또는 끌어다 놓기** — 선 차트 · 웨이퍼 파티클 맵처럼 바탕 · 선 · 점이 또렷한 PNG 를 글자 아트(`.txt`)로 바꿉니다
- **원본은 그대로, 결과는 덮어쓰지 않음** — 입력 옆에 `<이름>.txt`, 있으면 `<이름> (2).txt`
- **내 PC 전용** — 네트워크를 쓰지 않고, 파일은 사용자가 지정한 PNG 만 읽습니다

## 창

`python ascii-1.py` (인자 없이) 또는 `ascii-1.exe` 를 두 번 누르면 작은 창이 열립니다. 네 구역입니다.

| 구역 | 하는 일 |
|---|---|
| `01 OPEN` | `그림 열기…` (Ctrl+O) 로 PNG 를 고릅니다. 읽는 동안 `◐` 가 켜지고 창은 멎지 않습니다 |
| `02 OPTIONS` | 열 수(40–300) · 종류(자동 · 차트 · 웨이퍼) · `선을 ─ │ 로` · 글자 크기 `A−` `A+`. 바꾸면 이미 읽은 그림으로 **다시 그리기만** 합니다(다시 읽지 않습니다) |
| `03 ART` | 결과를 보여 줍니다. 가로 · 세로로 스크롤됩니다 |
| `04 STATUS` | 상태 한 줄과 `저장 (.txt)` (Ctrl+S) · `복사`. 저장은 명령줄과 같습니다 — 입력 옆 `<이름>.txt`, 있으면 덮어쓰지 않고 `<이름> (2).txt`. 그 폴더에 쓸 수 없으면 저장할 곳을 묻습니다 |

상태 기호: `●` 그렸음 · `◐` 읽는 중 · `‼` 확인 필요(그릴 것이 없음 · 종류가 안 맞음 — 저장 · 복사 꺼짐) · `×` 오류(`ERR` 칩 — 읽을 수 없는 그림 · 범위 밖 열 수). 

- 창 안으로 파일을 끌어다 놓는 것은 **지원하지 않습니다** (표준 라이브러리 `tkinter` 에는 없습니다). 그림 열기를 쓰거나, 파일을 `ascii-1.exe` 아이콘 위로 끌어다 놓으세요 — 그때는 창 없이 `.txt` 가 만들어집니다
- 파이썬에 `tkinter` 가 없으면(일부 리눅스) 창은 열리지 않고 이유를 알린 뒤 종료 코드 1 로 끝납니다. 명령줄은 그대로 돕니다. `check` 가 `창 (tkinter)  있음/없음` 을 알려 줍니다
- `python ascii-1.py gui 그림.png` 는 창을 열면서 그 그림을 바로 엽니다. `gui --selftest` 는 창을 열어 내장 그림을 읽고 그려 본 뒤 닫는 점검입니다
- exe 를 두 번 눌러 연 검은 콘솔 창은 창이 뜨면 숨깁니다(터미널에서 친 것이면 그대로 둡니다). 숨기지 못하는 환경에서는 콘솔이 같이 떠 있을 수 있지만 동작에는 지장이 없습니다

## 명령

| 명령 | 하는 일 |
|---|---|
| `python ascii-1.py` · `gui [그림.png]` | 창을 엽니다 |
| `python ascii-1.py 그림.png [그림2.png …]` | 그림마다 입력 옆에 `<이름>.txt` 를 만듭니다. 여러 장을 한꺼번에 끌어놓아도 됩니다 |
| `python ascii-1.py version` | 버전 |
| `python ascii-1.py check` | 자가 점검 — 내장 그림을 PNG 로 만들어 읽기 → 요소 찾기 → 글자 아트까지 통과시킵니다 |
| `python ascii-1.py help` | 도움말 |

| 옵션 | 뜻 |
|---|---|
| `--width N` | 열 수 (40–300, 기본 120). 그려질 내용의 폭에 걸리므로 클수록 촘촘합니다 |
| `--kind auto\|chart\|wafer` | 기본 `auto`. `wafer` 는 웨이퍼 외곽이 없으면, `chart` 는 웨이퍼 맵처럼 보이면 만들지 않고 확인을 요청합니다 |
| `--box` | 가로 · 세로선을 `─ │ ┼` 로 (그 밖의 격자 글자는 그대로 ASCII) |
| `--stdout` | 파일 대신 화면에 찍습니다 |
| `--no-wait` | 끝나도 Enter 를 기다리지 않습니다 |

그림 경로로 시작하는 명령(끌어다 놓은 것과 같은 모양)이고 콘솔이 대화형이면, 결과를 읽을 수 있게 끝난 뒤 `Enter 를 누르면 닫힙니다` 하고 기다립니다. 터미널에서 옵션부터 치거나 `--stdout` · `--no-wait` 를 주면 기다리지 않습니다.

## exe 로 쓰기

저장소 Releases 에서 `ascii-1-v…` 릴리스의 **`ascii-1.exe` 와 `ascii-1.exe.sha256`** 을 받아 아무 폴더에 둡니다. 설치할 것은 없고, 파이썬도 필요 없습니다. 두 번 누르면 [창](#창)이 열리고, PNG 를 `ascii-1.exe` 위로 끌어다 놓으면 소스(`python ascii-1.py`)의 명령줄과 똑같이 동작합니다 — 옵션 · 종료 코드 · 결과 파일도 같습니다.

| 확인할 것 | 방법 |
|---|---|
| 받은 파일이 올린 파일과 같은가 | `certutil -hashfile ascii-1.exe SHA256` 의 해시가 `ascii-1.exe.sha256` 에 적힌 것과 같은지 |
| 잘 돌아가는가 | `ascii-1.exe check` → 마지막 줄 `결과: OK` |

- **서명하지 않은 파일입니다.** 처음 열 때 Windows SmartScreen 이 `PC 보호` 창을 띄우거나 사내 백신이 막거나 오탐할 수 있습니다. 해시가 같은지 확인한 뒤 `추가 정보` › `실행` 으로 열거나, 보안 담당에게 허용을 요청하세요. 이 도구는 우회하지 않습니다
- 한 파일로 묶은 방식이라 실행할 때마다 임시 폴더(`%TEMP%\_MEI…`)에 풀어서 돕니다. GitHub 의 Windows 러너에서는 한 번에 1 초 안쪽이었고(스모크 시험 7 번에 4.7 초), 백신이 검사하는 PC 에서는 더 걸릴 수 있습니다
- 끝날 때 그 임시 폴더를 못 지우면 `Failed to remove temporary directory` 경고가 뜰 수 있습니다. 흔한 원인은 백신이 풀린 파일을 잡고 있는 경우와 프로그램을 강제로 닫은 경우입니다 — 이 PC 에서 원인이 무엇인지는 확인하지 못했습니다. 남은 `_MEI…` 폴더는 지워도 됩니다. 창이 아예 안 뜨면 이 경고 앞뒤의 메시지와 함께 알려 주세요
- exe 는 GitHub 의 Windows 에서 만든 것입니다. 태그(`ascii-1-vX.Y.Z`)를 푸시해야 릴리스가 생기고, 그 태그는 `ascii-1.py` 의 `VERSION` 과 같아야 합니다

## 결과와 종료 코드

출력의 마지막 줄은 늘 `결과: …` 입니다. 그림마다 한 줄(`OK  그림.png → 그림.txt (118열 50행 · 점 추정 20개)`)이 위에 찍힙니다.

| 종료 코드 | 마지막 줄 | 뜻 |
|---|---|---|
| 0 | `결과: OK` | 모든 그림을 만들었습니다 |
| 1 | `결과: 점검 실패` | 읽을 수 없는 그림(PNG 가 아님 · 깨짐 · 너무 큼 · 없음) 또는 결과 파일을 쓸 수 없음. 나머지 그림은 계속 만듭니다 |
| 2 | (없음 · 메시지는 오류 출력) | 사용법 오류 (모르는 옵션 · 범위 밖 `--width` 등). 아무것도 만들지 않습니다 |
| 3 | `결과: 확인 필요` | 그릴 것을 못 찾음 · 사진이나 채워진 그림 · `--kind` 가 맞지 않음. 그 그림은 만들지 않습니다 |

여러 장 중에 실패가 하나라도 있으면 1, 없고 확인 필요가 있으면 3 입니다.

## 읽을 수 있는 PNG

`ascii1_png.py` 가 표준 라이브러리(`zlib` · `struct`)만으로 읽습니다. 결과는 늘 8 비트 RGB 이고, 투명한 곳은 흰 바탕으로 칩니다.

| 항목 | 지원 |
|---|---|
| 색 유형 | 회색 · RGB · 팔레트 · 회색+알파 · RGBA |
| 비트 깊이 | 1 · 2 · 4 · 8 · 16 (16 비트는 위 바이트만) |
| 줄 필터 · 인터레이스 | 0–4 · Adam7 |
| 투명 | 알파 채널 · 팔레트 투명도 · 회색/RGB 투명색 |
| 한도 | 한 변 4000 픽셀 · 파일 64 MB |
| 읽지 않는 것 | JPEG 를 비롯한 PNG 가 아닌 파일 (확장자가 `.png` 여도 안이 JPEG 이면 `JPEG 로 보입니다` 하고 거부) |

깨진 파일 · 잘린 파일 · 압축 폭탄은 `PngError` 한 줄로 끝납니다. 원본은 어떤 경우에도 바꾸지 않습니다.

## 그림에서 요소 찾기

`ascii1_seg.py` 가 PNG 에서 바탕 · 선 · 점 · 원 외곽(웨이퍼) · 글자를 가릅니다. 방법과 잰 값은 저장소의 `docs/plans/ascii-1-design.md` 08 에 있습니다.

| 찾는 것 | 방법 |
|---|---|
| 바탕 | 네 가장자리에서 가장 흔한 색. 가장자리를 두른 테두리 선은 바탕이 아닙니다 |
| 색 | 바탕과 먼 칸을 색상으로 최대 6 군집(검정 · 회색은 중립 하나) |
| 선 | 한 행(열)의 40% 이상에 걸친 가로선 · 세로선 |
| 마커 | 선에 붙어 있어도 거리 변환으로 뗍니다 (선보다 충분히 굵을 때). 가로 · 세로선이 없는 차트는 곡선의 두께를 직접 재서 가릅니다 |
| 점 | 낱점 면적으로 개수를 추정합니다 — 뭉친 점은 추정치입니다 |
| 웨이퍼 외곽 · 노치 | 정사각에 가까운 둥근 외곽과 안쪽으로 패인 곳 |
| 글자 | 줄을 이룬 작은 덩어리는 읽지 않고 비웁니다 |
| 분석 안 함 | 바탕이 아닌 곳이 절반이 넘는 그림(사진 · 채워진 그림) |

## 글자 아트로 옮기기

`ascii1_render.py` 가 찾은 요소를 글자 격자로 옮깁니다. 격자 줄은 순수 ASCII 이고, 맨 아래 범례(한국어)가 군집마다 어떤 글자를 줬는지 알려 줍니다.

| 요소 | 글자 |
|---|---|
| 점 | 개수 많은 색부터 `o O @` · `x X %` · `* # &` — 왼쪽이 낱점, 가운데가 둘 이상, 오른쪽이 빽빽한 셀 |
| 가로선 · 세로선 | 검정 · 회색은 `-` `\|`, 색 있는 선은 `=` `~` (세로는 `!` `:`), 가로 · 세로가 만나면 `+` |
| 곡선 | `_ - / \ \|` (기울기를 따라). 마커 사이는 마커 중심까지 이어서 끊기지 않게 |
| 웨이퍼 외곽 · 노치 | `.` · 노치는 원의 방향에 따라 `v` `^` `<` `>` |
| 글자 · 숫자 | 읽지 않고 비웁니다 (범례에 몇 곳인지만) |

격자는 열 수(기본 120, 40–300)에 맞춰 만듭니다. 열 수는 그림 전체가 아니라 **그려질 내용의 폭**에 걸리므로 여백에 열을 쓰지 않고, 셀 가로가 1 픽셀보다 좁아지지는 않습니다(웨이퍼 225 픽셀 그림은 최대 약 130 열). 셀 세로를 가로의 2 배로 잡아 원이 둥글어 보입니다. 해상도를 높이려면 열 수를 늘립니다. 점은 추정 개수입니다.

| 할 일 | 명령 |
|---|---|
| 테스트 | `python -m unittest discover -s tests` (표준 라이브러리만 — 시험용 PNG 인코더는 `tests/pngenc.py` 에만 있습니다) |
| exe 만들기 (개발 도구) | `pip install pyinstaller==6.10.0` 다음 `python tools/build_exe.py` → `dist/ascii-1.exe` · `.sha256` |
| 만든 exe 시험 | `python tools/build_exe.py --smoke dist/ascii-1.exe` — version · check · 변환 · 이름 충돌 · 확인 필요 · 사용법 오류 |

| works 규칙 검사 | 저장소 루트에서 `python tools/works_check.py` |

CI(`.github/workflows/ascii-1.yml`)는 Windows · Ubuntu × Python 3.8 · 최신에서 테스트를 돌립니다. `.github/workflows/ascii-1-release.yml` 은 `ascii-1/**` 를 건드린 PR 마다 Windows 에서 exe 를 만들어 스모크 시험까지 돌리고(릴리스는 하지 않음), 태그를 푸시했을 때만 Release 에 올립니다. 테스트 그림은 전부 코드로 만든 것입니다.

## 데이터

저장하는 것이 없습니다. 이 앱이 만드는 파일은 입력 PNG 옆의 결과 `.txt`(UTF-8) 뿐입니다. Windows 에서는 줄 끝이 CRLF 로 써져 메모장에서 그대로 열립니다.

## 알려진 한계

- exe 는 서명하지 않았습니다 (SmartScreen · 백신이 막을 수 있음). 소스는 `python ascii-1.py` (파이썬 3.8 이상) 입니다. 사양 · 출력 모양은 `docs/plans/ascii-1-design.md` 를 보세요
- 그림 속 글자(`UCL` · 눈금 숫자 · 축 이름)는 읽지 않고 비웁니다. 점은 뭉친 곳을 면적으로 센 추정 개수입니다
- JPEG 는 읽지 않습니다 (확장자가 `.png` 여도 안이 JPEG 면 `JPEG 로 보입니다` 하고 거부)
- 요소 찾기는 마커가 선 두께의 2 배 + 2 px 보다 작으면 선과 마커를 못 가르고, 둥근 낱글자(`0`)는 점과 구분이 안 됩니다. 점선은 한 줄의 40% 이상을 덮으면 선, 그보다 성기면 점으로 셉니다. 같은 높이에 나란히 놓인 큰 마커들이 한 줄의 40% 이상을 덮어도 가로선으로 봅니다
- 속도: 1000×1000 RGB 를 읽는 데 필터에 따라 0.01–1.4 초. 한 장 전체(읽기 · 요소 찾기 · 글자 아트)는 376×292 차트가 0.2 초, 2000×2000 에 전경 45% 인 그림이 25 초 · 메모리 210 MB, 한도인 4000×4000 에 전경 45% 면 157 초 · 778 MB 입니다 (Linux · Python 3.13 에서 잰 값). 진행 표시가 없어 그동안 멈춘 것처럼 보입니다. Windows · Python 3.8 에서는 더 걸릴 수 있습니다

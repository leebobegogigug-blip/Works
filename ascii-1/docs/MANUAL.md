# Ascii–1 매뉴얼

PNG · JPEG 를 ASCII 아트로 바꾸는 명령형 도구입니다. 소개는 [README](../README.md), 설치 절차는 [INSTALL.md](../INSTALL.md)에 있습니다.

- **창에서 그림 고르기, 또는 끌어다 놓기** — 선 차트 · 웨이퍼 파티클 맵처럼 바탕 · 선 · 점이 또렷한 PNG · JPEG 를 글자 아트(`.txt`)로 바꿉니다
- **원본은 그대로, 결과는 덮어쓰지 않음** — 입력 옆에 `<이름>.txt`, 있으면 `<이름> (2).txt`
- **내 PC 전용** — 네트워크를 쓰지 않고, 파일은 사용자가 지정한 그림(PNG · JPEG)만 읽습니다

## 창

`python ascii-1.py` (인자 없이) 또는 `ascii-1.exe` 를 두 번 누르면 창이 열립니다. 켜는 연출(0.9 초)은 아무 키나 클릭으로 건너뜁니다. 화면은 [DESIGN.md](../../docs/DESIGN.md) 를 따르고, 아래는 "이 앱에서는 어디에" 입니다 (원칙 번호와 이름은 DESIGN.md 그대로).

| 원칙 | 이 앱에서는 |
|---|---|
| 1 한 화면 = 한 모드 | 핵심 값 네 개 — `COLS` `ROWS` `DOTS` `LINES` 를 7세그로 크게 (`02 STAT`) |
| 2 색 = 조작 | `03 DECK` 의 노브 네 개. 값은 노브의 색으로 보이고 그 노브가 바꿉니다: ① 파랑 열 수 · ② 라임 종류 · ③ 흰색 선 글자 · ④ 회색 글자 크기 |
| 3 번호 붙은 구역 | `01 SOURCE` · `02 STAT` · `03 DECK` · `04 ART` · `05 STATUS`. (`00` 은 전체 보기라 쓰지 않았습니다 — 왼쪽 열을 접고 ART 를 넓히는 `ART 크게` 는 번호 없이 머리의 단추입니다) |
| 4 엔지니어링을 숨기지 않기 | `SIZE` 그림 크기와 파일 크기 · `READ` `DRAW` 걸린 시간 · `KIND` 감지한 종류 · 머리의 LED `img` `art` `busy` |
| 5 즉각 반응 | 일하는 동안 `busy` LED 깜빡임과 ART 위의 라임 스윕 · 저장하면 도장 `저장` 과 `되돌리기` 초읽기 |
| 6 사각 격자 | 각진 모서리 · 8px 간격 · 점 격자 바탕 · 앞자리 0 (`0120`) · 구역 사이는 8px |
| 7 캐릭터 | 점 찍는 활자 — 머리의 네모 얼굴이 `o o`(대기) `- -`(읽는 중) `@ @`(그렸음) `O O`(확인 필요) `x x`(오류) `^ ^`(저장) 로 상태를 보여 줍니다 |

| 구역 | 하는 일 |
|---|---|
| `01 SOURCE` | `그림 열기` (Ctrl+O) 로 PNG · JPEG 를 고릅니다. 읽는 동안 창은 멎지 않습니다 |
| `02 STAT` | 그린 글자 아트의 열 · 행, 찾은 점 추정 개수, 가로 · 세로선 수. 아직 없으면 `----` |
| `03 DECK` | 노브를 돌리면 이미 읽은 그림으로 **다시 그리기만** 합니다(다시 읽지 않습니다). 글자 크기는 그림을 다시 그리지 않고 글꼴만 바꿉니다 |
| `04 ART` | 결과. 가로 · 세로 스크롤. 글자 크기가 `FIT` 이면 폭에 맞는 가장 큰 크기를 고릅니다 |
| 발(상태 줄) | `●` 그렸음 · `◐` 읽는 중 · `‼` 확인 필요(저장 · 복사 꺼짐) · `×` 오류(`ERR` 칩) · `√` 끝남. `저장 .txt` (Ctrl+S) · `복사` (Ctrl+Shift+C) |

노브를 돌리는 길은 여럿입니다 — 모두 같은 값을 바꿉니다.

| 조작 | 방법 |
|---|---|
| 한 단계 | `−` `+` 버튼 · 휠 · 위로 8px 끌기 · 오른쪽 클릭(내림) · 노브를 고른 뒤 `+` `−` 또는 방향키 |
| 노브 고르기 | 노브를 누르거나 키 `1`–`4` (고른 노브는 라임 테두리) |
| 한 단계가 얼마 | 열 수는 10 열씩, `Shift` 와 함께 휠 · 끌기 · 방향키를 쓰면 1 열씩. 종류 · 선 글자 · 글자 크기는 한 단계씩 (종류 · 선 글자는 끝에서 처음으로 돕니다) |
| 범위 | 열 수 40–300 — 범위 밖으로 나가지 않습니다. 글자 크기 `FIT` · 8–32px (16 · 32px 에서 Unifont 가 가장 또렷합니다) |

저장은 명령줄과 같습니다 — 입력 옆 `<이름>.txt`, 있으면 덮어쓰지 않고 `<이름> (2).txt`. 그 폴더에 쓸 수 없으면 저장할 곳을 묻습니다. 저장하면 도장이 찍히고 `되돌리기 8` 이 8 초 동안 줄어듭니다 — 그 안에 누르면 **방금 만든 그 파일만** 지웁니다 (그 사이 내용이 바뀌었으면 지우지 않습니다). 0 이 되면 확정이고, 원본 그림은 어느 경우에도 건드리지 않습니다.

| 키 | 하는 일 |
|---|---|
| `Ctrl+O` · `Ctrl+S` · `Ctrl+Shift+C` | 그림 열기 · 저장 · 복사 |
| `1`–`4` · `+` `−` · 방향키 | 노브 고르기 · 돌리기 (`+` `−` 는 한 단계, 한 칸씩은 `Shift`+방향키) |
| `F` | ART 크게 (왼쪽 열 접기 · 펴기) |
| `Ctrl+T` | 테마 바꾸기 |

- **테마**: `THEME` 단추 · `Ctrl+T` 로 dark(기본) → light → system 순으로 돕니다. system 은 Windows 의 앱 테마를 따르고(읽지 못하면 dark), 고른 테마는 저장하지 않습니다 — 켤 때마다 dark 입니다
- **글꼴**: [GNU Unifont](https://unifoundry.com/unifont/) (8×16)를 권합니다. 설치돼 있으면 그것으로, 없으면 `D2Coding` · `Consolas` 등 고정폭 글꼴로 대신합니다 (한글 줄 폭이 조금 어긋날 수 있습니다). 이 도구는 글꼴을 내려받거나 설치하지 않습니다
- 창 안으로 파일을 끌어다 놓는 것은 **지원하지 않습니다** (표준 라이브러리 `tkinter` 에는 없습니다). 그림 열기를 쓰거나, 파일을 `ascii-1.exe` 아이콘 위로 끌어다 놓으세요 — 그때는 창 없이 `.txt` 가 만들어집니다
- 파이썬에 `tkinter` 가 없으면(일부 리눅스) 창은 열리지 않고 이유를 알린 뒤 종료 코드 1 로 끝납니다. 명령줄은 그대로 돕니다. `check` 가 `창 (tkinter)  있음/없음` 을 알려 줍니다
- `python ascii-1.py gui 그림.png` 는 창을 열면서 그 그림을 바로 엽니다. `gui --selftest` 는 창을 열어 내장 그림을 읽고 그려 본 뒤 닫는 점검입니다
- exe 를 두 번 눌러 연 검은 콘솔 창은 창이 뜨면 숨깁니다(터미널에서 친 것이면 그대로 둡니다). 숨기지 못하는 환경에서는 콘솔이 같이 떠 있을 수 있지만 동작에는 지장이 없습니다

## 명령

| 명령 | 하는 일 |
|---|---|
| `python ascii-1.py` · `gui [그림.png]` | 창을 엽니다 |
| `python ascii-1.py 그림.png [그림2.png …]` | 그림마다 입력 옆에 `<이름>.txt` 를 만듭니다. 여러 장을 한꺼번에 끌어놓아도 됩니다 |
| `python ascii-1.py version` | 버전 |
| `python ascii-1.py check` | 자가 점검 — 내장 그림을 PNG 로 만들어 읽기 → 요소 찾기 → 글자 아트까지 통과시킵니다 |
| `python ascii-1.py help` | 도움말 |

| 옵션 | 뜻 |
|---|---|
| `--width N` | 열 수 (40–300, 기본 120). 그려질 내용의 폭에 걸리므로 클수록 촘촘합니다 |
| `--kind auto\|chart\|wafer` | 기본 `auto`. `wafer` 는 웨이퍼 외곽이 없으면, `chart` 는 웨이퍼 맵처럼 보이면 만들지 않고 확인을 요청합니다 |
| `--grid hide\|dots\|ticks\|show` | 그림 속 격자를 어떻게 그릴지. 기본 `hide` 는 격자줄을 그리지 않고 그림 상자 틀만 그린 뒤 범례에 `격자 가로 17 · 세로 21 줄 생략` 처럼 적습니다. `dots` 는 교차점에 `.` (웨이퍼 외곽이 있으면 `hide` 로), `ticks` 는 틀 위 격자 자리에 `+`, `show` 는 격자줄을 다 그립니다(데이터 밑에 깔림). 격자가 없는 그림에서는 아무것도 바꾸지 않습니다 |
| `--box` | 가로 · 세로선을 `─ │ ┼` 로 (그 밖의 격자 글자는 그대로 ASCII) |
| `--stdout` | 파일 대신 화면에 찍습니다 |
| `--no-wait` | 끝나도 Enter 를 기다리지 않습니다 |

그림 경로로 시작하는 명령(끌어다 놓은 것과 같은 모양)이고 콘솔이 대화형이면, 결과를 읽을 수 있게 끝난 뒤 `Enter 를 누르면 닫힙니다` 하고 기다립니다. 터미널에서 옵션부터 치거나 `--stdout` · `--no-wait` 를 주면 기다리지 않습니다.

## exe 로 쓰기

저장소 Releases 에서 `ascii-1-v…` 릴리스의 **`ascii-1.exe` 와 `ascii-1.exe.sha256`** 을 받아 아무 폴더에 둡니다. 설치할 것은 없고, 파이썬도 필요 없습니다. 두 번 누르면 [창](#창)이 열리고, 그림을 `ascii-1.exe` 위로 끌어다 놓으면 소스(`python ascii-1.py`)의 명령줄과 똑같이 동작합니다 — 옵션 · 종료 코드 · 결과 파일도 같습니다.

| 확인할 것 | 방법 |
|---|---|
| 받은 파일이 올린 파일과 같은가 | `certutil -hashfile ascii-1.exe SHA256` 의 해시가 `ascii-1.exe.sha256` 에 적힌 것과 같은지 |
| 잘 돌아가는가 | `ascii-1.exe check` → 마지막 줄 `결과: OK` |

- **서명하지 않은 파일입니다.** 처음 열 때 Windows SmartScreen 이 `PC 보호` 창을 띄우거나 사내 백신이 막거나 오탐할 수 있습니다. 해시가 같은지 확인한 뒤 `추가 정보` › `실행` 으로 열거나, 보안 담당에게 허용을 요청하세요. 이 도구는 우회하지 않습니다
- 한 파일로 묶은 방식이라 실행할 때마다 임시 폴더(`%TEMP%\_MEI…`)에 풀어서 돕니다. GitHub 의 Windows 러너에서는 한 번에 1 초 안쪽이었고(스모크 시험 7 번에 4.7 초), 백신이 검사하는 PC 에서는 더 걸릴 수 있습니다
- 끝날 때 그 임시 폴더를 못 지우면 `Failed to remove temporary directory` 경고가 뜰 수 있습니다. 흔한 원인은 백신이 풀린 파일을 잡고 있는 경우와 프로그램을 강제로 닫은 경우입니다 — 이 PC 에서 원인이 무엇인지는 확인하지 못했습니다. 남은 `_MEI…` 폴더는 지워도 됩니다. 창이 아예 안 뜨면 이 경고 앞뒤의 메시지와 함께 알려 주세요
- exe 는 GitHub 의 Windows 에서 만든 것입니다. 태그(`ascii-1-vX.Y.Z`)를 푸시해야 릴리스가 생기고, 그 태그는 `ascii-1.py` 의 `VERSION` 과 같아야 합니다

## 결과와 종료 코드

출력의 마지막 줄은 늘 `결과: …` 입니다. 그림마다 한 줄(`OK  그림.png → 그림.txt (118열 50행 · 점 추정 20개)`)이 위에 찍힙니다. 빽빽한 산점이 있으면 개수는 범위로 적습니다 (`점 추정 약 1800–2300개`).

| 종료 코드 | 마지막 줄 | 뜻 |
|---|---|---|
| 0 | `결과: OK` | 모든 그림을 만들었습니다 |
| 1 | `결과: 점검 실패` | 읽을 수 없는 그림(PNG · JPEG 가 아님 · 지원하지 않는 JPEG · 깨짐 · 너무 큼 · 없음) 또는 결과 파일을 쓸 수 없음. 나머지 그림은 계속 만듭니다 |
| 2 | (없음 · 메시지는 오류 출력) | 사용법 오류 (모르는 옵션 · 범위 밖 `--width` 등). 아무것도 만들지 않습니다 |
| 3 | `결과: 확인 필요` | 그릴 것을 못 찾음 · 사진이나 채워진 그림 · `--kind` 가 맞지 않음. 그 그림은 만들지 않습니다 (격자만 있는 그림은 그릴 것이 있는 것으로 보고 틀과 범례를 만듭니다) |

여러 장 중에 실패가 하나라도 있으면 1, 없고 확인 필요가 있으면 3 입니다.

## 읽을 수 있는 그림

PNG 와 JPEG 를 읽습니다. 어느 쪽인지는 확장자가 아니라 파일 첫 바이트(시그니처)로 가릅니다 — 이름이 `.png` 인 JPEG 도, 이름이 `.jpg` 인 PNG 도 제대로 읽습니다. 결과는 늘 8 비트 RGB 입니다.

### PNG

`ascii1_png.py` 가 표준 라이브러리(`zlib` · `struct`)만으로 읽습니다. 투명한 곳은 흰 바탕으로 칩니다.

| 항목 | 지원 |
|---|---|
| 색 유형 | 회색 · RGB · 팔레트 · 회색+알파 · RGBA |
| 비트 깊이 | 1 · 2 · 4 · 8 · 16 (16 비트는 위 바이트만) |
| 줄 필터 · 인터레이스 | 0–4 · Adam7 |
| 투명 | 알파 채널 · 팔레트 투명도 · 회색/RGB 투명색 |
| 한도 | 한 변 4000 픽셀 · 파일 64 MB |
| 읽지 않는 것 | PNG 도 JPEG 도 아닌 파일 (`PNG 가 아닙니다`) |

### JPEG

`ascii1_jpeg.py` 가 표준 라이브러리만으로 baseline JPEG 를 읽습니다.

| 항목 | 지원 |
|---|---|
| 형식 | baseline 순차(SOF0) · 8 비트 · 허프만 부호 |
| 성분 | 회색 1 성분 · 컬러 3 성분 (YCbCr, Adobe 표지가 RGB 라고 하면 RGB) |
| 색차 표본 | 4:4:4 · 4:2:2 · 4:4:0 · 4:2:0 과 그 밖의 정수비. 2 배 비율은 libjpeg 와 같은 방식으로 부드럽게 늘립니다 |
| 그 밖 | 재시작 표지(DRI · RSTn) · 성분마다 나눈 여러 스캔 · 8 · 16 비트 양자화 표 · APPn · 설명(COM)은 건너뜀 · EOI 가 빠진 파일 |
| 한도 | 한 변 4000 픽셀 · 파일 64 MB (PNG 와 같습니다. 크기는 해독 전에 머리에서 봅니다) |
| 읽지 않는 것 | progressive · 확장 순차(SOF1) · 무손실 · 산술 부호화 · 12 비트 · 2 성분 · 4 성분(CMYK · YCCK) — `JPEG 이지만 지원하지 않는 형식입니다 (PNG 로 저장해 주세요)` |

지원하지 않는 JPEG 는 그림판 · 미리보기 같은 프로그램에서 PNG 로 다시 저장하면 읽을 수 있습니다.

깨진 파일 · 잘린 파일 · 압축 폭탄 · 망가진 허프만 표는 `PngError`(JPEG 는 그 갈래인 `JpegError`) 한 줄로 끝납니다. 원본은 어떤 경우에도 바꾸지 않습니다.

## 그림에서 요소 찾기

`ascii1_seg.py` 가 그림에서 바탕 · 선 · 점 · 원 외곽(웨이퍼) · 글자를 가릅니다. 방법과 잰 값은 저장소의 `docs/plans/ascii-1-design.md` 08 에 있습니다.

| 찾는 것 | 방법 |
|---|---|
| 바탕 | 네 가장자리에서 가장 흔한 색. 가장자리를 두른 테두리 선은 바탕이 아닙니다 |
| 색 | 바탕과 먼 칸을 색상으로 최대 6 군집(검정 · 회색은 중립 하나) |
| 선 | 한 행(열)의 40% 이상에 걸친 가로선 · 세로선 |
| 마커 | 선에 붙어 있어도 거리 변환으로 뗍니다 (선보다 충분히 굵을 때). 가로 · 세로선이 없는 차트는 곡선의 두께를 직접 재서 가릅니다 |
| 점 | 낱점 면적으로 개수를 추정합니다 — 뭉친 점은 추정치입니다 |
| 웨이퍼 외곽 · 노치 | 정사각에 가까운 둥근 외곽과 안쪽으로 패인 곳 |
| 글자 | 줄을 이룬 작은 덩어리는 읽지 않고 비웁니다 |
| 분석 안 함 | 바탕이 아닌 곳이 절반이 넘는 그림(사진 · 채워진 그림) |

## 글자 아트로 옮기기

`ascii1_render.py` 가 찾은 요소를 글자 격자로 옮깁니다. 격자 줄은 순수 ASCII 이고, 맨 아래 범례(한국어)가 군집마다 어떤 글자를 줬는지 알려 줍니다.

| 요소 | 글자 |
|---|---|
| 점 | 개수 많은 색부터 `o O @` · `x X %` · `* # &` — 왼쪽이 낱점, 가운데가 둘 이상, 오른쪽이 빽빽한 셀 |
| 빽빽한 산점 | 같은 글자(`o O @`)로 셀마다 개수를 밀도처럼 그리고, 범례에 `파랑 점 약 1800–2300개 (빽빽함 · 밀도로 그림)` 처럼 범위를 적습니다 |
| 가로선 · 세로선 | 검정 · 회색은 `-` `\|`, 색 있는 선은 `=` `~` (세로는 `!` `:`), 가로 · 세로가 만나면 `+` |
| 그림의 격자 | 기본은 그림 상자 틀(`-` `\|` 모서리 `+`)만 그리고 범례에 줄 수를 적습니다. `--grid` 참고 |
| 곡선 | `_ - / \ \|` (기울기를 따라). 마커 사이는 마커 중심까지 이어서 끊기지 않게 |
| 추세선 | 곡선과 같은 글자 `_ - / \ \|`. 범례에는 `빨강 추세선` 처럼 곡선과 따로 적습니다. 빽빽한 산점 위를 지나는 셀에서는 추세선 글자를 그리고 범례에 `(빽빽한 점 위에 그림)` 이라고 적습니다 |
| 웨이퍼 외곽 · 노치 | `.` · 노치는 원의 방향에 따라 `v` `^` `<` `>` |
| 글자 · 숫자 | 읽지 않고 비웁니다 (범례에 몇 곳인지만) |

한 셀에 여럿이 겹치면 노치 > 점 > 선 · 그림 상자 틀 > 곡선 · 추세선 > 웨이퍼 외곽 > 그림의 격자 순으로 이깁니다 (빽빽한 산점만 추세선에 양보합니다).

격자는 열 수(기본 120, 40–300)에 맞춰 만듭니다. 열 수는 그림 전체가 아니라 **그려질 내용의 폭**에 걸리므로 여백에 열을 쓰지 않고, 셀 가로가 1 픽셀보다 좁아지지는 않습니다(웨이퍼 225 픽셀 그림은 최대 약 130 열). 셀 세로를 가로의 2 배로 잡아 원이 둥글어 보입니다. 해상도를 높이려면 열 수를 늘립니다. 점은 추정 개수입니다.

## 알려진 한계

- exe 는 서명하지 않았습니다 (SmartScreen · 백신이 막을 수 있음). 소스는 `python ascii-1.py` (파이썬 3.8 이상) 입니다. 사양 · 출력 모양은 `docs/plans/ascii-1-design.md` 를 보세요
- 그림 속 글자(`UCL` · 눈금 숫자 · 축 이름)는 읽지 않고 비웁니다. 점은 뭉친 곳을 면적으로 센 추정 개수이고, 빽빽한 산점은 겹침을 보정한 범위입니다
- 빽빽한 산점 위로 추세선이 지나는 셀에는 추세선 글자를 그리므로 그 셀의 밀도는 보이지 않습니다. 열 수가 커서 셀이 낱점보다 작아지면(300 열 근처) 빽빽한 곳도 낱점 글자 `o` 위주로 보이고 성긴 곳은 비어 보일 수 있습니다 — 개수의 합은 그대로입니다
- 창에는 `--grid` 노브가 없습니다 (노브는 네 개). 창은 늘 기본 `hide` 로 그리고, 다른 격자 표시는 명령줄로 만듭니다
- JPEG 는 baseline 만 읽습니다 ([JPEG](#jpeg) 참고). EXIF 의 회전 정보와 색 프로파일은 무시합니다 (사진기가 세워 찍은 그림은 눕혀진 채로 읽힙니다). 해독은 1015×901 의 4:2:0 차트가 약 1.5 초(Python 3.8 은 1.9 초), 사진처럼 빽빽한 1000×1000 이 3.4 초 · 2000×2000 이 14 초입니다 (Linux · Python 3.13 에서 잰 값)
- 요소 찾기는 마커가 선 두께의 2 배 + 2 px 보다 작으면 선과 마커를 못 가르고, 둥근 낱글자(`0`)는 점과 구분이 안 됩니다. 점선은 한 줄의 40% 이상을 덮으면 선, 그보다 성기면 점으로 셉니다. 같은 높이에 나란히 놓인 큰 마커들이 한 줄의 40% 이상을 덮어도 가로선으로 봅니다
- 속도: 1000×1000 RGB 를 읽는 데 필터에 따라 0.01–1.4 초. 한 장 전체(읽기 · 요소 찾기 · 글자 아트)는 376×292 차트가 0.2 초, 2000×2000 에 전경 45% 인 그림이 25 초 · 메모리 210 MB, 한도인 4000×4000 에 전경 45% 면 157 초 · 778 MB 입니다 (Linux · Python 3.13 에서 잰 값). 진행 표시가 없어 그동안 멈춘 것처럼 보입니다. Windows · Python 3.8 에서는 더 걸릴 수 있습니다

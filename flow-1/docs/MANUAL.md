# Flow–1 매뉴얼

파이썬 데이터 쿼리를 흐름도 한 장으로. 분석 스크립트 · 노트북을 읽어 쿼리마다 SELECT · FROM · JOIN · WHERE 를 카드 한 장에, 쿼리 사이의 조인 · 조건 · 병합 · 임시 테이블을 선으로 잇습니다.
소개는 [README](../README.md), 설치 절차는 [INSTALL.md](../INSTALL.md), 사내 LLM 이 이어서 고치는 법은 [GUIDE.md](GUIDE.md)에 있습니다.

- **읽기만** — 코드를 실행하지 않고 파이썬 문법 트리(ast)로 읽습니다. `--run` 을 줄 때만 스크립트를 돌립니다
- **패키지 이름을 몰라도** — 인자에 SQL 이 들어간 호출이면 쿼리로 봅니다. 사내 패키지 이름을 알려 주면 SQL 이 변수인 호출까지
- **옆에 탐색기** — 폴더를 펼쳐 파일을 누르면 흐름도. `+` 로 감시 목록에 고정하면 바뀔 때마다 다시 그립니다
- **내 PC 전용** — `127.0.0.1` 에만 열리고 밖으로 나가는 통신이 없습니다. 붙여 넣은 코드는 메모리에만, 실행 기록에는 시간 · 행 수만

## 설정 (`%LOCALAPPDATA%\flow-1\config.json`)

| 키 | 설명 |
|---|---|
| `watch` | 감시할 파일 · 폴더 목록. 폴더는 안의 `.py` · `.ipynb` 전부 (가상환경 · 캐시 · 숨김 폴더는 건너뜀). 창의 `+` · `--set "watch=A;B"` · `python flow-1.py 경로` 로 더합니다 |
| `query.modules` | 사내 쿼리 패키지의 import 이름 (여럿 가능). 그 패키지 · 그 패키지로 만든 객체의 `query.calls` 호출은 SQL 이 변수여도 쿼리로 봅니다. 비워 두면 SQL 모양 인자로만 찾습니다 |
| `query.calls` | 그 패키지에서 SQL (또는 `.sql` 파일 경로)을 받는 함수 · 메서드 이름 (기본 `query` · `execute` · `read_sql` · `sql` · `run` · `fetch`). 적으면 기본값을 바꿉니다 |
| `query.sinks` | 출력 노드로 볼 메서드 (기본 `to_csv` · `to_excel` · `to_parquet` · `to_pickle` · `to_json` · `to_feather` · `to_sql`) |
| `scan.max_files` | 감시 파일 수 한도 (기본 400) |
| `scan.poll_sec` | 파일이 바뀌었는지 보는 간격 (기본 2초) |
| `run.keep` | 스크립트마다 남길 실행 기록 수 (기본 20) |
| `theme` | `dark`(기본) · `light` · `system` |
| `company` | 화면 위 `FLOW–1` 옆에 작게 넣는 회사 이름 (24자까지 · 비우면 없음). 저장소에는 넣지 않고 이 PC 설정에만 |
| `port` | 기본 `8785` (대장의 8785–8794 안에서 빈 곳) |
| `open_window` · `idle_exit_min` | 켤 때 창 열기 · 창을 닫고 이만큼(분) 지나면 저절로 꺼짐 (기본 30, `0` = 안 꺼짐) |

전체 기본값은 [`config.example.json`](../config.example.json). 데이터 폴더는 `FLOW_HOME` 환경 변수로 바꿀 수 있습니다.
다른 창에서 `--set` · `--run` 으로 설정을 바꾸면 켜져 있는 창이 2초 안에 다시 읽습니다.

```text
python flow-1.py --set "query.modules=<사내 패키지>" --set "query.calls=<함수1>;<함수2>" --check
python flow-1.py --set "watch=D:\분석\월간;D:\분석\주간"
```

## 쓰는 법

1. `python flow-1.py` — 창이 열립니다 (이미 켜져 있으면 창만)
2. 왼쪽 아래 **탐색기**에서 폴더를 펼쳐 `.py` · `.ipynb` 를 누릅니다 — 가운데에 흐름도. SQL 이 있어 보이는 파일에는 `●`
3. 자주 보는 폴더 · 파일은 `+` 로 **감시 목록**에 고정합니다 — 파일을 고칠 때마다 다시 읽어 그립니다
4. 카드를 누르면 오른쪽 **02** 에 그 쿼리의 전부 — 절마다 나눈 SQL · 파라미터가 어디서 왔는지 · 테이블마다 쓰는 컬럼 · 결과가 가는 곳 · 원문
5. 걸린 시간을 보려면 스크립트를 `python flow-1.py --run 스크립트.py` 로 돌립니다 — 카드 아래에 시간 · 행 수가 붙습니다

코드 조각을 복사해 창에 **그냥 붙여 넣어도**(Ctrl+V) 되고, 파일을 끌어다 놓아도 됩니다. 붙여 넣은 것은 메모리에만 있고 끄면 사라집니다.
경로 칸에 경로를 붙여 넣고 Enter — 폴더면 탐색기가 그리로, 파일이면 엽니다. 옆의 `+` 는 그 경로를 감시 목록에 고정합니다.

창 없이:

```text
python flow-1.py --scan daily.py            쿼리마다 절 · 파라미터 출처 · 테이블 · 흐름을 글로 (사람 · 사내 LLM 이 확인하는 곳)
python flow-1.py --json D:\분석              분석 결과 JSON (format 1)
python flow-1.py --svg 흐름.svg daily.py     흐름도를 SVG 파일로 (폰트 · 색 포함 · --detail 3 · --theme light)
```

## 흐름도 읽는 법

| 모양 | 뜻 |
|---|---|
| 카드 | 쿼리 호출 하나. 머리 = 번호(`Q01`) · 결과를 받는 변수 · 부른 함수 · 줄. 몸통 = 절마다 한 줄 |
| 카드의 `LEFT` · `JOIN` · `FULL` … | 조인 종류 (굵게). 바로 아래 `ON` 이 조인 조건. `,` 는 FROM 에 쉼표로 적은 조인 (조건은 WHERE 에) |
| `spend s WITH` | WITH(CTE)로 만든 이름. 그 안에서 읽은 테이블의 선이 이 줄로 들어옵니다 |
| `{order_ids}` 상자 | 코드의 값이 SQL 에 들어가는 자리. 값을 코드에서 알면 그 값으로 바꿔 보이고, 모르면 상자 |
| 알약 (실선) | 읽기만 하는 테이블 · (점선) 쿼리가 쓰는 테이블 — 쓰고 다시 읽으면 임시 테이블 · 이름 뒤 `#2` 는 덮어쓴 뒤의 판 |
| 알약 (잔 점선) | 파일 입력(`read_csv` …) · 출력(`to_csv` …) |
| 병합 카드 `J01` | 판다스 `merge` · `join` · `concat`. `L` · `R` 입력과 조인 종류 · 키 |
| 실선 | 테이블 → 그 테이블이 나오는 줄 · 데이터(결과 변수) → 병합 · 출력. 굵은 선 = 테이블에 쓰기 |
| 점선 | 앞 쿼리의 결과가 다음 쿼리의 조건(자리)으로 — 그 자리가 든 줄에 붙습니다 |
| 카드 테두리 점선 | SQL 을 코드에서 다 읽지 못함 (실행할 때 정해짐) |
| 머리의 `반복` · `조건부` | 반복문 안 · if 갈래 안의 호출 |

`00 전체` 는 쿼리가 있는 파일 전부를 한 장에 — 같은 테이블로 파일끼리 이어집니다.

## 찾는 규칙

자세한 정본은 [GUIDE.md › 04 분석 규칙](GUIDE.md#04-분석-규칙)입니다. 요약:

- **쿼리 호출**: ① 인자에 SQL 모양 문자열이 든 호출 ② `query.modules` 패키지(와 거기서 만든 객체)의 `query.calls` 이름 호출 ③ 판다스 `read_sql` · `read_sql_query`. `print` · 로그 · `write` · `append` 처럼 SQL 을 다루기만 하는 호출은 뺍니다
- **SQL 되살리기**: 문자열 · f-string · `.format` · `%` · `+` · `+=` · `join` · `dedent` · `strip` · `replace` · 사전 · 목록 · `open(…).read()` 한 `.sql` · `.hql` 파일 · 사내 패키지 호출에 넘긴 `.sql` 경로 (스크립트 옆에서 1 MB 까지)
- **흐름**: 결과 변수가 다음 SQL 의 자리에 쓰이면 점선. 판다스 `merge` · `join` · `concat` 은 병합 카드. `to_csv` 같은 출력 · `read_csv` 같은 입력은 알약
- **함수 · 반복 · 클래스**: 로컬 함수는 부른 자리마다 펼쳐 읽습니다 (3단계까지, 카드 머리에 부른 줄 · 02 에 경유). SQL 목록을 도는 반복은 원소마다. 인스턴스를 만들어 부른 메서드도
- **노트북**: 코드 셀을 이어 읽습니다. `%`매직 · `!`명령 줄은 건너뛰고, `%%sql` 셀은 SQL 카드. 문법이 틀린 셀만 건너뜁니다

## 실행 기록 (`--run`)

```text
python flow-1.py --run 스크립트.py [그 스크립트의 인자…]
```

- 스크립트를 이 파이썬에서 **진짜로 끝까지** 실행합니다 (`__name__ == "__main__"`). DB 에 쓰는 쿼리도 실행되니, 평소처럼 돌려도 되는 스크립트에만 씁니다
- 흐름도에 있는 쿼리 호출 자리(파일:줄:칸)만 감싸 잽니다 — 사내 패키지의 API 를 몰라도 되고, 다른 코드는 그대로 돕니다. 스크립트 폴더 아래에서 import 하는 모듈의 쿼리도 잽니다
- 카드 아래: `√ 1.2s · 12,340행` (여러 번이면 `×3`) · 실패 `ERR` · 실행 중 `◐` (창이 켜져 있으면 실시간). 막대 길이 = 그 실행에서 가장 오래 걸린 쿼리 대비
- `실행 기록` 버튼(04 RUNS)에서 지난 실행을 골라 겹쳐 봅니다. 02 에는 그 쿼리의 최근 12회 막대
- 실행한 스크립트는 감시 목록에 더해집니다. 종료 코드는 스크립트의 것 그대로
- 행 수는 결과의 `shape`(판다스 · 넘파이) · 목록 길이 · `rowcount` 로만 셉니다 — 결과를 다시 읽거나 저장하지 않습니다

## 알려진 한계

- **정적 분석입니다.** 실행할 때만 정해지는 SQL(다른 파일에서 import 한 함수가 만드는 SQL · 입력에 따라 바뀌는 문자열)은 카드에 `{자리}` 로 남습니다. 다른 파일의 함수는 펼치지 않습니다 — 그 파일도 감시하면 그 파일의 흐름도에 나옵니다
- if 갈래가 SQL 을 둘로 나누면 if 쪽 SQL 을 보이고 의존은 합칩니다. `while` · 재귀는 한 번만 읽습니다
- SQL 은 완전한 문법기가 아니라 절 나누기입니다. 모르는 문장은 글 그대로 두고 FROM · JOIN · INTO 뒤의 이름만 테이블로 봅니다 (방언을 더하는 법: [GUIDE.md › 06](GUIDE.md#06-sql-방언-맞추기))
- 판다스 병합은 이름(`merge` · `join` · `concat`)과 인자로 알아봅니다. 사용자가 만든 병합 함수는 병합 카드가 아니라 데이터 흐름으로만 이어집니다
- `--run` 의 행 수는 결과에 `shape` · 길이 · `rowcount` 가 있을 때만 셉니다 (지연 계산 객체는 세지 않음)
- **규약 S-04 (웹형 한 파일 배포)를 따르지 않습니다.** `flow-1.py` 하나가 아니라 분석 모듈 네 개(`flow1_sql` · `flow1_scan` · `flow1_graph` · `flow1_trace`)로 나눴습니다. 사내 LLM 이 한 번에 읽을 수 있는 크기(모듈당 1,500줄 안쪽)로 나눠야 고칠 곳만 읽고 고칠 수 있어서입니다. UI · 폰트는 S-04 대로 `build.py` 로 내장합니다 (`flow1_assets.py`)

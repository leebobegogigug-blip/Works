# works 개발 헌법

works 를 **고치는** 모든 LLM 에이전트(opencode · Claude Code · 그 밖의 무엇이든)가 같은 순서로 읽고, 같은 기준으로 판단하고, 같은 모양으로 끝내게 하는 작업 규칙이다.

- **무엇을 지키나**(앱이 지킬 것)는 [RULES.md](../RULES.md) 가 정본이다. 이 문서는 **어떻게 일하나**만 적는다.
- W · S 조항의 내용은 옮겨 적지 않고 번호로만 부른다. 이 문서의 조항 번호는 `D-nn` 이다.
- 적용 범위는 [AGENTS.md](../AGENTS.md) 와 같다 — 코드 · 문서를 고치는 작업에만. 앱 설치 · 사용 중이면 이 문서를 무시한다.
- 어기면 그 작업은 끝나지 않은 것이다. 보고하기 전에 되돌리거나 고친다.

## 00 입구와 우선순위

### 도구마다 입구

| 도구 | 자동으로 붙는 파일 | works 에서 |
|---|---|---|
| `AGENTS.md` 를 읽는 도구 (opencode 등) | `AGENTS.md` | 입구. 이 문서를 가리킨다 |
| Claude Code | `CLAUDE.md` | `@AGENTS.md` 한 줄 |
| 자동으로 읽는 파일이 없는 도구 | — | 아래 시작 프롬프트를 첫 마디로 |

도구별 파일에는 규칙을 적지 않는다. `AGENTS.md` 를 가리키는 한 줄만 둔다 (루트와 `flow-1/` 의 `CLAUDE.md` 처럼). 새 도구를 붙일 때도 그 한 줄짜리 파일만 더한다.

```text
works 저장소를 고친다. 손대기 전에 AGENTS.md → RULES.md → docs/DEVELOP.md 를 끝까지 읽고,
고칠 앱 폴더에 AGENTS.md 가 있으면 그것도 끝까지 읽어. 규칙과 부딪히면 하기 전에 조항 번호를 말하고 기다려.
할 일: <무엇을 · 어느 앱에서>
끝나면 docs/DEVELOP.md › D-11 틀로 보고해.
```

### 부딪힐 때

사용자의 지시는 **무엇을** 할지 정하고, 문서는 **어떻게** 할지 정한다. 지시가 문서의 금지와 부딪히면 [D-02](#d-02-부딪히면-멈추고-말한다) 로 간다.
문서끼리 부딪히면 위가 이긴다. 같은 순위에서는 더 좁은(구체적인) 쪽이 이긴다.

| 순위 | 문서 | |
|---|---|---|
| 1 | RULES.md 헌법 W | 무엇으로도 넘지 않는다 |
| 2 | 고칠 앱의 `AGENTS.md` · `docs/GUIDE.md` · `docs/UI.md` | 그 앱 안에서만 |
| 3 | RULES.md 규약 S · [DESIGN.md](DESIGN.md) · `docs/SPEC-*.md` | |
| 4 | 이 문서 (D) | |
| 5 | 모델 · 도구의 기본 습관 · 다른 저장소의 관례 | 위와 부딪히면 버린다 |

## 조항

### D-01 읽고 시작한다

손대기 전에 아래를 **끝까지** 읽는다.

| 언제 | 읽을 곳 |
|---|---|
| 늘 | `AGENTS.md` → RULES.md → 이 문서 |
| 앱 하나를 고칠 때 | 그 앱의 `AGENTS.md` (있으면) → `docs/MANUAL.md` › 개발 → `docs/GUIDE.md` (있으면) 00 읽는 법 표에서 할 일의 절 |
| 화면 · 문서 · 이미지 | [DESIGN.md](DESIGN.md) · 앱의 `docs/UI.md` (있으면) |
| 사내 LLM 기능 | [SPEC-llm.md](SPEC-llm.md) |
| 새 앱 · 이름 · 포트 · 단축키 · 환경 변수 | [REGISTRY.md](REGISTRY.md) · [templates/](templates/) · [RULES.md › 새 앱 만드는 순서](../RULES.md#새-앱-만드는-순서) |
| 설치 절차 (`INSTALL.md`) | RULES.md › W-08 · 그 `INSTALL.md` 전부 |
| 검사기 (`tools/`) | `tools/works_check.py` 머리말 · `tools/tests/` |

- 고칠 파일은 고치기 전에 읽는다. 큰 파일은 고칠 구역 전부를 읽는다 (구역 표시 줄 `# ──` 이 있으면 그 구역 단위로).
- `git log --oneline -10 -- <폴더>` 로 최근에 무엇이 바뀌었는지 본다. 최근 커밋이 일부러 바꾼 것을 되돌리지 않는다.
- 읽지 않은 코드 · 문서에 대해 말하지 않는다.

### D-02 부딪히면 멈추고 말한다

요청이 헌법 W 나 앱 `AGENTS.md` 의 금지와 부딪히면, **손대기 전에** 세 가지를 말하고 답을 기다린다.

1. 부딪히는 조항 번호 — `W-04` · `flow-1/AGENTS.md › 01 의 5`
2. 그대로 하면 무엇이 깨지나 — 한 줄
3. 갈 수 있는 길 — 추천을 맨 앞에
   - 조항 안에서 같은 목적을 이루는 방법
   - 규칙 문서를 먼저 고치는 PR ([RULES.md › 규칙 바꾸기](../RULES.md#규칙-바꾸기))
   - [예외 대장](REGISTRY.md#예외-대장)에 기한과 함께 적기

- 사용자가 길을 고르면 그 길로 간다.
- 규약 S 와 부딪히면 말하고 진행해도 된다. 따르지 않은 까닭을 그 앱 MANUAL › 알려진 한계나 PR 에 적는다 ([RULES.md › 등급](../RULES.md#등급)).
- **조용히 비켜 가지 않는다.** 검사기에 안 걸리게 문자열 쪼개기 · 예외 대장에 몰래 줄 넣기 · 테스트 건너뛰기 · CI 를 통과시키려고 워크플로나 검사기 고치기는 모두 위반이다.

### D-03 모르면 묻고, 정해진 것은 묻지 않는다

- **묻는다** — 요청이 두 가지로 읽히고 어느 쪽이냐에 따라 결과가 달라질 때 · 되돌리기 어려운 일을 하기 전 · 사내 정보가 있어야 할 때 (사내 이름은 코드가 아니라 설정에 — W-12).
- **되돌리기 어려운 일** — 파일 · 폴더 지우기 · 이름 · 설정 키 · 저장 형식 · 공개 명령 `format` 바꾸기 · 예외 대장에 줄 더하기 · 사용자 PC 의 설정 바꾸기 · git history 다시 쓰기 · force push.
- **묻지 않는다** — RULES.md · 이 문서 · 둘레 코드가 답하는 것. 답이 있으면 그대로 하고, 무엇을 따랐는지 보고에 한 줄 적는다.
- **묻는 모양** — 한 번에 모아서. 질문마다 선택지 2–4개 · 추천 하나를 맨 앞에 · 선택마다 결과 한 줄.

### D-04 요청한 만큼만 고친다

- 한 작업은 앱 하나다 (S-08). 두 앱에 걸치면 커밋을 나누고, 앱 사이는 공개 명령으로만 잇는다 (W-01).
- 보이는 김에 고치지 않는다 — 이름 바꾸기 · 줄 맞춤 · import 정리 · 주석 다듬기 · 타입 힌트 달기 · 리팩터링. 발견한 것은 보고 › 남은 위험에 적는다.
- 모듈 · 파일을 통째로 다시 쓰지 않는다. 함수 하나 · 구역 하나씩 고친다.
- 요청에 없으면 만들지 않는다 — 새 파일 · 설정 키 · 명령 · 옵션 · 의존 · 요약이나 노트나 CHANGELOG 같은 문서. 기록은 커밋 본문과 보고에 남긴다.
- 디버그 출력 · 임시 파일 · 주석 처리한 옛 코드 · `TODO` 를 남기지 않는다. 못 한 것은 보고에 적는다.

### D-05 둘레 코드처럼 쓴다

**Python 3.8 에서 도는 것만** 쓴다 (W-02 · CI 가 3.8 에서 돌린다). 자주 틀리는 것:

| 쓰지 않는 것 (3.9+) | 대신 |
|---|---|
| 사전 합치기 `a \| b` | `{**a, **b}` |
| `s.removeprefix(p)` · `s.removesuffix(p)` | `s[len(p):] if s.startswith(p) else s` |
| 실행되는 곳의 `list[int]` · `dict[str, int]` · `int \| None` | `typing.List[int]` · `Optional[int]` (주석에만 쓸 때는 `from __future__ import annotations` 가 있어야 한다) |
| `match` 문 | `if` · `elif` |
| 괄호로 묶은 여러 `with (a, b):` | `with a, b:` |
| `ast.unparse` · `functools.cache` · `zoneinfo` · `Path.is_relative_to` | `ast.get_source_segment` · `lru_cache(maxsize=None)` · 고정 오프셋 `timezone` · `relative_to` + `try` |
| `tomllib` · `datetime.UTC` · `itertools.pairwise` · `zip(..., strict=True)` | 직접 · `timezone.utc` · `zip(a, a[1:])` · 길이 확인 |
| `datetime.fromisoformat("…Z")` (3.11 부터 `Z` 를 읽는다) | `Z` 를 `+00:00` 으로 바꾼 뒤 |
| f-string 안에 같은 따옴표 `f"{d["k"]}"` (3.12) | `f"{d['k']}"` |

말은 자리마다 정해져 있다.

| 어디 | 말 |
|---|---|
| 코드 이름 (변수 · 함수 · 파일) | 영어 · 둘레의 이름 짓기 그대로 |
| 주석 · 독스트링 · 화면 문구 · 오류 글 · 점검 출력 | 한국어 · 주석 밀도는 둘레 그대로 · 점검 출력의 마지막 줄은 S-03 |
| README · MANUAL · INSTALL (사람이 읽는 문서) | 존댓말 · 짧은 문장 ([DESIGN.md › 06](DESIGN.md#06-문서와-말투)) |
| RULES · AGENTS · DESIGN · REGISTRY · SPEC · GUIDE · 이 문서 (규칙 문서) | 평서문 `…한다` |
| 커밋 · 보고 | D-10 · D-11 |

- 문서의 구분은 ` · `, 넘어가기는 `›`, 화면 이름은 en dash (`Flow–1`, S-01). 코드 · 영문 · 숫자 뒤의 조사는 띄어 쓴다 (`ui.html` 을 · `127.0.0.1` 에만).
- 새로 쓰는 코드 · 문서 · 커밋에 이모지와 폭 2칸 기호를 넣지 않는다 ([DESIGN.md › 03](DESIGN.md#03-아이콘)). 글자 폭을 시험하는 테스트 입력은 된다.
- 줄 끝 · 인코딩 · BOM 은 그 앱의 `.gitattributes` 와 S-05 그대로 둔다. 파일을 통째로 쓰는 도구를 썼으면 `git diff --stat` 으로 모든 줄이 바뀌지 않았는지 본다.
- 새 한도 · 이름 · 경로는 모듈 위의 상수로 둔다.

### D-06 있는 것만 쓴다

- 함수 · 옵션 · 설정 키 · 파일 · 명령을 코드나 문서에 쓰기 전에 저장소에서 찾아 확인한다 (`grep` · `--help`). 없으면 지어내지 않고 없다고 말한다.
- 표준 라이브러리는 3.8 에 있는 것만 쓴다 (D-05 표).
- 문서에 적는 숫자(테스트 수 · 줄 수 · 속도 · 버전)는 돌려서 얻은 값만 적는다 (W-11).
- 기억 속 다른 저장소나 옛 버전의 모양을 가져오지 않는다. 비슷한 것이 이 저장소에 있으면 그 모양을 따른다 (예: LLM 연결은 SPEC-llm.md 의 기준 구현 Secretary–1).

### D-07 테스트는 계약이다

- 버그는 실패하는 테스트를 먼저 쓰고 **지금 실패하는 것을 본다** → 고친다 → 통과를 본다.
- 기능은 테스트를 같은 커밋에 넣는다.
- 통과시키려고 테스트를 약하게 하지 않는다 — 지우기 · 건너뛰기(skip) · 기대값 느슨하게 · 제한 시간 늘리기 · `assert` 를 `try` 로 감싸기. 테스트가 틀렸다고 보면 고치기 전에 까닭을 말한다 (D-02).
- 골든 · 기대 출력 파일을 다시 쓰면 `git diff` 를 한 줄씩 보고, 의도한 줄만 남긴다.
- 테스트는 이 PC 의 실제 설정 · 데이터 폴더를 읽거나 쓰지 않는다. 임시 폴더를 `REPORT_HOME` · `FLOW_HOME` · 가짜 `HOME` 처럼 넘긴다. 외부 서비스는 가짜 서버로 (W-11).
- 가끔 실패하는 테스트의 원인은 "가끔" 이 아니다. Windows 파일 잠금 · 시간대 · 실행 순서 · 포트를 찾아 고친다.
- 문서와 코드가 다르면 테스트가 지키는 쪽이 맞다 — 문서를 고친다. 테스트가 없으면 묻는다 (D-03).

### D-08 같이 바꿀 곳을 같이 바꾼다

앱 폴더의 `AGENTS.md` 에 같은 표가 있으면 그 표가 먼저다 (예: `flow-1/AGENTS.md › 02`).

| 바꾸는 것 | 같은 커밋에서 같이 | 빠뜨리면 잡는 것 |
|---|---|---|
| `ui.html` · 내장 폰트 | `python build.py` 로 다시 만든 결과. 내장된 쪽(`INDEX_HTML` · `*_assets.py`)은 손으로 고치지 않는다 | `build.py --check` |
| 사용자에게 보이는 것 (명령 · 옵션 · 화면 · 문구 · 키) | 앱 `docs/MANUAL.md` · README 사양 | 사람 |
| 테스트 수 | README 에 적힌 테스트 수 | `works_check.py` (W-11) |
| 설정 키 | 기본값 · 검증 · `config.example.json` · MANUAL 설정 표. `llm.*` 는 SPEC-llm.md 그대로 | 앱 테스트 · `works_check.py` (S-09) |
| 공개 명령의 출력 모양 | `format` 올리기 · MANUAL · [대장 › 공개 명령](REGISTRY.md#공개-명령) | `works_check.py` (W-01) |
| 저장 파일의 모양 | 형식 버전 올리기 · 옛 버전 읽기 (W-06) | 앱 테스트 |
| 포트 · 단축키 · 환경 변수 · 데이터 폴더 · 이름 | [대장](REGISTRY.md) 먼저 (S-06). 이름은 W-09 | `works_check.py` (S-06) |
| PC 에 남기는 것 (PATH · 바로가기 · HKCU) | [대장 › PC 에 남기는 것](REGISTRY.md#pc-에-남기는-것) · `INSTALL.md` 제거 절 (W-08) | 사람 · `works_check.py` (W-08 일부) |
| 예외 대장에 적힌 위반을 고침 | 그 줄 지우기 | `works_check.py` "지워도 됨" |
| RULES.md 조항 | `AGENTS.md` 요약 · 검사기 · 예외 대장 ([RULES.md › 규칙 바꾸기](../RULES.md#규칙-바꾸기)) | `works_check.py` (RULES) |
| 기능 · 고침 | `VERSION` — 고침은 셋째 자리 · 새 기능은 둘째 자리 · 첫째 자리는 사람이 정한다. PR 하나에 한 번 | — |

### D-09 돌려 본 것만 끝났다고 한다

끝은 아래를 전부 돌리고 통과한 상태다.

| 고친 곳 | 돌릴 것 |
|---|---|
| 앱 | 그 앱 `docs/MANUAL.md` › 개발 절에 적힌 검사 · 테스트 전부. 앱 `AGENTS.md` 에 끝내기 전 목록이 있으면 그것 |
| `tools/` | `python -m unittest discover -s tools/tests` |
| 무엇이든 (문서만 고쳤어도) | `python tools/works_check.py` — 새 경고 없음 (CI 는 `--strict`) |

- Python 3.8 이 있으면 3.8 에서도 돌린다. 없으면 "3.8 은 CI 에 맡김" 이라고 보고에 적는다.
- 돌리지 못한 것은 못 돌렸다고 까닭과 함께 쓴다. "통과할 것" · "문제없어 보인다" 는 보고가 아니다.
- 실패는 출력 그대로 보인다. 줄이거나 고쳐 쓰지 않는다.

### D-10 커밋은 한 모양으로

- 제목은 S-08 모양이다. `무엇` 은 고친 결과를 사용자가 알아듣는 말로 쓴다 — `flow-1: 같은 SQL 파일을 적은 모양대로 두 번 세던 것 · Windows CI`. "버그 수정" · "리팩터링" · "업데이트" 한 낱말로 끝내지 않는다.
- 본문은 빈 줄 → 왜 (한두 줄) → `- ` 목록으로 무엇.
- 커밋 전에 `git status` · `git diff --staged` 로 의도한 파일만 들어갔는지 본다. `.gitignore` 에 걸린 것(`config.json` · 사용자 데이터 · `*.tmp` · 캐시)을 `-f` 로 넣지 않는다.
- 작업 가지에서 PR 로 낸다. `main` 에 바로 push 하지 않는다 · force push 와 남의 가지 history 다시 쓰기를 하지 않는다 · 머지는 사람이 한다.

### D-11 보고는 한 모양으로

작업을 끝내면 한국어로(사용자가 다른 말을 쓰면 그 말로) 이 틀 그대로 보고한다. 칸을 빼지 않는다 — 없으면 `없음`.

```text
## 한 일          한 줄 · 어느 앱
## 고친 곳        파일 › 함수 (설정이면 --set 줄)
## 테스트         더하거나 바꾼 테스트 이름
## 검사           D-09 의 명령마다 마지막 줄 그대로 · 못 돌린 것은 못 돌렸다고
## 부딪힌 조항    W · S · 앱 규칙 번호와 고른 길 (D-02)
## 남은 위험      못 한 것 · 사람이 볼 것 · 보이는 김에 발견한 것 (D-04)
```

- 보고에 키 · 토큰 · 사내 이름을 넣지 않는다 (W-04 · W-12).
- 앱 GUIDE 에 보고 틀이 따로 있으면(예: `flow-1/docs/GUIDE.md › 11-6`) 그 틀을 쓴다.

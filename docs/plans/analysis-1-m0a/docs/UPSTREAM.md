## 대조 방법

- M1-a 부터: 워크플로의 월 1회 예약 job `upstream` 이 위 표의 works 파일이 works `main` 에서 '옮긴 works 커밋' 뒤로 바뀌었으면 이슈를 연다. 앱 실행 경로 밖의 개발 도구다. 대조는 그 이슈가 열릴 때 한다.
- 그 전 (M0) 에는 손으로 한다. 사용자 PC 에서는 works 가 바로 위 폴더에 있다:

```text
git -C "D:\OPENCODE" fetch origin
git -C "D:\OPENCODE" log --oneline 447758f4b43ebafe7b3ec89acf7eec458ea2e27e..origin/main -- RULES.md docs/DEVELOP.md docs/DESIGN.md docs/SPEC-llm.md tools/works_check.py secretary-1/secretary-1.py secretary-1/tests/fake_llm_server.py report-1/report-1.py report-1/tests/fake_llm_server.py flow-1/flow-1.py flow-1/build.py flow-1/flow1_graph.py
```

- 바뀐 것이 있으면 따라갈지 고른다. 옮긴 코드는 이 저장소의 것이라 갈라져도 바로 깨지지는 않는다. 화면 틀 · SPEC-llm 은 따라가는 것이 기본이다 — 사용자가 works 앱과 나란히 쓰니 같은 키 · 같은 명령 · 같은 모양이어야 한다 [제안].
- 따라가면 이 저장소 파일을 고치고, 그 줄의 '옮긴 works 커밋' 을 새 SHA 로 바꾸고, 링크의 SHA 도 같이 바꾼다 (규칙이면 [RULES.md › 규칙 바꾸기](../RULES.md#규칙-바꾸기)). 사본으로 실제로 옮길 때도 그때의 SHA 로 고친다.
- 따라가지 않으면 아래 '갈라진 것' 에 까닭을 한 줄 적는다.

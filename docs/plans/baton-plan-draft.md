## 00 한 장 요약

- **무엇**: Claude Code 의 긴 세션을 논문이 말하는 "짧은 맥락" 처럼 일하게 하는 플러그인. 압축할 때 지나간 일을 줄인 요약 대신 **남은 일에 필요한 것만 고른 인수인계서** 를 쓰게 하고 (P1), 압축 직후 이어 달리는 법을 짧게 알린다 (P2). 그다음 단계로 압축 전 원본에서 필요한 줄만 찾아오고 (P5), 큰 입력은 통째로 읽지 않고 찾아서 읽게 한다 (P6). 효과는 잰 숫자로만 말한다 (P4 · P7).
- **왜**: 논문의 실험에서 맥락을 16–48K 로 묶어도 장기 작업의 정확도가 크게 떨어지지 않았고 (Opus 4.5 −3.7 – +5.6pp [논문 p.9–10]), 긴 입력은 골라 읽기만으로 오히려 올랐다 (Opus 4.5 −0.4 – +40.0pp [논문 p.11–12]). 다만 그 결과를 지킨 것은 압축 **횟수** 가 아니라 압축 **내용** 이었다 — "좋은 압축은 실행 기록의 서사가 아니라 다음 실행을 위해 골라 담은 브리핑" [논문 부록 A · p.20].
- **핵심 결정 3개**
  1. **문턱은 건드리지 않고 내용만 바꾼다.** Claude Code 의 `PreCompact` 훅은 표준 출력을 압축 요약의 지시로 쓴다 [문헌: hooks › PreCompact output — 훅 하나에 10,000자 상한]. Baton 은 이 한 자리에 논문 부록 A · G 의 인수인계 틀을 넣는다. 자동 압축 문턱 (`autoCompactWindow` · `/autocompact`) 은 바꾸지 않는다 — 정가 요금에서는 자주 압축할수록 캐시를 못 써서 오히려 비싸질 수 있기 때문이다 (02 · R1).
  2. **권한을 넓히지 않고, 고장 나도 일을 막지 않는다.** 훅은 `allow` 를 돌려주지 않고 압축을 막지 않으며, 실패하면 아무것도 하지 않은 것과 같다 (BT-01 · BT-02). 보안 도구가 아니라 일을 돕는 도구라서, 막는 쪽으로 실패하는 Diode 와 일부러 반대로 간다.
  3. **잰 다음에 키운다.** Claude Code 의 압축은 이미 구조화된 요약을 만든다 [문헌: context-window › What survives compaction]. 그래서 Baton 이 정말 보탬이 되는지는 재 보기 전에는 모른다. M0 정찰로 훅이 문서대로 도는지 보고, M3 A/B 로 켬 · 끔을 비교해서, 기준에 못 미치는 부품은 지운다 (05 › 그만두는 조건).
- **첫 마일스톤 M0 정찰** (앱 코드 0줄 · 가짜 서버 · 합성 과제): KIT-1–KIT-8 판정표가 다 차면 합격. 가장 중요한 것은 KIT-1 — `PreCompact` 의 출력이 실제 압축 요청의 어디에 · 어떤 모양으로 실리는지, 사용자가 `/compact` 에 준 지시와 어떻게 합쳐지는지.
- **솔직한 한계**: 논문은 Opus 4.5 · GPT 5.6 Sol 과 bash 하나뿐인 최소 하네스 (mini-swe-agent) 로 쟀고, 반복 실행 · 신뢰구간이 없다. Claude Code 는 하네스가 더 강하고 (자동 압축 · 하위 에이전트 · 범위 읽기 · 5개 파일 다시 읽기) 압축도 이미 구조화되어 있어서, 논문만큼의 차이는 나지 않을 수 있다. 비용 절감은 약속하지 않는다 (08).

## 01 문제 · 목표 · 비목표

### 문제

- 긴 세션은 압축을 거친다. 압축 뒤에 Claude 가 하던 일 · 사람이 정해 준 것 · 이미 안 된 방법을 잊으면 같은 일을 다시 하거나, 사람이 다시 설명해야 한다. 논문의 저자들도 사람이 끼어드는 작업에서는 압축 뒤에 사용자 선호가 사라지는 일이 흔하다고 적었다 [논문 부록 A · p.20].
- 압축 요약이 지나간 일을 고르게 줄이면 남은 일에 필요한 것이 빠진다. 논문은 요약형 압축이 모든 사실에 같은 무게를 주고 되풀이된 구간을 부풀린다고 보았다 [논문 부록 A].
- 큰 파일 · 긴 출력을 통째로 맥락에 넣으면 맥락이 빨리 차고 비싸진다. 논문에서 긴 입력을 찾아서 골라 읽은 쪽은 정가 기준으로도 비용이 크게 줄었다 (예: NIAH Opus 4.5 $74.00 → $4.00 · RULER $880.00 → $102.85 [논문 표 14 · 15 · p.28]).
- 압축으로 버려진 정확한 값 (경로 · 출력 · 오류) 이 나중에 필요해지면 되찾을 길이 마땅치 않다. 논문은 이 반례 (동전 던지기 기록) 를 들고, 대화 기록 전체를 남겨 두고 골라 읽는 도구로 되찾게 하면 풀린다고 했다 [논문 3.1 · p.10].

### 비목표

- 자동 압축 문턱 바꾸기 (`autoCompactWindow` · `CLAUDE_CODE_AUTO_COMPACT_WINDOW` · `autoCompactEnabled`). 문턱은 사람이 정한다 (W-07). Baton 은 재 본 결과를 보여 줄 뿐이다 (Q4).
- 한 행동마다 압축 (논문의 SAC) · 하위 에이전트로 세션을 잘게 끊는 지휘 루프. 띄울 때마다 비용이 들고 캐시가 깨진다. 큰 조사를 하위 에이전트로 보내라는 안내 (P3) 까지만 한다.
- 비용 절감 약속 · 모델 학습 (논문의 SSSM) · 다른 모델로 요약 · 클라우드 동기화 · 팀 공유.
- 대화 원문 · 압축 요약 본문을 따로 저장하기 (BT-03).
- Claude Code 의 압축 알고리즘을 갈아 끼우기. Baton 은 지시 한 자리와 압축 앞뒤의 안내만 다룬다.

## 03 이 도구가 할 수 없는 일

- Claude Code 가 만드는 요약을 Baton 이 직접 쓰지 않는다. Baton 은 지시를 **덧붙일** 뿐이고, 모델이 그 지시를 얼마나 따를지는 보장하지 못한다 (R2).
- 사용자가 `/compact <지시>` 를 쓰면 그 지시와 Baton 의 지시가 어떻게 합쳐지는지 문서에 없다 [미확인 — KIT-1]. Baton 의 지시는 "사용자가 준 지시가 먼저" 라고 적는다 (부록 A).
- 압축은 보안 경계가 아니다. 압축으로 맥락에서 빠진 비밀도 디스크의 대화 기록에는 남아 있다 (Claude Code 가 쓴다). Baton 은 그 기록을 지우지도 지키지도 않는다 (R8).
- 플러그인을 끄거나 Python 이 없으면 Baton 은 조용히 아무것도 하지 않는다 (BT-02). `/baton:status` 가 그 상태를 알린다.
- 웹 Claude (claude.ai) · Claude Code 가 아닌 TUI 에는 훅이 없다.

## 04 불변식

어떤 판 · 어떤 설정에서도 깨지면 안 되는 약속이다. 테스트가 하나씩 지킨다.

| # | 불변식 |
|---|---|
| BT-01 | **권한을 넓히지 않는다.** Baton 의 훅은 `permissionDecision: "allow"` 를 돌려주지 않고, 도구 입력을 고치는 `updatedInput` 을 쓰지 않는다 (`updatedInput` 은 `allow` · `ask` 와 같이 써야 하고 [문헌: hooks › PreToolUse], `allow` 는 사람의 권한 확인을 건너뛴다). 쓰는 결정은 `deny` (까닭 글은 Claude 에게 보인다) 뿐이다 |
| BT-02 | **고장 나도 일을 막지 않는다.** 모든 훅은 `onFailure: "continue"` (Claude Code 기본 · v2.1.295 이상 [문헌]) 이고, 훅 안의 예외는 표준 출력 없이 종료 코드 0 으로 끝난다. `PreCompact` 는 어떤 경우에도 압축을 막지 않는다 (종료 코드 2 · `"decision": "block"` 금지) — 문맥 한도 오류를 복구하려던 자동 압축을 막으면 그 요청이 실패하기 때문이다 [문헌: hooks › PreCompact] |
| BT-03 | **대화 원문을 디스크에 쓰지 않는다 (W-05).** `compact_summary` · 프롬프트 · 도구 출력 · 파일 내용을 저장하지 않는다. 저장하는 것은 개수 · 길이 · 시각 · 경로의 sha256 앞 16자뿐이다. 사람이 확정한 결정 (P7) 만 예외이고, 저장하기 전에 무엇이 저장되는지 보인다 |
| BT-04 | **비밀을 다시 퍼뜨리지 않는다 (W-04).** 저장 · 출력 전에 키 · 토큰 꼴을 검사해 걸리면 저장하지 않고 출력에서는 가린다 (`[가림 n자]`). 비밀 값을 명령줄로 받는 옵션을 만들지 않는다 |
| BT-05 | **맥락에 넣는 글에는 상한이 있다.** `PreCompact` 출력 4,000자 · `SessionStart` 출력 1,500자 · 원본 찾기 (P5) 한 번에 8,000자 · 골라 읽기 거절 까닭 300자 [제안 — 문서 상한 10,000자보다 넉넉히 아래] |
| BT-06 | **숫자는 잰 것만 말한다 (W-11).** README · 화면 · 문서에 적는 효과 · 비용 숫자는 M3 A/B 키트를 돌려 얻은 값과 그 조건 (모델 · 판 · 과제 수 · 반복 수) 만 적는다 |
| BT-07 | **Claude Code 내부 형식은 믿지 않는다.** 대화 기록 JSONL 처럼 공개 계약이 아닌 것을 읽는 코드는 모르는 모양이면 "못 읽음" 으로 끝내고, 짐작으로 채우지 않는다 |
| BT-08 | **사람이 정한 설정을 바꾸지 않는다 (W-07).** 사용자 · 프로젝트 · 관리형 설정 파일을 쓰지 않는다. 압축 문턱 · 권한 · 모델은 사람이 바꾼다. Baton 이 쓰는 곳은 자기 데이터 폴더뿐이다 |

## 05 모양 — 네 갈래와 고른 것

| 갈래 | 무엇 | 좋은 점 | 나쁜 점 |
|---|---|---|---|
| A 스킬만 | `SKILL.md` 에 인수인계 · 골라 읽기 안내 | 가장 쉽다 · 위험 없음 | 압축 순간에 개입하지 못한다. 스킬 본문은 압축 뒤 다시 실리지만 한 스킬 5,000 토큰까지 잘린다 [문헌: context-window] |
| **B 훅 + 스킬 (고름 · M1)** | `PreCompact` 지시 · `SessionStart`(compact) 안내 · `PostCompact` 개수 세기 · 스킬 | 압축 내용 한 자리를 바로 바꾼다 · 디스크에 남는 것이 거의 없다 | 지시를 모델이 따르는지 보장 못 함 (R2) |
| C B + 명령 · 도구 (M2 · 조건부) | 원본 찾기 (P5) · 골라 읽기 거절 (P6) · 결정 고정 (P7) | 논문의 나머지 둘 (3.1 · 부록 E) 까지 | 내부 형식 의존 (R5) · 마찰 (R6) · 저장 (R7) |
| D 지휘 루프 | 하위 에이전트로 한 행동씩 (SAC 흉내) | 논문의 가장 짧은 맥락 | 비용 · 캐시 · 복잡도. 비목표 |

- 고른 길: **B 로 시작하고, C 의 부품은 M0 정찰과 M3 A/B 가 허락할 때만 하나씩 더한다.** D 는 하지 않는다.

### 그만두는 조건 [제안 · 결과를 보기 전에 적는다]

- M3 A/B 에서 P1 (압축 지시) 을 켠 쪽이 G1 을 못 지키면 (성공률 −1pp 넘게 떨어짐) P1 을 지운다.
- G2 · G3 를 둘 다 못 넘는 부품은 지운다. 남는 부품이 없으면 저장소를 보관 (archive) 으로 돌리고, 측정 결과만 README 에 남긴다.
- KIT-1 에서 `PreCompact` 출력이 압축 요청에 실리지 않으면 B 전체를 멈추고 A 로 내려간다.

### P1 인수인계 지시 — 정해 둔 것

- 틀은 부록 A 의 글이다. 제목 여덟 개를 순서대로 쓰게 하고, 쓸 것이 없으면 "없음" 이라고 쓰게 한다 — 빈 제목이 사라지면 P4 가 셀 수 없다.
- 첫 줄에서 "사용자가 `/compact` 에 준 지시가 있으면 그것이 먼저다" 라고 적는다 (03 · KIT-1 이 합쳐지는 모양을 확인한다).
- 출력은 4,000자 안 (BT-05). P7 의 결정이 붙어도 넘지 않게 결정 쪽을 자른다 (앞에서부터 남긴다 · 잘랐다고 한 줄).
- 입력에서 읽는 것은 `trigger` · `custom_instructions` 의 있음 · 없음 · `session_id` 뿐이다. `custom_instructions` 의 글은 저장하지 않는다 (BT-03).
- 예외 · 시간 초과 · 모르는 입력 → 아무것도 내지 않는다. 그러면 Claude Code 의 기본 압축 그대로다 (BT-02).

### P2 이어 달리기 안내 — 정해 둔 것

- `source` 가 `compact` 일 때만 낸다. `startup` · `resume` · `clear` · `fork` 에서는 내지 않는다 (P7 이 생기면 `resume` 도 [제안 — KIT-7]).
- 내용은 짧게 (1,500자 안): 인수인계서의 "사람이 정한 것" · "남은 계획" 부터 확인하라 · 정확한 값이 필요하면 짐작하지 말고 다시 얻거나 (좁은 명령) P5 로 찾아라.
- Claude Code 는 압축 직후 최근에 고친 파일 다섯 개를 다시 읽어 준다 (5,000 토큰이 넘는 파일은 경로만) [문헌: context-window]. P2 는 그것을 되풀이하지 않는다.

### P4 개수 세기 — 정해 둔 것

- 세션마다 한 파일 `stats\<YYYY-MM>\<session_id 의 sha256 앞 16자>.json` 을 원자적으로 덮어쓴다 (W-06). 칸: `format` · `version` · `compactions` (`manual` · `auto` 각각) · `summary_chars` (회마다) · `summary_headings` (회마다 0–8) · `reads_after_compact_repeat` · `read_denials` · `recall_calls`.
- 경로는 sha256 앞 16자로만 남긴다. 파일 이름 · 경로 원문 · 요약 본문은 남기지 않는다 (BT-03).
- 비용 · 토큰은 훅 입력에 없다. 대화형 세션의 실제 사용량은 statusLine 입력에 오지만, 플러그인이 statusLine 을 걸 수 있는지는 [미확인]. M3 A/B 는 `claude -p` 의 JSON 출력으로 잰다 [미확인 — KIT-8].

### P5 원본 찾기 — 조건 (M2)

- 대화 기록 JSONL 은 Claude Code 의 내부 형식이다 (BT-07). KIT-4 가 판마다 "압축 경계 · 그 앞 메시지 · 도구 출력을 찾을 수 있다" 를 확인한 판에서만 켠다. 모르는 판이면 "못 읽음".
- 부르는 길 둘 중 KIT-5 가 고른다: (가) `python "<플러그인>/baton.py" recall --grep "<정규식>"` 를 Bash 로 — 권한 창을 거친다 · Bash 가 막힌 곳에서는 못 쓴다. (나) 표준 입출력 MCP 도구 `recall` — 권한 창이 없지만 MCP 서버가 자기 세션의 기록 파일을 알아낼 길이 있어야 한다 [미확인].
- 돌려주는 것: 맞은 줄의 앞뒤 몇 줄 · 8,000자 상한 · "다음 창" 명령 · 키 꼴 가림 (BT-04). 정규식은 시간 · 크기 상한을 둔다 (지나친 되돌아 찾기로 멈추지 않게).

### P6 골라 읽기 거절 — 조건 (M2)

- Claude Code 의 `Read` 는 이미 기본으로 앞쪽 일부만 읽는다 (이 세션의 도구 설명 기준 2,000줄). 그래서 P6 이 아껴 줄 것은 줄이 아주 긴 파일 (한 줄 JSON · 로그) 정도다 [미확인 — KIT-6 이 큰 Read 한 번이 실제로 몇 토큰을 싣는지 잰다]. 아껴 줄 것이 적으면 P6 은 만들지 않고 P3 안내로 끝낸다.
- 만들면: 범위 (`offset` · `limit`) 없이 크기 256 KiB [제안] 를 넘는 파일만 `deny`. 같은 파일을 범위와 함께 다시 부르면 통과. 셸의 `cat` · `type` 은 보지 않는다 (명령 풀이는 믿을 수 없다 · 알려진 한계).
- `updatedInput` 으로 범위를 대신 넣어 주는 길은 쓰지 않는다 (BT-01). 한 턴을 더 쓰는 대신 권한을 건드리지 않는다.

### P7 결정 고정 — 조건 (M2)

- Claude Code 는 압축 뒤 프로젝트 `CLAUDE.md` · 자동 메모리 · 계획 모드의 계획을 디스크에서 다시 싣는다 [문헌: context-window]. 오래 갈 규칙은 거기에 두면 된다. P7 은 **이번 작업에서만 유효한 사람의 결정** ("이번에는 공개 API 를 바꾸지 않는다") 을 위한 것이다.
- KIT-7 이 "기본 압축 요약이 사람의 결정을 잃는다" 를 합성 대화로 보여 줄 때만 만든다. 잃지 않으면 만들지 않는다.
- 저장은 세션마다 (`pins\<session_id 의 sha256 앞 16자>.json`) · 14일 [제안] 뒤 지운다. 저장하기 전에 저장될 글을 그대로 보인다 — 명령이 Claude 에게 "글을 보여 주고 확인을 받은 뒤 `baton.py pin add` 를 표준 입력으로" 를 시키고, 사람은 Bash 권한 창에서 그 글을 본다 (W-05 · W-07). 키 꼴이면 거절 (BT-04).

## 07 플러그인 한 묶음 · 자리 · 설정

```text
baton/                               저장소 = 플러그인 = 마켓플레이스 [제안 — Q2]
├─ .claude-plugin/plugin.json        이름 baton · 버전
├─ .claude-plugin/marketplace.json   이 저장소를 마켓플레이스로
├─ skills/baton/SKILL.md             P3 — 중요한 줄을 위에
├─ commands/                         /baton:status · /baton:handoff · (M2) /baton:recall · /baton:pin
├─ hooks/hooks.json                  PreCompact · PostCompact · SessionStart(compact) · (M2) PreToolUse(Read)
├─ baton.py · batonlib/              표준 라이브러리만 — 훅 · 상태 · 개수 · (M2) recall · pin
├─ kit/                              M0 정찰 · M3 A/B (가짜 서버 · 합성 과제)
└─ docs/ · tests/ · tools/
```

- **훅 꼴**: exec 꼴 (`command` = `python` · `args` = `["${CLAUDE_PLUGIN_ROOT}/baton.py", "hook", "<이벤트>"]`) · `onFailure: "continue"` · `timeout` 5초 [제안] (문서 기본은 600초 — 압축 앞에서 오래 기다리지 않게). 명령은 이름 `python` 만 적는다 — 절대 경로를 적으면 훅이 고장 났을 때 사용자 이름이 든 경로가 Claude 에게 갈 수 있다.
- **데이터 자리**: `%LOCALAPPDATA%\baton\` (Windows 밖 `~/.local/share/baton/`) — W-06. `${CLAUDE_PLUGIN_DATA}` 는 쓰지 않는다 (플러그인을 지우면 같이 지워져 사람이 모르는 사이에 기록이 사라진다 · 제거는 INSTALL › 제거 절에서 사람이 지운다). 테스트는 환경 변수 `BATON_HOME` 으로 옮긴다.
- **설정**: v1 은 설정 파일이 없다. 켜고 끄는 것은 플러그인 켜기 · 끄기 하나다 (`/plugin`). M2 부품이 생기면 부품마다 끄는 키 하나씩 [제안 — Q3].
- **명령 · 종료 코드** (works S-03 그대로): `baton.py hook <이벤트>` · `status` · `stats [--month YYYY-MM]` · `check` · `version` · `help` · (M2) `recall` · `pin`. 점검 출력의 마지막 줄은 `결과: OK` · `결과: 확인 필요` · `결과: 점검 실패`.
- **다른 플러그인과 같이**: 코드 · 설정 · 명령을 서로 쓰지 않는다. 같은 PC 에 Diode 가 깔려 있으면 Diode 방에서는 Bash · 다른 MCP 가 막혀 P5 (가) · (나) 와 P7 이 돌지 않는다. P1 · P2 는 그 세션이 이미 가진 글만 다루므로 새 길을 열지 않는다 [미확인 — KIT-8 에서 둘을 같이 깔고 한 번 본다]. 그 밖의 특별 처리는 하지 않는다 (Q6).

## 08 비용 — 정직한 기대

- 논문의 "창이 작으면 싸다" 는 추정 요금 (부록 B) 이고, 우리가 내는 것은 토큰 수 × 정가다. Claude Code 문서에서 맥락 길이에 따른 할증을 본 것은 Haiku 5.5 (100K 토큰 넘는 요청) 하나다 [문헌: model-config]. 다른 모델의 단가 구조는 정가표로 확인한다 [미확인 — KIT-8]. 그래서 그 이득은 우리에게 그대로 오지 않는다고 보고 계획한다 (02).
- P1 · P2 는 압축 횟수를 바꾸지 않으므로 비용은 거의 같아야 한다 — 요약이 길어지면 그만큼 는다. G3 (+10% 안) 가 그 상한이다.
- P6 · P3 의 골라 읽기는 큰 파일 작업에서 입력 토큰을 줄일 수 있다 (논문에서 정가로도 준 유일한 갈래). 얼마나 줄지는 KIT-6 · M3 전에는 숫자를 약속하지 않는다.
- P5 는 찾아온 만큼 토큰을 더 쓴다. 다시 하는 일을 줄여 갚는지는 G2 로 잰다.
- M3 A/B 자체가 API 비용을 쓴다 (과제 × 반복 × 켬 · 끔). 한도는 사람이 정한다 (Q5).

### A 인수인계 지시 원문 (초안 · P1 · P2)

`PreCompact` 가 낼 글 (논문 부록 G 의 틀을 한국어로 옮기고, 사람의 결정 칸을 더했다):

```text
[baton 인수인계] 사용자가 /compact 에 준 지시가 있으면 그 지시가 먼저다. 이 글은 그다음이다.
이 요약은 지나간 일의 기록이 아니라, 다음에 이어서 일할 사람에게 넘기는 인수인계서다.
지나간 일을 고르게 줄이지 말고, 남은 일에 필요한 것만 골라 적는다. 아래 제목을 이 순서 그대로 쓰고, 쓸 것이 없으면 "없음" 이라고 쓴다.
1. 원래 과제 - 사용자가 맡긴 일을 거의 그대로. 도중에 바뀐 요구가 있으면 바뀐 것까지.
2. 사람이 정한 것 - 사용자가 고르거나 금지하거나 바란 것. 사용자의 말에 가깝게.
3. 지금 하던 일 - 하던 일과 그 까닭, 바로 다음 한 걸음 (명령이나 고칠 곳까지).
4. 확인된 사실 - 정확한 경로, 이름, 명령, 관찰한 값, 중요한 오류. 확인한 것과 추측을 나눠 적는다.
5. 바꾼 것 - 바꾸거나 만든 파일마다 무엇을 바꿨고 검증했는지.
6. 검증 - 돌린 검사와 결과, 실패, 우회한 방법.
7. 막다른 길 - 해 봤지만 안 된 방법 (다시 하지 않게).
8. 남은 계획 - 남은 하위 목표를 할 순서대로, 그리고 끝났다고 볼 조건.
필요한 출력이 잘렸으면 그것을 다시 얻을 좁은 명령을 적는다. 관찰하지 않은 것을 지어내지 않는다. 키, 토큰, 비밀번호는 적지 않는다.
```

`SessionStart`(compact) 가 낼 글:

```text
[baton] 방금 대화가 압축되었다. 위 인수인계서의 "2. 사람이 정한 것" 과 "8. 남은 계획" 부터 확인하고 이어서 한다.
정확한 값 (경로, 출력, 오류) 이 필요하면 짐작하지 말고 좁은 명령으로 다시 얻는다.
```

- 문장 부호는 ASCII 와 한글만 쓴다 (긴 줄표 · 가운뎃점은 어떤 터미널의 붙여 넣기에서 빠질 수 있다 — Diode 에서 겪은 일과 같은 까닭).

## 00 한 장 요약

- **답부터**: 된다. 다만 "가렸다가 보내고, 돌아오면 되돌린다" 그대로는 안 된다. 이름 · 식별자는 가려지지만, 지켜야 할 기술의 본체 (공정 조건 · 수치 · 구조 · 순서) 는 가려도 **뜻이 남는다**. 그래서 원칙을 바꾼다 — **가린 원자료를 보내는 게 아니라, 원자료가 필요 없는 일만 Claude 에게 준다.** Claude 가 받는 것은 사내 단어 · 숫자 · 파일 · 그림 · 코드 원문이 없는 **일의 모양** (brief) 이다.
- **모양 (05 · 6판에서 바꿈)**: Claude 가 앞이다. 사용자는 Terminal–1 의 Claude 채널에서 Claude CLI 와 일하고, Claude 는 다이오드의 도구로 opencode (사내 LLM · 원자료) 에 일을 넘긴다. 일을 넘기면 Claude 는 '전달함' 한 줄만 받는다. opencode 의 결과 · 로그 · 오류는 Claude 에게 가지 않고, 사내 LLM 이 쓴 **봉인 보고** 만 사람이 확정한 뒤 Claude 에게 간다. 순방향 (밖 › 안) 은 흐르고 역방향 (안 › 밖) 은 막히는 다이오드 그대로다.
- **Claude CLI 에 플러그인 하나 (07 · 7판)**: 사용자는 Claude CLI 에서 일한다. Diode 는 Claude CLI 에 설치하는 플러그인 `diode` 이고, 그 안에 스킬 (일하는 법) · 훅 (막는 힘) · MCP 허브 (봉인 · 확정 창 · 일꾼 잇기) · 명령 (`/diode:setup` · `/diode:room` …) · 표준 라이브러리 프로그램이 같이 들어 있다. 설치하면 그 사람의 모든 Claude CLI 세션에서 훅이 돈다 — 방이면 방 규칙, 원자료 폴더면 막음, 그 밖은 안전벨트.
- **Terminal–1 은 선택 (07 · 7판)**: Terminal–1 에서 Claude CLI 를 여는 것은 사내에서 고르는 튜닝이다 — [사내 작업 지침](terminal-1-claude-guide.md). Diode 는 Terminal–1 없이 Claude CLI 만으로 돈다. 일꾼 opencode 는 사용자가 포트를 정해 띄워 두고 (예: `opencode --port 4096`), 그 주소를 플러그인 설정에 한 번 넣는다.
- **사내 마무리 (07 · Q5)**: 이 저장소는 사내 TUI 를 볼 수 없다. 일반 부분은 여기서 합성 자료로 만들고, 사내 TUI 어댑터 · 사내 PC 정찰 · 코드 최종 검토는 사내 Claude 가 한다. 경계는 앱 문서 `docs/INHOUSE.md` 로 고정하고, 사내 이름은 공개 저장소로 되돌아오지 않게 막는다 (W-12).
- **공개 라이브러리 질문 (06 · Q7)**: 된다. 다만 원문 코드 · 원문 오류 글이 아니라 사내 LLM 이 일반 이름으로 다시 쓴 **합성 재현 코드** 로만, 허용 목록에 있는 라이브러리만.
- **모델 · effort (07 · 3판)**: Claude 쪽은 손잡이가 둘 — 모델 (Opus 급 · Sonnet 급) × effort (`low` – `max`). 사내 LLM 이 어려움을 제안하고, 다이오드가 기본값을 고르고, 사람이 확정 창에서 아무 조합으로나 바꾼다. opencode 쪽은 손잡이가 하나 — 모델 (글 · 그림) 뿐이고, 어려운 일은 effort 대신 일을 더 잘게 나눠 다룬다. effort 는 나가는 바이트를 바꾸지 않으므로 보안 손잡이가 아니라 비용 · 품질 손잡이다.
- **스킬 문장은 벽이 아니다 (AL-09)**: LLM 이 지키는 규칙은 확률이다. 막는 일은 결정적 코드 (검사기) · 권한 (opencode · Claude Code) · 사람의 확정 창이 한다. SKILL.md 는 길 안내일 뿐이다.
- **세 겹**: ① 사내 LLM 이 원자료를 일의 모양으로 **추상화** (brief.json — 닫힌 형식) ② 결정적 검사기 D1–D6 + 사내 LLM 2차 판정 D7 이 **막는 쪽으로 실패** ③ 사람이 확정 창에서 **보낼 바이트 그대로** 확인 (D8). 돌아오는 길에서는 가명 토큰을 되돌리되, 코드에는 글자 치환 대신 **묶기 파일** 을 안쪽에서 만든다 (06).
- **사람이 Claude Code 를 직접 쓸 때 (안전벨트)**: 가장 흔한 사고는 사람이 원문을 붙여 넣는 것이다. 같은 검사기를 Claude Code 의 `UserPromptSubmit` 훅 (프롬프트를 Claude 에 닿기 전에 막는다 [문헌]) 과 `PreToolUse` 훅 (원자료 폴더 읽기를 막는다 [문헌]) 에 건다. M1 에 넣는다.
- **이 도구가 못 하는 것 (02)**: 법적 판단 · 회사 승인 · 회사 망 DLP 를 대신하지 못한다. 같은 PC · 같은 계정에서 셸을 쥔 LLM 앞에서는 PC 안의 어떤 장치도 단단한 벽이 아니다 (L-11). **보안 부서가 이 설계를 보고 허용 범위를 정하기 전까지 실데이터는 0** 이다 (AL-10 · Q4).
- **예산과 보안이 같은 쪽을 가리킨다 (08)**: Claude 를 지휘자로 긴 에이전트 대화를 돌리면 맥락이 쌓여 한도를 금방 쓴다. 짧은 brief 한 번 → 답 한 번인 자문역이 훨씬 싸다 [추정].
- **첫 걸음**: M0 정찰 (앱 코드 0줄 · 합성 자료만) — 가짜 Claude 서버를 127.0.0.1 에 띄워, 깨끗한 방에서 연 대화형 Claude 세션이 **실제로 무엇을 보내는지 바이트로** 본다 (KIT-1 — 작업 폴더 경로 · 사용자 이름 · 방 안내 글이 시스템 프롬프트에 실리는지). 그다음 M1 은 사람이 복사 · 붙여 넣는 손 다리 + 안전벨트다.

### 이름과 정체

**이름 — Diode (`diode`).** 다이오드는 전류를 한쪽으로만 흘리는 소자다. 이 도구에서 순방향은 밖 › 안 (Claude 의 답이 들어온다), 역방향은 안 › 밖 (원자료 — 막힌다) 이다. 역방향 누설 전류에 해당하는 것은 사람이 확정한 봉인 글 (brief) 뿐이다.

- **이름의 함정 (R18)**: 보안 쪽에서 "데이터 다이오드" 는 물리적으로 한 방향 통신만 되는 망연계 장비를 뜻한다. 이 도구는 그것이 아니다 — 소프트웨어이고, 봉인 글은 나가고 답은 들어오며, 같은 PC 안에 단단한 벽이 없다 (02). 보안 부서 설명 한 장 (T4) · README · MANUAL 첫머리에 "이름은 비유다. 하드웨어 데이터 다이오드와 같은 보증을 주지 않는다." 를 적는다.

**정체 — Claude CLI 에 설치하는 플러그인 하나 (7판).** Claude CLI 에 이 플러그인을 배우게 하면 지금까지의 기능이 켜진다. 다만 막는 힘이 어디서 나오는지는 겹마다 다르다.

| 플러그인 안의 겹 | 무엇 | 막는 힘 |
|---|---|---|
| 스킬 (`skills/diode/SKILL.md`) | Claude 가 다이오드로 일하는 법 — 토큰으로 말하기 · `dispatch` 로 넘기기 · `inbox` 로 보고 받기 · 사내 말은 말 봉인 칸으로 | 없다 — 안내다 (AL-09) |
| 훅 (`hooks/hooks.json`) | 세션의 프로젝트 폴더로 모드를 가른다 — 방 · 원자료 폴더 · 그 밖. 사람이 치는 말 검사 · 도구 호출 막기 | 있다 — 결정적 코드 · Claude CLI 안에서 |
| MCP 허브 (`.mcp.json` › `diode.py mcp`) | 도구 넷 · 가명 표 (메모리) · 확정 창 · 일꾼 opencode 에 지시 넣기 · 보고 받기 | 있다 — 바깥으로 가는 유일한 길 (AL-01) |
| 명령 (`/diode:setup` · `/diode:room` · `/diode:dict` · `/diode:status`) | 처음 설정 · 방 만들기 (방의 권한 규칙 · statusLine 을 방 설정에 씀) · 사전 · 상태 | 설정을 만든다 |
| 프로그램 (`diode.py` · 표준 라이브러리) | 검사기 D1–D8 · seal · unseal · 확정 창 · 감사 기록 — 훅 · 허브 · 명령이 모두 이것을 부른다 | 있다 — 결정적 코드 |

- 스킬만 배우게 하면 안 된다. 스킬은 LLM 에게 주는 글이라 LLM 이 지키지 않으면 끝이다. 그래서 "스킬" 이 아니라 **플러그인** 으로 낸다 — 같은 설치 한 번에 훅과 허브가 같이 들어온다.
- 플러그인이 할 수 없는 것 [문헌: Claude Code plugins-reference 2026-11-05]: 권한 규칙 · statusLine 을 실어 나르지 못한다 (플러그인 설정은 `agent` · `subagentStatusLine` 만). 그래서 방의 권한 deny 규칙과 statusLine 은 `/diode:room` 이 방 폴더의 프로젝트 설정에 쓴다.
- 플러그인 밖에서 필요한 것 셋: Python 3.8 이상 (훅 · 허브가 돈다) · 일꾼을 쓸 때는 포트를 정해 띄운 opencode · 처음 설정 (`/diode:setup` — 사전 · 원자료 폴더 목록 · 일꾼 주소). 일꾼이 없어도 방 · 안전벨트 · 말 봉인 · 자문은 돈다.
- opencode 쪽에는 설치할 것이 없다. 허브가 지시마다 일꾼 안내문 (보고 꼴 · `propose` 쓰는 법 · 원문을 넣지 말 것) 을 붙인다. opencode 의 권한 예시 (`opencode/`) 는 선택이다.
- 저장소 하나 = 플러그인 하나 = 마켓플레이스 하나다 (works W-01 의 뜻 · 09).

다이오드도 역전압을 너무 걸면 항복한다. 그래서 확정 창이 있다.

## 01 문제 · 목표 · 비목표

### 문제

- Claude 사용량에 월 한도가 있다. 사내 LLM 은 한도가 없지만 기획 · 화면 설계는 Claude 가 낫다고 본다. 둘을 나눠 쓰고 싶다.
- 나눠 쓰는 순간 자료가 두 모델 사이를 오간다. 사내 LLM 이 만진 것 (코드 · 결과 · 오류 글 · 파일 이름) 은 원자료가 묻어 있다. 오가는 길마다 새는 길이 생긴다 (03).

### 목표 (잴 수 있게)

| # | 목표 | 재는 법 | 문턱 [제안] |
|---|---|---|---|
| G1 | 바깥 바이트에 원자료가 없다 | 합성 자료에 카나리아 (지어낸 비밀 문자열 · 꼴 바꾼 변형 포함) 를 묻고, 가짜 Claude 서버가 받은 바이트 전부에서 찾는다 | 1,000 시나리오에서 0 |
| G2 | 막는 쪽으로 실패한다 | 검사기 오류 · 사내 LLM 응답 없음 · 시간 초과 · 사전 비어 있음 · 창 닫음 · 모르는 형식을 하나씩 일으킨다 | 모든 경우 안 나감 (테스트) |
| G3 | brief 가 쓸모 있다 | 합성 과제에서 Claude 가 brief 만 보고 낸 계획 · UI 초안을 사내 LLM 이 이어서 구현할 수 있나 | 사람 판정 5점 중 4 이상 |
| G4 | 싸다 | 자문 한 번 · UI 초안 한 번의 실제 토큰 (KIT-6) | 자문 한 번이 월 한도의 1% 이하 |
| G5 | 사람이 읽을 수 있다 | 확정 창에서 보낼 내용을 읽고 판단하는 시간 | 1분 안 (brief 크기 상한으로 맞춘다) |
| G6 | 재식별을 알아챈다 | brief 로 원래 단어를 추측할 수 있게 일부러 만든 시나리오에서, Claude 답에 사전 단어가 되돌아오면 U2 가 잡는다 | 잡는 비율을 M0 에서 재고 문턱을 정한다 |

### 비목표

- 원자료를 "안전하게 만들어" 보내는 도구가 아니다. 그런 변환은 없다고 보고 설계한다.
- Claude 에게 사내 코드의 리뷰 · 디버깅 · 데이터 분석을 맡기지 않는다. 원문 코드 · 데이터가 있어야 하는 일은 안쪽 일이다. 공개 라이브러리 질문은 합성 재현 코드로만 된다 (Q7).
- 사내 TUI 를 고치지 않는다 (Q5). Terminal–1 같은 works 앱도 고치지 않는다 — 고쳐야 하면 그 앱의 따로 된 기획 · 커밋이다 (W-01 · Q10).
- 회사 망 DLP · 보안 부서 승인 · 법적 판단을 대신하지 않는다 (02).
- 그림을 바깥으로 보내지 않는다. 사내 화면 캡처는 안쪽의 그림 모델이 읽는다.

## 02 먼저 정할 것 — 이 도구가 할 수 없는 일

정직하게 적는다. 이 칸을 건너뛰고 만들면, 도구가 있다는 사실이 "안전하다" 는 착각을 만든다.

1. **허용 범위는 회사가 정한다.** 어떤 등급의 무엇이 Claude 로 가도 되는지 (예: 일반 프로그래밍 질문은 되나 · 업무 화면 구조는 되나) 는 보안 부서가 정한다. 이 도구는 그 범위를 기계로 지키는 장치일 뿐이다. 정해 주지 않으면 기본값은 **아무것도 안 보냄** 이다.
2. **같은 PC 안에는 단단한 벽이 없다.** 사내 LLM 이 셸을 쓰면, 그 계정이 할 수 있는 일은 다 한다 — `claude` 명령을 직접 부를 수도, 설정 파일을 고칠 수도 있다. 그래서 opencode 셸 권한을 기본 `ask` 로 두고 (사람이 명령마다 본다), 회사 망 쪽 DLP 가 Claude 로 가는 통신을 보는지 확인한다 (Q4). 남는 위험은 리스크 R1 에 적는다.
3. **사람이 마지막 문이다.** 확정 창이 있어도 사람이 읽지 않고 누르면 소용없다. 그래서 brief 를 작게 묶고 (G5), 걸린 곳 · 이번 달 횟수를 크게 보인다.
4. **너무 많이 막으면 사람은 도구를 끈다.** 오탐이 많으면 사용자는 다이오드를 비켜 Claude 에 직접 붙여 넣는다 — 가장 나쁜 결과다. 쓰기 쉬움도 보안 성질이다 (R6).

## 04 불변식

어떤 판 · 어떤 설정에서도 깨지면 안 되는 것이다. 테스트가 하나씩 지킨다.

| # | 불변식 |
|---|---|
| AL-01 | **바깥으로 가는 길은 하나다.** 봉인된 글을 바깥 쪽에 건네는 코드는 다이오드의 건네기 (07) 와 다이오드 도구 `inbox` 에만 있고, 둘 다 확정 창이 보인 바이트만 옮긴다. 스킬 · 에이전트 문서에는 Claude 에 닿는 다른 방법을 적지 않는다 |
| AL-02 | **사람이 창에서 눌러야 나간다.** 확정은 tkinter 창의 버튼으로만 한다. 확정을 건너뛰는 옵션 · 환경 변수 · 설정 키를 만들지 않는다 (테스트는 프로세스 안에서 함수를 바꿔 끼운다). 창이 없는 환경에서는 보내지 않는다 |
| AL-03 | **막는 쪽으로 실패한다.** 검사기 예외 · 시간 초과 · 사내 LLM 응답 없음 · 사전 비어 있음 · 모르는 `format` · 창 닫힘 → 안 보냄 |
| AL-04 | **일의 모양만 나간다.** 바깥으로 가는 것은 brief.json 을 정해진 틀로 펼친 글뿐이다. 숫자 · 그림 · 파일 · 코드 원문 · 경로 · 주소가 없다. 크기 상한이 있다 |
| AL-05 | **가명 표는 안쪽에만, 매번 새로.** 토큰은 무작위다 (해시 금지 — 사전이 있으면 해시는 거꾸로 풀린다). 같은 단어도 자문마다 다른 토큰이다 |
| AL-06 | **Claude 가 닿는 곳에는 봉인된 것만 있다.** Claude 세션은 깨끗한 방에서만 열고, 방 프로필 (07) 이 방 밖 읽기 · Bash · 다이오드 밖 MCP · WebFetch 를 막는다. Claude 가 쓸 수 있는 다이오드 도구는 넷 (`dispatch` · `inbox` · `status` · `jobs`) 뿐이다. 방 프로필을 걸 수 없는 TUI 면 A′ 를 쓰지 않는다 (C 만). 원자료 폴더에서 연 Claude 세션은 어떤 경우에도 일하는 자리가 아니다 |
| AL-07 | **나간 것은 모두 남긴다.** 보낸 바이트 그대로 · sha256 · 시각 · 모델 · 토큰 수를 감사 기록에 남긴다. 확정 창이 "이 내용이 기록에 남습니다" 를 먼저 보인다 (W-05) |
| AL-08 | **들어온 것은 믿지 않는다.** U1–U5 를 통과해야 안쪽 파일이 된다. 돌아온 코드는 안쪽에서 테스트를 거친 뒤에만 쓴다 |
| AL-09 | **스킬 문장은 벽이 아니다.** 금지는 코드 · 권한 · 창이 지킨다. SKILL.md 에만 있는 금지는 금지로 세지 않는다 |
| AL-10 | **실데이터는 승인 뒤.** 설정 `policy.real_data` 기본 `false` — 그동안은 합성 자료 표시가 있는 brief 만 보낸다. 이 값은 창에서 사람만 바꾼다 (`--set` 거부) |
| AL-11 | **막은 까닭에 걸린 단어를 쓰지 않는다.** 출력 · 로그 · 훅의 까닭 글에는 `사전 단어 2개 (D2) · 3줄` 처럼 개수 · 검사 번호 · 줄만. 훅의 까닭 글은 Claude 가 읽기 때문이다 |
| AL-12 | **보안에 걸린 설정은 바깥에서 못 바꾼다.** 사전 위치 · 검사 문턱 · 정책은 환경 변수 · 명령줄로 덮어쓰지 않는다. 테스트용 `DIODE_HOME` 만 있고, 데이터 폴더가 기본 위치가 아니거나 사전이 비면 보내지 않는다 |
| AL-13 | **방은 확정된 것만 읽는다.** 방 프로필은 `outbox` 파일의 sha256 이 감사 기록의 확정 목록에 있을 때만 읽기를 허락한다. 같은 계정이라 벽은 아니지만 (R1), 확정 없이 방에 들어간 파일은 조용히 지나가지 못한다 |
| AL-14 | **안쪽의 출력은 Claude 에게 가지 않는다.** `dispatch` 가 돌려주는 것은 고정된 꼴 (`sent` · `job` · 오류 번호) 뿐이다. 사내 LLM 의 응답 · 로그 · 오류 글 · 파일 내용 · 파일 이름은 어떤 도구의 결과로도 Claude 에게 가지 않는다. Claude 가 받는 안쪽 소식은 사람이 확정한 봉인 보고 (`kind: "report"`) 뿐이다 |
| AL-15 | **안쪽으로 가는 지시도 사람이 본다.** `dispatch` 는 기본으로 확정 창에 토큰을 되돌린 지시를 보이고 사람이 넘긴다 (6판 기본 · 사용자 조건 '보안 위험 없게'). 모든 지시는 기록에 남고, Terminal–1 의 일꾼 채널에 그대로 보인다 |

## 05 모양 — 네 갈래와 고른 것

| | A. Claude 가 지휘 · 결과를 그대로 받음 | **A′. Claude 가 앞 · 돌아오는 길만 다이오드 (6판 · 확정)** | B. opencode 가 지휘 · Claude 는 자문 | C. 사람이 다리 |
|---|---|---|---|---|
| 흐름 | Claude 가 `opencode run` 으로 사내 LLM 을 부리고 결과를 받는다 | Claude 가 다이오드 도구 `dispatch` 로 일을 넘긴다 → 사내 LLM 이 원자료로 일한다 → 사내 LLM 이 쓴 보고를 다이오드가 봉인하고 사람이 확정해야 Claude 에게 간다 | 사내 LLM 이 일을 나누고 기획 · UI 초안만 Claude 에게 묻는다 | 사람이 봉인 글을 복사해 붙여 넣는다 |
| 사람이 일하는 자리 | Claude | **Claude (Terminal–1 Claude 채널)** | opencode | 둘 다 |
| Claude 의 도구 | 파일 · 셸 | 방 안 파일 · 다이오드 도구 넷 · 웹 검색 (07) | 방 안만 | 사람이 쓰는 Claude 의 도구 |
| 바깥으로 가는 길 | 많다 — 사내 LLM 의 모든 결과가 Claude 맥락으로 (L-03) | 하나 — 봉인 보고 (AL-01 · AL-14) | 하나 | 하나 (사람 손) |
| 예산 | 많이 | 중간 — Claude 가 대화를 쥐지만 보고가 짧다 (08) | 적게 | 적게 |
| 약한 곳 | 원자료가 곧장 샌다 | 바깥 Claude 가 안쪽 일꾼을 조종한다 (L-24) · 확정 횟수가 는다 (R5) | 사내 LLM 의 지휘 능력 | 자동화가 적다 |
| 판정 | **하지 않는다** — 제약이 바로 깨진다 | **목표 모양 (M2–M3)** | 5판까지의 목표 — A′ 안에 `room` 자문으로 남는다 | **첫 배포 (M1)** · 비상 길 |

- A 와 A′ 는 지휘자가 같고 돌아오는 길만 다르다. 그 한 길이 전부다.
- C 를 먼저 내는 까닭은 그대로다: 자동 호출 없이도 쓸모가 있고, 다이오드의 핵심 (봉인 · 검사기 · 창 · 되돌리기) 을 그대로 쓴다.
- 비유하면, Claude 에게는 사랑채를 내주고 심부름꾼을 부를 종을 준다. 종은 울리되, 심부름꾼이 서재에서 가져온 것은 사람이 보고 나서야 사랑채로 건너간다.

## 06 다이오드 — seal · 창 · 건네기 · unseal

```text
안쪽 (사내 PC · 원자료)                                   바깥 (Claude)
사내 LLM ── brief.json ──> seal ──> 확정 창 (사람) ──> 건네기 ──> 사내 TUI 의 Claude
   ^                       D1–D7      D8 · 기록 AL-07   clipboard    (깨끗한 방 · 방 프로필)
   |                                                    room · adapter      |
   |                                                                        v
 구현 · 테스트 <── 묶기 파일 · 결과 <── unseal (U1–U5 · 가명 되돌리기) <──── 답
```

### brief.json — 닫힌 형식 (부록 A)

- 사내 LLM 이 원자료를 보고 쓰는 **일의 모양**이다. 키가 닫혀 있고 (모르는 키 = 거부), 칸마다 길이 상한이 있고, 자유 글 칸은 적다.
- 사람 · 화면 · 항목 · 단계는 이름 대신 가명 토큰과 **닫힌 종류** (`화면` · `항목` · `단계` · `표` · `역할`) 로 적는다. 사람은 이름이 아니라 역할로만 나온다.
- 항목은 뜻 대신 **꼴** 로 적는다 — `숫자 · 단위 있음` · `범주 · 값 7개 안팎` 은 되고, 단위 이름 · 값 범위 · 실제 범주 이름은 안 된다.
- 다이오드가 brief.json 을 정해진 틀로 펼쳐 프롬프트 글을 만든다. Claude 는 brief.json 에 없는 것을 하나도 받지 않는다.
- 종류 (`kind`) 는 넷: `report` (사내 LLM 이 Claude 에게 보내는 일꾼 보고 — 6판의 주된 바깥 글) · `plan` (기획) · `ui` (UI/UX 초안) · `lib` (공개 라이브러리 질문 — 아래 · Q7). `report` 는 상태 (`done` · `blocked` · `question`) · 닫힌 숫자 칸 (바뀐 파일 수 · 통과 · 실패한 테스트 수 — D4 의 예외 · 0–9999) · 일반 말로 쓴 결과 요약 · 열린 질문만 갖는다. 코드 원문 · 로그 · 오류 원문 · 파일 이름은 칸이 없다.
- `route` 칸 (07 › 모델 · effort 고르기) 은 **안쪽 전용** 이다. 사내 LLM 이 어려움 (`difficulty`) 과 effort 제안을 닫힌 값으로 적고, 다이오드는 이 칸을 펼친 글에 넣지 않는다 — 건네기가 모델 · effort 를 TUI 에 맞추는 데만 쓴다. 자유 글 칸 (까닭 등) 을 두지 않는다.

### 가명 토큰

- 꼴: `PH_` + 무작위 대문자 · 숫자 4자 (예: `PH_K7Q2`). 코드 식별자 · 문자열 · 글 어디에 들어가도 깨지지 않는 꼴을 골랐다. 자문마다 새로 뽑는다 (AL-05).
- 표 (토큰 → 진짜 단어) 는 **메모리에만** 있다 (Q6 확정) — seal 부터 unseal 까지 창 하나가 열려 있는 동안만 산다. 창을 닫으면 그 자문의 답은 되돌릴 수 없고, 다시 seal 한다. `room` 건네기로 답을 기다리는 동안에도 창은 열려 있다.

### 나가는 검사 D1–D8

모두 통과해야 창의 보내기 단추가 켜진다. 하나라도 걸리면 고쳐서 다시 seal 한다 — 자동으로 가려서 보내지 않는다 (가린 결과를 사람이 보지 않으면 확정이 아니다).

| # | 검사 | 무엇을 |
|---|---|---|
| D1 | 형식 | brief.json 스키마 · 닫힌 키 · 칸별 길이 · 전체 크기 상한 (예: 펼친 글 8 KB [제안]) · `route` 의 닫힌 값 |
| D2 | 사전 | 사용자가 확정한 사내 단어 (제품 · 공정 · 과제 · 고객 · 시스템 이름 · 약어). 대소문자 · 띄어쓰기 · 하이픈 · 한영 표기 변형까지 |
| D3 | 꼴 | 경로 (`C:\` · `\\` · `/home`) · URL · IP · 호스트 · 메일 · 사번 · 로트 · 부품 번호 꼴 (사용자가 정규식으로 더함) · 날짜와 시각 |
| D4 | 숫자 | 자유 글에 숫자 금지. 구조에 필요한 개수는 닫힌 칸 (`count` 0–99) 으로만 [제안] |
| D5 | 덩어리 | 코드 블록 · base64 · hex · 엔트로피가 높은 문자열 — 원문이 숨어 나가는 길 |
| D6 | 토큰 | `PH_` 꼴만 · brief 안의 토큰이 모두 표에 있음 |
| D7 | 사내 LLM 판정 | "이 글이 특정 회사 · 공정 · 제품 · 수치 · 사람을 드러내는가" 를 사내 LLM 에 묻는다 ([SPEC-llm.md](../SPEC-llm.md) 의 `llm` 설정). 예 → 막음 · 응답 없음 → 막음 (AL-03). 보조 검사일 뿐 D2–D6 을 대신하지 않는다 |
| D8 | 사람 | 확정 창에서 **보낼 바이트 그대로** 를 본다. 토큰 강조 · 걸릴 뻔한 곳 · 모델 · 예상 비용 · 이번 달 누계 · "보내면 되돌릴 수 없습니다" |

- 사전 만들기: `dict suggest <폴더>` 가 안쪽에서 프로젝트를 훑어 후보 (자주 나오는 고유 명사 · 식별자) 를 내고, 사용자가 창에서 확정한다 (W-07). 사전은 데이터 폴더에만 있고 출력에 단어를 찍지 않는다 (AL-11).

### 공개 라이브러리 질문 — `kind: "lib"` (Q7)

- 되는 것: "공개 라이브러리 X 로 Y 를 하려면" · "이런 꼴의 예외는 무엇이 원인인가" 를 일반 말과 **합성 재현 코드** 로 묻는 것. 사내 코드를 그대로 붙이는 질문은 안 된다 — 사내 LLM 이 일반 이름으로 다시 쓴 최소 재현만.
- 합성 재현 코드 규칙 (D5 의 `lib` 예외 · 결정적 · 세부는 T6):
  - 라이브러리는 허용 목록 (`policy.lib_allow` — 이름 · 판) 에 있는 것만. 목록은 사용자가 창에서 확정하고, 보안 부서에 보이는 질문에 넣는다 (KIT-5). 사내 패키지 이름은 사전 (D2) 에 있으므로 따로 막힌다.
  - 식별자는 언어 예약어 · 내장 이름 · 허용 라이브러리의 공개 이름 · 정해진 자리 이름 (`df` · `a` · `b` · `x` · `y` · `col_1`–`col_9` · `item` · `value` [제안]) · `PH_` 토큰만. 공개 이름 목록은 안쪽에 설치된 판에서 뽑는다 [제안 — T6].
  - 문자열 값은 자리 글 (`"a"` · `"b"` · `"x"`) 만 · 주석 금지 (주석은 자유 글이라 새는 길) · 숫자는 코드 안에서만 세 자리까지 · 40줄 상한 [제안].
  - 오류 글은 원문을 붙이지 않는다. 예외 이름 + 합성 재현으로 다시 만든 메시지만 (원문 오류 글에는 경로 · 파일 이름 · 값이 낀다 — L-06).
- 라이브러리 이름 자체가 많은 것을 말할 수 있다. 장비 제어 · 특정 공정 분야의 라이브러리는 무엇을 만드는지 드러낸다 (L-19 · R16).
- 돌아온 답의 API 는 지어낸 것일 수 있다. 사내 LLM 이 안쪽에 설치된 판으로 돌려 확인한 뒤 쓴다 (U5).

|---|---|---|
| U1 | 토큰 | 표에 없는 토큰 · 꼴이 깨진 토큰 (`ph_k7q2` · `PH_K7Q`) 을 줄과 함께 보인다. 아는 토큰만 되돌린다 |
| U2 | 역유입 | 답에 사전 단어가 있으면 — Claude 가 brief 만 보고 진짜 단어를 맞혔다는 뜻이다 → 그 주제의 자문을 멈추고 사람에게 알린다 (brief 가 재식별될 수 있었다) |

### 코드에는 치환 대신 묶기

- 기획 글은 토큰을 진짜 단어로 바꿔 쓴다 (글자 치환).
- UI 코드는 바꾸지 않는다. 진짜 항목 이름에 띄어쓰기 · 한글이 있으면 코드가 깨지고, 치환 실수는 조용히 틀린 화면을 만든다. 대신 Claude 는 `FIELDS.PH_K7Q2` 처럼 토큰으로만 짜고, 다이오드가 안쪽에서 **묶기 파일** (`binding.local.js` — 토큰 → 진짜 이름 · 표시 글) 을 만든다. 묶기 파일은 안쪽에만 있고 커밋하지 않는다.

### 감사 기록

- `%LOCALAPPDATA%\diode\audit\` 에 자문마다 한 파일: 보낸 바이트 · sha256 · 시각 · 모델 · 토큰 수 · 결과 (보냄 · 버림 · 막힘과 검사 번호). 가명 표 · 원문은 없다.
- "무엇을 보냈나" 를 나중에 증명할 수 있어야 한다. 보안 부서가 요구하는 보존 기간 · 형식은 Q4 에서 받는다.

## 07 호스트 — Claude 가 앞 · opencode 일꾼 · 깨끗한 방 · 안전벨트

### 플러그인 한 묶음 (7판)

```text
diode/                               저장소 = 플러그인 = 마켓플레이스
├─ .claude-plugin/plugin.json        이름 diode · userConfig (일꾼 주소 · Python 명령 · opencode 비밀번호는 sensitive)
├─ .claude-plugin/marketplace.json   이 저장소를 마켓플레이스로
├─ skills/diode/SKILL.md             Claude 가 다이오드로 일하는 법 (안내)
├─ commands/                         /diode:setup · /diode:room · /diode:dict · /diode:status
├─ hooks/hooks.json                  SessionStart · UserPromptSubmit · PreToolUse — 모드별로 막는다 (onFailure block)
├─ .mcp.json                         허브: python ${CLAUDE_PLUGIN_ROOT}/diode.py mcp
├─ diode.py · diode/                 표준 라이브러리 — 검사기 · 봉인 · 확정 창 · 허브 · 상태 명령
├─ opencode/                         (선택) 일꾼 opencode 의 권한 예시
└─ docs/ · tests/ · tools/diode_check.py
```

- **설치** (다른 사람도 같은 길): `/plugin marketplace add <diode 저장소>` → `/plugin install diode@diode` → `/diode:setup`. 회사가 관리형 설정으로 마켓플레이스 · 플러그인을 묶어 두었으면 그 길을 따른다 [미확인 — KIT-2].
- **모드** — 훅과 허브는 세션의 프로젝트 폴더 (`CLAUDE_PROJECT_DIR` [문헌]) 로 가른다:

| 모드 | 언제 | 훅 · 허브 |
|---|---|---|
| 방 | 프로젝트 폴더가 `/diode:room` 으로 만든 방 (방 표지 · 방 설정이 그대로) | 방 프로필 (07 › 깨끗한 방) · 허브 도구 넷 켬 |
| 원자료 폴더 | 프로젝트 폴더가 설정 `policy.raw_dirs` 아래 | 모든 프롬프트를 막는다 ("원자료 폴더에서 Claude 를 열었습니다 — `/diode:room` 으로 방을 여세요") · 모든 도구 호출 deny · 허브 도구 끔 |
| 그 밖 | 보통 폴더 | 안전벨트 — 사람이 치는 말 검사 · `policy.raw_dirs` 를 건드리는 파일 도구 deny · 허브 도구 끔 |

- **데이터 자리**: `%LOCALAPPDATA%\diode\` (W-06). 플러그인 데이터 폴더 (`${CLAUDE_PLUGIN_DATA}`) 는 플러그인을 지우면 같이 지워진다 [문헌] — 감사 기록이 사라지면 안 되므로 쓰지 않는다. 지우는 법은 INSTALL › 제거에 `[질문]` 으로.
- **일꾼 주소 · 비밀번호**: 플러그인 `userConfig` 의 `worker_url` (기본 `http://127.0.0.1:4096` · 127.0.0.1 만) — Terminal–1 이 `DIODE_WORKER_URL` 을 넘기면 그것이 앞선다. opencode 비밀번호는 `sensitive` userConfig (Claude Code 가 안전한 저장소에 둔다 [문헌]) 또는 opencode 의 `OPENCODE_SERVER_PASSWORD`. 명령줄로 받지 않는다 (W-04).
- **Python**: 훅은 exec 꼴로 `<python> ${CLAUDE_PLUGIN_ROOT}/diode.py hook …` 을 부른다. Windows 의 훅 기본 셸은 Git Bash 가 없으면 PowerShell 이다 [문헌] — exec 꼴로 셸을 피한다. Python 이 없으면 훅이 실패하고 `onFailure: "block"` 이라 Claude CLI 가 막힌다 → `/diode:setup` 이 먼저 확인하고, 막힐 때의 문구가 고치는 법을 알려 준다 (R23).
- **`bin/` 은 두지 않는다** — Bash PATH 에 올라가는데 방에서는 Bash 를 막고, claude.ai · Cowork 는 `bin/` 이 있는 플러그인을 설치하지 않는다 [문헌].

|---|---|---|---|
| 사내 LLM (글 · 큰 모델) | 지휘 · 원자료 읽기 · brief 쓰기 · D7 판정 · 구현 · 테스트 · 묶기 · 리뷰 | 본다 | 모델만 |
| 사내 LLM (그림) | 사내 화면 캡처 읽기 · 돌아온 UI 초안을 안쪽에서 렌더한 그림 검토 | 본다 | 모델만 |
| Claude Opus 급 (1M) | 기획 · 구조 설계 · 어려운 판단 | 못 본다 | 모델 · effort |
| Claude Sonnet 급 (1M) | UI/UX 초안 (HTML 한 파일 · 합성 자료) · 공개 라이브러리 질문 — 출력이 길어 싼 쪽 | 못 본다 | 모델 · effort |

### 모델 · effort 고르기 (3판 · 사용자 요구)

**Claude 쪽 — 손잡이 둘.** 모델 × effort. [문헌: Claude Code model-config 문서 2026-11-05]

- 사내가 쓰는 두 모델 (Opus 5 · Sonnet 5 계열) 은 effort `low` · `medium` · `high` · `xhigh` · `max` 를 모두 받고, 기본은 `high` 다. 모델이 받지 않는 값을 주면 Claude Code 가 그 아래 받는 값으로 낮춘다. 같은 이름의 effort 라도 모델마다 눈금이 다르다.
- 고르는 순서: ① 사내 LLM 이 brief 의 `route` 에 어려움 (`simple` · `normal` · `hard` · `critical`) 과 effort 제안 (`auto` · `low` – `max`) 을 닫힌 값으로 적는다 ② 다이오드가 아래 기본표로 모델 · effort 를 고른다 ③ **사람이 확정 창에서 아무 조합으로나 바꾼다** — 막지 않는다. 창은 고른 조합의 어림 비용 [추정] 과 이번 달 누계를 같이 보인다. `auto` 는 effort 를 정하지 않고 모델 기본을 따른다.
- 기본표 [제안 — KIT-6 비용 · G3 품질로 고친다]:

| 일 (`kind` · 어려움) | 모델 | effort |
|---|---|---|
| `plan` · `critical` (갈림길이 많은 구조 설계) | Opus 급 | `xhigh` (사람이 `max` 로 올릴 수 있다) |
| `plan` · `hard` | Opus 급 | `high` |
| `plan` · `normal` · `simple` (다듬기 · 열린 질문 정리) | Opus 급 | `medium` · `low` |
| `ui` · `hard` 이상 (새 화면 · 상호작용이 많음) | Sonnet 급 | `high` |
| `ui` · `normal` · `simple` (고치기) | Sonnet 급 | `medium` · `low` |
| `lib` · `hard` 이상 (원인이 깊은 오류) | Sonnet 급 | `high` |
| `lib` · `normal` · `simple` (사용법) | Sonnet 급 | `medium` · `low` |

- 건네기마다 맞추는 법 [문헌 · 사내 판은 KIT-2 · T16]:
  - `clipboard`: 확정 창이 "세션 준비 줄" 을 따로 복사하게 보인다 — `/model <설정 이름>` · `/effort <값>`. Claude Code 는 세션 도중 `/effort` 로 바꿀 수 있고, 다음 메시지부터 새 값이 적용된다. 그다음에 봉인 글을 붙여 넣는다.
  - `room`: 방은 자문마다 새로 연다. 다이오드가 방 설정 (`.claude/settings.json`) 에 `model` 과 `effortLevel` 을 그 자문의 값으로 쓴다. 다만 설정 파일의 `effortLevel` 은 `max` 를 받지 않는다 — `max` 면 창이 세션 준비 줄 `/effort max` 를 복사하게 보인다 (세션 안의 `/effort` 는 `max` 를 받는다 [문헌]). 실제로 걸린 effort 는 방의 statusLine 이 받은 `effort.level` 로 확인한다 (07 › Terminal–1 에서 같이 쓰기).
  - `adapter`: 계약의 `put` 이 `route` (모델 · effort) 를 같이 받는다. 사내 TUI 가 effort 를 받지 못하면 어댑터 `check()` 가 그렇게 알리고, 창은 effort 칸을 "TUI 기본" 으로 잠근다.
- 우선순위 주의 [문헌]: 환경 변수 `CLAUDE_CODE_EFFORT_LEVEL` 이 가장 앞서고, 그다음 세션 안의 `/effort` · 실행 때 `--effort` · 설정 순이다. 사용자 환경에 그 변수가 있으면 다이오드가 고른 값이 무시된다 → 창이 "환경 변수가 effort 를 덮어씀" 을 알린다. 회사가 관리형 설정 `maxEffortLevel` 로 상한을 걸었으면 그 위로는 올라가지 않는다.
- effort 는 **나가는 바이트를 바꾸지 않는다** — 보안 손잡이가 아니다. D1–D8 은 effort 와 상관없이 똑같이 돈다. 다만 effort 가 높을수록 Claude 가 brief 에서 원래 단어를 더 잘 맞힐 수 있으므로, U2 역유입 경보는 effort 와 상관없이 늘 켠다.

**opencode 쪽 — 손잡이 하나.** effort 가 없고 모델만 바꾼다 (사용자 환경).

- 에이전트 둘 [문헌: opencode 문서 › agents — 에이전트마다 모델 · M0 에서 판 확인]: `diode` (주 에이전트 · 사내 글 모델) · `diode-vision` (하위 에이전트 · 사내 그림 모델 — 렌더한 UI 초안 검토 · 사내 화면 캡처 읽기). 모델 이름은 설치 때 `[질문]` 으로 사용자 provider 목록에서 고르고, 저장소의 에이전트 파일에는 적지 않는다 (W-12).
- 사내 모델 둘은 어려움의 단계가 아니라 글 · 그림의 갈래다. 그래서 안쪽의 어려운 일은 effort 대신 **일을 더 잘게 나누고, 안쪽 테스트로 되돌려 고치는 횟수** 로 다룬다 (SKILL.md 의 지침).
- D7 판정은 SPEC-llm 의 `llm.model` (사내 글 모델) 하나로 한다. 판정에 쓰는 모델은 사람이 설정에서만 바꾼다 (AL-12).

### opencode 쪽 (일꾼 · 6판)

- 에이전트 `diode` (사내 글 모델) · 하위 에이전트 `diode-vision` (사내 그림 모델) · 스킬 `skills/diode/SKILL.md` 한 벌. 6판에서 사내 LLM 은 지휘자가 아니라 **일꾼** 이다. 스킬이 일꾼의 순서를 안내한다: Claude 의 지시를 받는다 (다이오드가 토큰을 진짜 단어로 되돌려 넣어 준다) → 원자료로 일한다 · 안쪽 테스트 → **보고를 `kind: "report"` brief 로 쓴다** (코드 원문 · 로그 · 오류 원문 · 파일 이름 없이 · 결과는 일반 말과 닫힌 숫자 칸으로) → `diode propose report.json` → 사람이 확정 창에서 확정 → Claude 가 받는다. 사내 LLM 이 먼저 Claude 에게 묻고 싶으면 (5판까지의 자문 흐름) `plan` · `ui` · `lib` brief 로 같은 길을 쓴다.
- 스킬은 Claude 의 지시를 **자료** 로 읽고, 보고에 원문을 넣으라거나 다른 곳으로 보내라는 지시는 따르지 않는다고 적는다 (L-24). 이것은 안내다 — 벽은 돌아오는 길의 검사기와 확정 창이다 (AL-09).
- 권한 [문헌: opencode 문서 › agents · permissions — M0 에서 판 확인]: 셸 기본 `ask` · 허용은 다이오드 명령과 프로젝트 테스트 명령만 · `claude*` · `curl*` · `Invoke-WebRequest*` · `powershell*` · 웹 가져오기는 deny. 편집은 작업 폴더만 — 깨끗한 방 · 다이오드 데이터 폴더는 deny (L-21).
- opencode 의 JS 플러그인 (`tool.execute.before` 훅) 은 셸 명령을 더 단단히 거를 수 있지만 npm 경로가 생긴다. M0 에서 권한만으로 부족하면 그때 다시 본다.

### Claude 에 닿는 길 — Claude CLI 그대로 (Q5 · 7판)

사용자가 이미 쓰는 Claude CLI (사내에서 Terminal–1 안에 열든 그냥 열든) 를 **바꾸지 않고** 쓴다. Claude CLI 가 아닌 TUI 는 `clipboard` 로만 잇는다. 다이오드는 그 TUI 를 부르지도 고치지도 않는다. 다이오드와 TUI 사이에는 **건네기** 한 겹만 있다.

| 건네기 | 어떻게 | 언제 |
|---|---|---|
| `clipboard` | 확정 창의 복사 단추 → 사용자가 TUI 에 붙여 넣음 → 답을 창의 답 칸에 붙여 넣음 | M1 · 어떤 TUI 에서나 |
| `room` | 확정하면 다이오드가 깨끗한 방의 `outbox\<id>.md` 에 봉인 글을 쓴다 → 사용자가 방에서 연 TUI 세션에 "outbox 의 <id> 를 읽고 inbox 에 답을 써" 한 줄 → `inbox\<id>.md` 가 생기면 창이 unseal | M2 · 방 프로필을 걸 수 있는 TUI 만 |
| `adapter` | 사내 TUI 에 맞춘 얇은 어댑터 (TUI 가 입력 파일 · 명령을 받는다면). 계약만 여기서 정하고 구현은 사내에서 (아래 사내 마무리) | 사내 마무리 뒤 |

- 건네기가 무엇이든 바깥으로 가는 바이트는 확정 창이 보인 것과 같다 (AL-01 · AL-02). 건네기는 글을 옮길 뿐 만들지 않는다.
- 헤드리스 (`claude -p`) 는 기본으로 쓰지 않는다. 1판의 헤드리스 프로필은 부록 E 로 옮겨 두고, 사내에서 필요하면 `adapter` 의 한 갈래로 다시 꺼낸다.
- 새 Windows Terminal 의 `Ctrl+V` 는 `…` `—` `“ ”` `•` 같은 글자를 빠뜨릴 수 있다 [문헌: Terminal–1 MANUAL › 알려진 한계]. 그래서 seal 이 펼치는 글은 ASCII 문장 부호만 쓰고 [제안 — T6], 가명 토큰은 ASCII 라 이 문제를 비켜 간다. 그래도 깨지면 U1 이 깨진 토큰을 잡는다.

### 깨끗한 방

- 방은 Claude 세션을 여는 폴더다. 안에는 다이오드가 쓴 것만 있다: `outbox\` (확정한 봉인 글) · `inbox\` (답) · 방 안내 글 (다이오드가 쓰는 고정 글 — "outbox 만 읽고 inbox 에만 써라"). 안내 글은 길 안내이지 벽이 아니다 (AL-09).
- 벽은 **방 프로필** 이 한다. 사내 TUI 가 Claude Code 라면 방 폴더의 프로젝트 설정 (`.claude/settings.json`) 에 건다 — 방에서 열 때만 적용되고 사용자 설정을 건드리지 않는다 [문헌: hooks 문서 · 사내 판은 KIT-2]:
  - `PreToolUse` — Read · Write · Edit · Glob · Grep 은 방 안만. `Bash` · `WebFetch` · `mcp__*` 는 deny (Bash 는 경로 검사로 거를 수 없다). 웹 검색 (`WebSearch`) 은 쓴다 (Q9) — Claude 는 봉인 글만 알므로 검색어도 봉인 글에서만 나온다. 들어온 검색 결과는 L-22. `WebFetch` 는 Claude 가 고른 주소로 요청이 나가는 길이라 [미확인 — 어디서 나가는지 KIT-2] deny 로 두고, 필요하면 사람이 방 설정에서 연다.
  - `PreToolUse` 의 Read 가 `outbox` 파일이면 sha256 이 감사 기록의 확정 목록에 있어야 한다 (AL-13 · L-21).
  - `UserPromptSubmit` — 사람이 방 세션에 직접 치는 글도 scan.
  - 모든 훅에 `onFailure: "block"`.
- 사내 TUI 가 Claude Code 가 아니어서 이런 훅이 없으면 `room` 을 쓰지 않는다 — `clipboard` 만 (AL-03 · AL-06).
- 방 위치: 작업 폴더 경로가 시스템 프롬프트에 실릴 수 있다 [미확인 — KIT-1]. 경로에 사용자 이름 · 사번이 들어가지 않는 곳을 KIT-1 결과로 정한다 [제안: `D:\DIODE\room`].
- 자문마다 대화를 새로 시작한다 (Claude Code 면 `/clear`). 앞 자문의 맥락이 쌓이지 않게 — 모자이크 (L-05) 와 비용 (08) 둘 다 때문이다.

### Claude 가 앞에서 — 세 흐름과 허브 (6판)

사용자는 Terminal–1 의 Claude 채널에서 Claude CLI 와 일한다. 오가는 길은 셋이고, 길마다 문이 다르다.

| # | 흐름 | 방향 | 문 |
|---|---|---|---|
| ① | 사람 › Claude (사람이 치는 말) | 안 › 밖 | 안전벨트 `UserPromptSubmit` 가 사전 단어 · 경로 · 숫자 꼴을 막는다. 사내 이야기가 필요하면 확정 창의 **말 봉인** 칸에 사내 말로 쓰고, 다이오드가 토큰으로 바꾼 글을 사람이 확인해 붙여 넣는다 |
| ② | Claude › opencode (일 넘기기 · `dispatch`) | 밖 › 안 (순방향) | Claude 가 아는 것은 봉인 글뿐이라 안쪽으로 가는 것 자체는 새지 않는다. 다이오드가 토큰을 진짜 단어로 되돌린 지시를 확정 창에 보이고 사람이 넘긴다 (AL-15 · 기본 켬). Claude 에게는 `{"sent": true, "job": "J-0007"}` 만 돌아간다 (AL-14) |
| ③ | opencode › Claude (보고 · `propose` › `inbox`) | 안 › 밖 (역방향) | 사내 LLM 이 쓴 `report` brief → D1–D8 → 사람 확정 → 방 `outbox` → Claude 가 `inbox` 로 받는다. 이 길 밖으로 안쪽 소식이 Claude 에게 가는 길은 없다 |

- **허브 = 다이오드 MCP 서버** (`diode.py mcp`): Claude Code 가 방에서 띄우는 표준 입출력 MCP 서버다 (방의 프로젝트 MCP 설정 · 포트 없음 · W-03). 표준 라이브러리 JSON-RPC 로 짠다 [제안 — 판 호환은 KIT-7]. 세션 동안 살아 있으면서 가명 표를 **메모리에** 쥐고 (Q6 그대로), 확정 창을 띄우고, 일꾼이 낸 보고 (`propose`) 를 받는다. Claude 세션이 끝나면 표도 사라진다.
- **Claude 의 다이오드 도구 넷** (입력 · 출력 꼴 고정 · 크기 상한 · L-27):

| 도구 | Claude 가 주는 것 | Claude 가 받는 것 |
|---|---|---|
| `dispatch` | 지시 글 (토큰 포함) · 방에 쓴 첨부 파일 이름 (UI 초안 등 — 안쪽으로 복사) | `sent` · `job` · 오류 번호 |
| `inbox` | 없음 또는 `job` | 확정된 봉인 보고 (outbox 의 것만) |
| `jobs` | 없음 | 일 목록 — `job` · 상태 (`sent` · `working` · `reported` · `rejected`) · 시각 |
| `status` | 없음 | 일꾼 연결 · 확정 대기 수 · 이번 달 사용 (상태 명령과 같은 칸) |

- **일꾼에 넣는 길**: 허브는 짝지은 opencode 서버 (Terminal–1 이 넘겨주는 127.0.0.1 주소 `DIODE_WORKER_URL` — Terminal–1 사내 작업 지침 › 04-6) 의 세션에 지시를 넣는다. Terminal–1 의 compose 칸이 쓰는 opencode HTTP 와 같은 길이다 [문헌: Terminal–1 MANUAL › 08 · 정확한 끝점은 KIT-7]. 주소가 127.0.0.1 이 아니면 넣지 않는다. 일꾼의 응답은 허브가 읽지 않는다 — 일꾼이 끝나면 스스로 `propose` 한다.
- **첨부**: Claude 가 방에 쓴 UI 초안 같은 파일은 `dispatch` 의 첨부로 안쪽 작업 폴더에 복사한다 (순방향). 복사하기 전에 U3 (바깥 주소) 를 거치고, 묶기 파일 (06) 로 진짜 항목 이름에 잇는다.
- **확정이 늘어난다**: 지시 하나에 확정 둘 (넘기기 · 보고). 승인 피로 (R5) 를 줄이려고 확정 창은 지시 · 보고를 한 줄 요약과 바뀐 곳 강조로 보이고, 같은 일 (`job`) 의 보고는 지시와 나란히 보인다. 넘기기 확정을 끄는 손잡이는 M0 · M4 결과를 보고 사람이 정한다 — 6판 기본은 켬이다.

### (선택) Terminal–1 에서 같이 쓰기 — 사내 튜닝 (Q10 · 7판에서 선택으로)

사용자는 사내 Claude Code 를 Terminal–1 안에서 쓰면서 이 도구를 같이 쓰려 한다. Terminal–1 은 지금 opencode 전용이다 — 상태 · 입력 · 사용량 · 펫 칸이 모두 opencode 의 127.0.0.1 HTTP · SSE 를 본다 [문헌: Terminal–1 MANUAL › 08 구조]. 그래서 Terminal–1 에 **Claude 채널** 을 새로 더하고, 6판에서는 그 채널이 사람이 일하는 자리가 되어 opencode 채널을 일꾼으로 짝짓는다. 그 일은 Terminal–1 의 따로 된 기획 ([terminal-1-claude-plan-draft.md](terminal-1-claude-guide.md)) 이고, 이 절은 다이오드 쪽에서 맞출 것만 적는다.

```text
Terminal–1 창
├─ 00 overview      두 채널을 한눈에
├─ 01 diode         Claude 채널 · 사람이 일하는 자리 · 사내 Claude Code · 다이오드 방 폴더
│                   Claude ──dispatch──> 다이오드 허브 ──(토큰 되돌림 · 확정)──> 02 에 지시
│                   Claude <──inbox──── 방 outbox <── 사람 확정 <── 다이오드 검사 <── 02 의 report
│                   오른쪽: DIODE 칸 (확정 대기 · 일 목록 · 이번 달) · 아래: 02 일꾼의 상태 (허락 대기 칩)

                    지시를 받아 일하고 report brief 를 propose · 허락 요청은 사람이 여기서 답한다
```

- **상태 명령 (바깥 인터페이스)**: 다이오드가 읽기 전용 명령 하나를 낸다 — `diode.py --status --json [--room "<폴더>"]`, 표준 출력에 UTF-8 JSON, `format` 1. Diode 는 works 밖이라 works 대장의 공개 명령 표에는 오르지 않는다. 대신 MANUAL › 바깥 인터페이스에 적고, `format` 을 올리는 규칙은 works W-01 과 같게 지킨다 (T11). 부르는 쪽은 Terminal–1 이다.
  - 내주는 것: 그 폴더가 방인지 · 방 프로필 상태 (`ok` · `missing` · `changed`) · 안전벨트 켜짐 여부 · 일꾼 연결 · 확정 대기 · outbox · inbox 대기 수 · 일 목록 (job · 상태) · 이번 달 사용 (statusLine 으로 받은 실제 값 · 없으면 어림이라는 표시) · 마지막으로 걸린 effort. 칸 이름 · 값 범위는 [Terminal–1 사내 작업 지침 › 04-5](terminal-1-claude-guide.md) 의 계약이 정본이다.
  - 내주지 않는 것: 사전 단어 · 봉인 글 · 답 · 가명 표 · 감사 기록 내용 · 정규식 · 모델 이름 (사내 이름이다). Terminal–1 칸은 화면 공유 · 스크린샷에 찍힐 수 있다.
- **Terminal–1 이 Claude 채널을 여는 문턱** (Terminal–1 사내 작업 지침 › 04-4 의 요약): 방이면 연다 · 방이 아니면 안전벨트가 켜졌을 때만 경고와 `[질문]` 뒤에 · 다이오드 명령이 없거나 실패하거나 모르는 `format` 이면 Claude 채널을 열지 않는다. W-01 의 "그 기능만 끄고 계속 돈다" 가 여기서는 곧 막는 쪽 실패다.
- **statusLine — 실제 사용량과 effort 확인**: 방 프로필에 `statusLine` 으로 `diode.py --statusline` 을 건다 [문헌: statusline 문서 2026-11-05 — 프로젝트 설정에 둘 수 있고, 표준 입력 JSON 에 `cost.total_cost_usd` · `context_window.total_input_tokens` · `context_window.total_output_tokens` · `model` · `effort.level` · `session_id` 가 온다 · 300ms 로 묶어 돈다]. 다이오드는 이 중 비용 · 토큰 · 모델 · effort 만 감사 기록에 더하고, 같이 오는 `transcript_path` 는 열지 않는다. 한 줄 출력 예: `DIODE  room ok  effort high  month 12%`. 사내 판에서 칸 이름이 다르면 사내 마무리에서 맞춘다 (T16).
- 사내 마무리의 검토 세션 (`D:\OPENCODE\diode`) 도 Terminal–1 Claude 채널로 연다. 방이 아니므로 안전벨트 + `[질문]` 길이다.

### 사내 마무리 — 사내 Claude 가 최종 검토 (Q5)

이 저장소에서는 사내 TUI 를 볼 수 없다 (W-12). 그래서 일반 부분은 여기서 합성 자료로 만들고, 사내에서만 할 수 있는 부분은 사내 Claude 가 마무리한다. 그 경계를 앱 문서 `diode/docs/INHOUSE.md` 로 고정한다 (T15).

| 여기서 (공개 저장소 · 합성 자료) | 사내에서 (사내 Claude · 사내 PC) |
|---|---|
| 다이오드 본체 · 검사기 · 확정 창 · 건네기 `clipboard` · `room` · 방 프로필 · 안전벨트 · 어댑터 **계약** · 가짜 TUI 로 계약 테스트 | 사내 TUI 어댑터 구현 · KIT-1 · KIT-2 를 사내 PC · 사내 TUI 판으로 다시 · 사내 모델 이름 · 사전 · 정규식 설정 · 사내 PC 에서 전체 테스트 · 코드 최종 검토 |

- 어댑터 계약 [제안 — T6]: `name` · `check() → 결과 (effort 를 받는지 포함)` · `put(id, sealed_text, route)` · `get(id) → 답 또는 없음`. `route` 는 모델 · effort 두 값뿐이다. 어댑터는 봉인된 글만 받는다 — 원문 · 가명 표에 닿는 인자가 없다. 계약 테스트를 통과해야 설정에서 고를 수 있다.
- 사내 이름이 들어간 것 (어댑터 설정 · TUI 이름 · 모델 이름) 은 `.gitignore` 로 막힌 `adapters.local\` 또는 데이터 폴더에만 둔다. 공개 저장소로 되돌아오는 것은 사내 이름이 없는 일반 코드뿐이다 (W-12 · R17).
- **검토 세션의 자리**: 사내 Claude 로 다이오드 코드를 검토할 때는 `D:\OPENCODE\diode` 에서 연다. 저장소 루트 (`D:\OPENCODE`) 에서 열지 않는다 — 루트 아래에는 데이터를 프로그램 폴더에 두는 앱이 있다 (Secretary–1 · 예외 대장 W-06 · 일정과 설정). 검토 세션에도 안전벨트를 켠다 (L-20).
- 검토 대상은 공개 코드뿐이고 사내 월 한도 안에서 한다. 사내에서 고친 일반 코드를 공개 저장소로 되가져올 때는 diff 를 사람이 한 줄씩 본다.

### Claude Code 안전벨트 (방 밖 세션 · M1 — Q8 · 7판: 플러그인 훅의 '그 밖' 모드)

[문헌: Claude Code hooks 문서 2026-11-05] 방 프로필이 방 안의 벽이라면, 안전벨트는 사용자가 방 밖에서 연 모든 세션에 거는 사용자 설정이다. 사내 TUI 가 Claude Code 일 때만 걸 수 있다.

- `UserPromptSubmit` 훅 → `diode scan` (D2 · D3 · D5). 걸리면 종료 코드 2 로 막는다 — 문서는 "프롬프트가 Claude 에 닿지 않는다" 고 적는다.
- `PreToolUse` 훅 (Read · Grep · Glob · Bash · Edit · Write · WebFetch) → 깨끗한 작업 폴더 밖을 건드리면 deny. 훅은 보조이고 "단단한 허용 · 거부는 권한 체계로" 라는 문서 권고대로 권한 deny 규칙을 같이 둔다.
- 훅 실패를 막는 쪽으로: `onFailure: "block"` (v2.1.295 이상) — 없으면 시간 초과한 훅이 도구 호출을 통과시킨다 [문헌]. 사내 PC 의 Claude Code 판을 KIT-2 에서 확인한다.
- 사용자가 훅을 끄지 못하게 하려면 관리형 설정 (`allowManagedHooksOnly`) 이 필요한데 관리자 권한이 든다 — W-08 이 금지하므로 이 도구는 하지 않고, 회사 IT 에 줄 설정 안내만 MANUAL 에 둔다.
- 못 막는 것: 웹 Claude (claude.ai) 에 붙여 넣기 · 다른 PC. 교육과 회사 DLP 의 몫이다.

```text
작업 폴더 = 빈 임시 폴더 · 입력 = 표준 입력 (명령줄 인자는 프로세스 목록에 보인다)
```

- `--system-prompt-file` 로 기본 시스템 프롬프트를 통째로 바꾼다 — 기본 프롬프트에 작업 폴더 경로 같은 환경 정보가 들어가는지 [미확인] 를 KIT-1 에서 보고, 들어가면 이 교체가 필수다.
- `--bare` 만으로는 안 된다 — 문서가 "Bash · 파일 읽기 · 편집 도구는 남는다" 고 적는다 [문헌].
- 회사 게이트웨이가 Anthropic 호환 주소를 직접 준다면 표준 라이브러리 `urllib` 로 부르는 갈래도 있다. 바깥으로 가는 바이트를 가장 정확히 쥐는 길이다.

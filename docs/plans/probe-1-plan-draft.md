## 00 한 장 요약

- **무엇**: 공정 데이터를 Spotfire 처럼 그리고 · 거르고 · 계산하는데, 옆자리 LLM 이 조작을 대신하고 (조작 대행), 내 주장에 동의 · 반대를 계산 번호 (`c014`) 로 말하고 (책사 — 숫자는 코드인 계산관이 만든다), 확정한 것만으로 그림 달린 보고서를 엮는 (서기) 내 PC 전용 웹형 works 앱.
- **누구**: Windows 사내 PC 에서 혼자 결론까지 가고, 그 결론으로 남을 설득해야 하는 반도체 공정 엔지니어 한 명. 데이터 3천–2천만 줄 · 30–50열 · CSV 3GB 안. 사내 LLM (OpenAI 호환).
- **핵심 결정 3개**
  1. **엔진은 DuckDB 하나 · 버전 하나 — 필수 의존성이라고 밝힌다.** W-02 는 한 항목 규칙 PR 로 열고, 엔진이 없으면 분석이 안 된다는 사실을 대장 · README 에 그대로 적는다. 선택 기능 조문 우회 · 엔진 두 벌 · 예외 대장은 쓰지 않는다. 버전은 M0 에서 사용자 PC 의 Python 으로 고르고, 식 컴파일러는 어느 버전에서도 뜻과 속도가 같은 '지루한 SQL' 만 낸다.
  2. **숫자 · 등급 · 그림은 결정적 코드, LLM 은 조작 고르기와 문장만.** 등급 문턱은 숫자로 보이고 사용자가 바꾼다. M1 에서 LLM 조작은 모두 제안 카드 (Enter 한 번) 이고, 한 단계 조작은 문형 해석기가 LLM 없이 바로 한다. 그림은 서버가 한 벌로 그려 화면 · 보고서 · PPTX 가 같다.
  3. **코드 전에 정찰, 그다음 LLM 없이도 남는 뼈대부터.** 모르는 것 여덟 (실행 허가 · 사내 LLM 품질 · 설치 · 2천만 줄 속도 · 브라우저 그리기 · 그림 반출 · 반출 정책 · 범위) 을 M0 에서 사용자 PC 로 잰다. 문턱은 결과를 보기 전에 적고, LLM 품질은 점이 아니라 구간으로 판정한다. M1 은 b1 (LLM 없는 뼈대 — 어느 가지로 가도 남는다) 과 b2 (LLM) 로 나눈다.
- **추천**: 14 › Q1 (W-02 길) · Q2 (반출 · 실행 정책) 답을 먼저 받는다 › 대장 '예정' PR · W-02 규칙 PR (M0 첫 주) › 정찰 키트와 Spotfire 골든을 사용자 PC 에서 › 그 뒤에야 코드.
- **첫 마일스톤 M0 정찰** (2–3주 [추정] · 앱 코드 0줄): 판정표 13줄이 다 차고 가지 · 엔진 버전 · 도구 수 · 반출 단계 · 새 판 반입 길을 고르면 합격. 사용자는 자기 데이터로 그린 그림 세 장 (상자 · 웨이퍼 맵 · 추세) 을 손에 쥔다. 다음 M1-b1 은 가져오기 › 상자 · 산점도 · 웨이퍼 맵 · 추세 › 필터 · 마킹 › 판정 카드 › HTML 보고서 · PNG 복사 › 다시 열기를 LLM 없이 잇는 뼈대다.
- **솔직한 한계**: 'Spotfire 완벽' 은 한 번에 못 한다 — P0 은 사용자가 '자주' 로 고른 조작이다. 2천만 줄 × 50열은 CSV 약 6.6GB [추정] 라 '3GB' 와 동시에 못 맞춘다. 사내 PC 에서 잰 숫자는 아직 하나도 없고, 일정은 b1 을 만들어 본 뒤에야 믿을 만해진다.

## 01 문제 정의 · 목표 · 비목표

### 문제

- Spotfire 는 손이 되어 주지만 말벗은 아니다. "그거 제품 구성 차이 아니야?" 라고 물어 줄 사람이 없다. 결론까지의 시간이 고독하다 (사용자 말).
- 혼자 결론을 내면 세 가지가 샌다.
  - 훑다가 우연히 걸린 1등을 발견으로 착각한다 — 장비 50 × 스텝 100 을 훑으면 효과가 하나도 없어도 α 0.05 에서 거짓 양성이 평균 250개다 [추정: 계산].
  - lot · 시간 · 제품 구성에 섞인 착시를 놓친다 — 교란 · 심슨 · die 행을 독립 표본으로 센 p 값.
  - 남을 설득할 그림과 예상 질문 준비가 분석과 따로 노는 일이 된다.
- LLM 채팅 창을 옆에 띄우면 세 가지가 안 된다: 데이터를 못 보고 · 숫자를 지어내고 · 맞장구친다. 2천만 줄에서는 작은 차이도 다 '유의' 해서 맞장구는 해롭다.

### 진짜 문제 — 모르는 것

- 사내 정책이 이 앱 (공개 저장소 코드 · 네이티브 바이너리 · 로컬 서버) 을 돌리게 하는지 · 사내 LLM 이 도구를 제대로 부르는지 · 사내 PC 에 엔진이 깔리는지 · 사내 PC 가 2천만 줄을 견디는지 · 사내 정책이 무엇을 내보내게 하는지 — 다섯 다 [미확인] 이다. 하나라도 빨강이면 설계가 바뀐다. 그래서 목표 T0 을 둔다: 설계를 바꿀 사실은 코드를 쓰기 전에 안다.

- `LOAD` 가져오기 · 역할 확정. `ANALYZE` 보고 · 묻고 · 따진다 (기본). `STORY` 발견 카드 · 보고서 조립 · 내보내기. 모드 사이는 라임 와이프. F 키 = 그림 하나 크게 — 빽빽해진 분석 화면을 원칙 1 쪽으로 되돌리는 탈출구.

+---------------+----------------------------------------------+---------------------------+

+---------------+----------------------------------------------+---------------------------+

### 반도체 특화

- M1: 역할 태그 (키 · 시간 · 범주 · 측정 · 규격 · 좌표 · 빈) — 태그가 없으면 그 태그가 필요한 검사는 `‼` 로 멈춘다 · lot 수준 접기가 기본 (K-04 · lot 요약 표 3,200묶음 0.148s [실험]) · 상자 위 lot 점 · 제품 · 주 교란 (K-05) · 효과를 σ 와 스펙 폭 대비 % 로 (K-13) · 웨이퍼 맵 v0 (die 평균 · 불량률 한 장).
- M2: 웨이퍼 맵 — 다이 격자 맞춤 · 원천별 노치 방향 메타 · 가장자리 제외 고리 · 존 반경 0–0.5 · 0.5–0.8 · 0.8–1.0 [추정 · 설정값] · 겹친 맵 · 갤러리 · 빈 하나 선택. 공통성 표 (나쁜 lot 마킹 › 스텝 × 장비 순위 · 칸 수가 탐색 장부로) · 이벤트선 (PM · 레시피 변경) · Cp · Cpk (군내 σ) 와 Ppk (전체 σ) 를 섞지 않고 둘 다 — 어느 σ 인지 계산 명세에 · lot 정규화 틀 (쓰면 책사가 K-05 주의를 붙인다) · 중복 키 정책 (재측정 · rework · 재테스트: 첫 값 · 마지막 값 · 평균을 고르고 조작 기록에).
- M3: SPC (I-MR · Xbar-R · EWMA λ 0.2 · L 3 · WE 규칙 · Nelson 선택) · 장비 매칭 TOST (허용 차 Δ 는 사용자가 정한다) · split lot 짝 비교와 별칭 (K-11) · 이벤트 전후 (K-14). P2: 골든 프로파일 유사도 · K-평균.

### 식 언어 v1 (Spotfire 문법의 부분집합 › SQL)

- 목표: 예전 Spotfire 분석의 식을 붙여 넣으면 v1 범위 안에서는 그대로 돈다. 안 되는 함수는 위치에 밑줄을 긋고 비슷한 함수를 보인다.
- v0 (M1): `+ - * / ^` · 비교 · `and or not` · `in (…)` · `If()` · `Case when … then … else … end` · `is null` · 수학 `Abs Round Sqrt Ln Log10 Exp` · 집계 `Sum Avg Count Min Max Median StdDev` · OVER `[열]` · `Intersect(…)` · `All()`.
- v1 (M2) 에 더함: 집계 `UniqueCount Var StdErr Q1 Q3 P10 P90 Percentile` · 수학 `Power Floor Ceiling Mod Sign` · 문자 `Upper Lower Trim Len Left Right Mid Concatenate Find Substitute RXReplace RXExtract` · 날짜 `Year Month Day Hour Week DayOfWeek DateAdd DateDiff` · 형 `Integer Real String DateTime ParseDateTime SN` · 순위 `Rank DenseRank` · 구간 `BinByEvenIntervals BinBySpecificLimits BinByDateTime` · OVER `AllPrevious([정렬 열])`. 합계 함수 57개 · OVER 4꼴.
- 넣지 않는 것: `DateTimeNow` · 난수 · `First` · `Last` — 순서 없는 표에서 값이 바뀌어 같은 계산 번호가 다른 값을 낸다. P1: `Previous` · `Next` · `LastPeriods` · `Parent` · `Axis.*` 문맥 OVER · `THEN` · 문서 속성 `${…}`.
- 계산 문맥 — Spotfire 와 뜻이 같아야 하는 핵심: 계산 열 = 필터 · 마킹을 무시한 전체 행 · 그림 축의 사용자 식 = 필터 뒤 행 · OVER 범위는 그 문맥 안. Spotfire 가 이렇게 하는지 [미확인] — M0 의 Spotfire 골든 (Q4) 으로 확인한다. 어긋나면 'lot 평균 대비 편차' 같은 매일 쓰는 식이 필터를 걸 때마다 다른 숫자를 낸다.
- 집계 규칙: 계산 열에서 OVER 없는 집계는 '전체' (`OVER ()`), 그림 축에서는 묶음 집계 — AST 단계에서 가른다 (프로토타입이 '집계 안 창 함수' 오류를 내며 드러난 함정 [실험]).
- 원칙: 열은 스키마에 있는 이름만 인용 · 문자열은 늘 `?` 매개변수 · 함수는 허용 목록만 · 오류는 위치와 함께 · 없는 열은 비슷한 이름 제안. 표준 라이브러리 프로토타입 173줄이 주입 시험 (닫는 괄호 뒤 `DROP TABLE` 류는 거부 · 문자열은 매개변수라 무해) 을 통과했다 [실험].
- 의미 표 (편집기에 표시): 표본 · 모집단 표준편차 · 분위 보간 방식 · 짝수 n 의 중앙값 · NULL 이 섞인 집계와 비교 · 주 번호와 요일 시작 · 정수 나눗셈 (DuckDB `7/2` 는 3.5 [실험]) — Spotfire 쪽 뜻은 모두 [미확인]. 숫자가 1% 만 달라도 신뢰가 깨지므로 다를 수 있는 곳을 숨기지 않는다 (원칙 4).
- M2 합격: P0 함수 · OVER 꼴 전부가 Spotfire 골든과 표시 자릿수에서 일치하고, 다른 것은 의미 표에 까닭과 함께 올라 있다. 골든을 못 받으면 목표를 '붙여 넣으면 돈다' 에서 '이름이 같은 함수' 로 내린다.

## 06 LLM 협업 설계

### 역할 넷 — 누가 숫자를 만드나

| 역할 | 누가 | 한다 | 못 한다 |
|---|---|---|---|
| 조작 대행 | LLM | 말을 조작 도구 호출로 바꾼다 (M1 은 모두 제안 카드) | 확인 없이 적용 · 밖으로 내보내기 |
| 계산관 | 결정적 코드 (엔진 · 판정 모듈) | 모든 숫자 · 검사 · 등급 · 계산 번호. LLM 은 무엇을 계산할지만 고른다 | — |
| 책사 | LLM + 코드 | 사용자 문장을 주장 꼴로 (칩으로 보이고 사용자가 확정) · 검사 결과를 말로 · 반론과 다음 수 고르기 · 그림 고르기 의논 | 등급 올리기 · 숫자 만들기 |
| 서기 | LLM + 코드 | 확정한 일지로 발견 카드 · 캡션 · '오늘의 논의' 요약 · 보고서 문장 초안 | 근거 없는 줄 (`ERR`) 확정 |

- 모델은 하나다. 역할마다 시스템 프롬프트와 도구 묶음만 다르다. 서기는 도구 호출이 아니라 줄 JSON 을 받는 요청이다 (Report–1 의 초안 방식) — 보고서 초안은 절마다 한 요청 (`max_tokens` 기본 2048 안) 이고, `finish_reason=length` 면 그 절만 다시 부른다.

- 사용자만 (도구가 아니다 · 등급 3): 파일 쓰기 (보고서 · CSV 저장) · 원시 행 보내기 (카드마다 20행까지) · 대화 보관 · 반출 단계 바꾸기 · 캐시 지우기. LLM 은 "행 20개를 보면 빨라집니다 — [행 보내기] 를 눌러 주세요" 처럼 말로만 청한다.
- 조인 · 행 빼기 · 값 바꾸기는 M2 에서 화면 조작으로 먼저 낸다. 도구로 열지는 빈칸 장부 횟수로 정한다 (상한 14 에 한 자리가 비어 있다). `query_sql` (읽기 전용 SELECT 하나 · 200행 · 10s · `json_serialize_sql` 검사 등 네 겹 [실험]) 은 M5 에서, 시험지 SQL 문항을 넘을 때만 같은 방식으로 넣는다.
- 도구 정의 크기: M1 6개 2,412자 · 전체 4,910자 (`edit_chart` 를 `make_chart` 에 합치기 전 14개 기준 · 한국어 설명 · 압축 JSON) [실험]. 약한 모델에 몇 개를 보일지는 M0 KIT-3 이 정한다 (11 › R1b). `apply_ops` 를 두는 까닭: json 모드는 한 단계에 도구 하나이고 Secretary–1 의 단계 한도는 6 이라 '필터 › 계산 열 › 피벗' 연쇄가 모자란다. 이 앱의 단계 한도는 8 [제안] 이고, 연쇄의 첫 결과가 화면에 뜰 때까지 p95 30s [제안] 를 KIT-3 에서 잰다.
- 시험지 (도구 호출 품질 관리): 약 110문항 · 합성 스키마 (15 › F). 채점은 결정적: 도구 이름 · 필수 인자 · 값 정규화 일치 · 없는 열 0 · 식은 AST 정규화 · 주장 꼴은 칸마다. 출력은 점수 · 구간 · 지연 p50 · p95 · 형식 오류 수 · json 전환 횟수뿐이고 응답 원문은 메모리에서 버린다 (W-05 · W-12). M0 · M1 은 KIT-3, M2 부터 `probe-1.py --exam` — 모델을 바꿀 때마다 다시.
- 판정은 점이 아니라 Wilson 95% 구간이다 (11 › R1). 20문항에서 16개 (80%) 를 맞혀도 구간이 58–92% 라 초록과 빨강이 겹친다 [추정: 계산]. 같은 문항의 반복은 독립 표본이 아니라서 구간은 문항 수로 내고, 3회 반복은 문항마다 다수결과 '흔들린 문항 수' 로 쓴다.

### 빠른 길 · LLM 없는 모드 (M1)

- Spotfire 에서 '챔버별 PARAM_05 상자' 는 클릭 세 번 · 3초다. `stream: false` LLM 의 p95 20s 로는 못 이긴다. 그래서 LLM 앞에 결정적 길 둘을 둔다: 축 칸마다 열 고르기 목록 (Spotfire 축 선택기 꼴) · 결정적 한국어 문형 해석기 — `<범주>별 <측정> 상자 · 추세 · 맵` · `<값> 만` · `<값> 빼고` 꼴, 열 이름은 스키마와 대조. 맞으면 LLM 없이 바로 그린다 (반출 0 · 지연 0 · 사용자 자신의 조작이라 바로 적용 + 되돌리기). 안 맞을 때만 LLM 으로 넘긴다. Ctrl+K 빠른 명령도 같은 해석기다.
- LLM 은 연쇄 · 판정 · 문장 · 바꿔 말한 요청에 쓴다. 그래서 시험지의 A · B 묶음은 해석기가 못 받는 바꿔 말하기만 담는다 (15 › F).
- LLM 없는 모드: 모든 조작은 화면과 문형 해석기로 된다. LLM 은 같은 도구를 부를 뿐이다. 판정 카드는 검사표 + 고정 문장, 주장 꼴은 화면 양식, 보고서는 확정 카드 + 틀 문장 (Report–1 의 '기본 초안' 선례), '오늘의 논의' 는 일지에서 뽑은 틀 문장 — M1-b1 이 곧 이 모드이고 시험 대부분이 이 모드로 돈다. 가지 B (조작 대행 끔) 는 도구를 `describe_data` · `compare_groups` · `propose_finding` 셋만 두어 책사 문장과 서기만 남긴다.

### 위험 등급과 적용 방식

| 등급 | 무엇 | 적용 |
|---|---|---|
| 0 읽기 | 요약 · 비교 · 검사 | 묻지 않는다 |
| 1 보기 바꾸기 | 그림 · 필터 · 마킹 · 선 | M1: 제안 카드 (점선 미리보기) › Enter 한 번. M2: 즉시 수락 비율이 2주 동안 80% [제안] 이상이면 바로 적용 + 되돌리기 초읽기 (손 쉼 0.4s · 판 번호) 로 올린다 |
| 2 데이터 뜻 바꾸기 | 계산 열 · 피벗 · 언피벗 · 구간 · 발견 카드 | 제안 카드 (점선 미리보기) › Enter · Esc |
| 3 밖으로 | 파일 쓰기 · 원시 행 · 보관 | 사용자 단추만 — 늘 미리보기 › 확정 (W-07 · W-03 · W-05) |

- 되돌리기는 조작 스택이고 M1 은 맨 위부터만 (선형) 되돌린다. 사용자와 LLM 조작이 한 스택에 쌓인다. LLM 조작 하나만 골라 되돌리기 (뒤에 기대는 조작 목록 — 곧 의존 그래프) 와 판 번호 충돌 처리는 P1 이다. 파이프라인 단계는 VIEW 라서 되돌리기 비용이 0 이다. 처음 안은 '바로 적용 › 되돌리기 30% 를 넘으면 제안으로 내림' 이었다. 그러면 손 쉼 · 판 번호 · 공용 스택 · 선택적 되돌리기 같은 협업 편집기 수준의 상태 문제가 M1 에 한꺼번에 들어온다. 순서를 거꾸로 해 측정 뒤에 올린다.

### 근거 id 와 숫자 검증

- 결정적 결과마다 계산 번호 `c` + 앞자리 0 세 자리 (`c014`). 장부에 남기는 것: 명세 JSON · 컴파일한 SQL 의 sha256 · 데이터 판 (원본 sha256 앞 16자 + 그 단계까지 파이프라인 해시 + 필터 · 마킹 조건 해시 또는 키 목록 해시) · 엔진 버전 · 값 요약 (50행까지 · 메모리 — 09). 같은 열쇠면 다시 쓴다. 엔진 버전이 다르면 새 번호에 '엔진이 바뀌어 다시 계산' 을 붙인다. 부동소수 합의 끝자리는 버전 사이에도, 같은 버전의 실행 사이에도 흔들렸다 (lot 별 표준편차 합 …2673 · …2674 [실험]). 그래서 값 대조는 비트가 아니라 표시 자릿수로 한다.
- LLM 문장은 줄 JSON `{text, refs[], numbers[{text, calc}]}` 로 받는다 (Report–1 의 줄 모델 + 숫자 칸). 서버가 숫자를 뽑아 대조한다:
  - 대조 대상은 `numbers[]` 에 적힌 숫자, 그리고 서수 (두 번째) · 앞으로의 기간 (다음 2주) · 순위 (상위 5개) 표현 사전으로 거르고 남은 숫자다. lot · wafer · 장비 수는 거르지 않는다 — 판정에 쓰인다 (K-03). 사전은 시험지와 함께 자란다. 식별자 속 숫자 (EQP_07 · STEP_010 · LOT00001 · c014) 는 스키마의 값 목록으로 걸러 대조하지 않는다.
  - 값 · 반올림 자리 · 단위로 맞춘다 — % 는 ×100 도 본다 · σ 단위 · `1.5e3` 과 `1,500` 은 같은 수. 인용한 계산 번호의 값과 문장 숫자가 다르면 값이 우연히 같은 다른 번호가 있어도 `숫자?` 다.
  - 안 맞으면 `숫자?` 칩 · 사실 줄에 refs 가 없으면 `ERR` (확정을 막는다). 확정 때 서버가 다시 판정한다 (화면을 믿지 않는다).
- 대조기 품질은 따로 잰다: 라벨 붙인 합성 문장 200개에서 `숫자?` 오탐 5% 이하 · 가짜 LLM `lie` · `number` 의 틀린 숫자 미탐 0 · 인용 값 불일치 미탐 0 [제안]. '숫자 100% 가 계산 번호나 `숫자?`' 는 검사기의 정의라 늘 참이어서 품질 지표로 쓰지 않는다. 07 METER 에 최근 판정의 `숫자?` 비율을 보인다 — 오탐이 잦으면 사용자가 칩을 무시한다. 끌고 있는 동안의 표본 · 근사 값은 계산 번호를 받지 못한다. 근거가 될 수 있는 숫자는 전체 데이터로 정확히 계산한 것뿐이다.

### 판정 형식 — 등급은 코드가

| 등급 | 조건 (코드가 검사 결과로 · 낱말의 문턱은 아래 표) | 말머리 (고정) |
|---|---|---|
| 강함 | 필수 검사 모두 √ · lot 수준 차가 질문 묶음의 α/m (Bonferroni) 를 넘어 살아남음 · 층화 뒤 방향 유지 · 실무 효과 · 시간 나눔 재현 (M1) 또는 사전 등록 · 가린 홀드아웃 (M3) · (인과 표현이면) 시간 순서 맞음 | 동의합니다 |
| 보통 | 필수 검사는 통과했지만 α/m · 재현 · 메커니즘 중 하나가 없거나, 좁힌 범위에서만 성립 | 대체로 동의합니다. 다만 … |
| 약함 | 행 수준에서만 유의 · 훑기 뒤 재현 안 됨 · 효과가 실무 효과 문턱 아래 | 아직 동의하기 어렵습니다 |
| 반대 | 층화 뒤 방향이 뒤집힘 · 검정력이 충분한데 lot 수준 차 없음 · 동등성 (TOST) 입증 · 시간 순서가 거꾸로 | 동의하지 않습니다 |
| 판단 보류 | 그 판에 있는 필수 검사를 데이터 때문에 못 돌림 — 역할 태그 없음 · n 부족 · 별칭 · 데이터 결함 (K-01 · K-02) | 판단을 미룹니다. …가 먼저입니다 |

| 낱말 | 기본 문턱 [제안] |
|---|---|
| 실무 효과 | lot 평균 차가 lot 간 σ 의 0.5 이상, 또는 스펙 폭의 5% 이상 — 측정마다 덮어쓴다 |
| 검정력 충분 | 그 실무 효과에서 lot 수준 검정력 0.8 이상 — 정규 근사로 결정적으로 계산 (순열 검정의 근사) |
| K-03 최소 크기 | 묶음마다 lot 5개 이상 |
| K-05 교란 | 비교 묶음 사이 제품 (또는 주) 구성 차가 20%p 이상이면 층화 필수 |
| 층화 뒤 방향 유지 | 층 가중 평균 차와 부호가 같은 층이 2/3 이상 |
| 시간 나눔 재현 | 뒤 30% 기간의 lot 에서 같은 방향 · p < 0.05. 사용자가 이미 본 데이터라 진짜 홀드아웃이 아니다 — 가린 홀드아웃은 M3 (A-05) |
| m (다중 비교) | 그 질문 묶음의 탐색 장부 (A-06) |

- 문턱은 판정 카드에 보이고 사용자가 바꿀 수 있다. 바꾼 사실 (전 · 후 값) 은 보고서 3 절에 남는다. 보이지 않는 문턱 하나에 '반대' 가 좌우되면 사용자는 반론도 할 수 없다. 정답지는 코드보다 먼저, 이 문턱으로 사람이 손으로 정한 등급을 커밋한다 (13). 확신 (높음 · 중간 · 낮음) 도 코드가 정한다: 돌려서 통과한 필수 검사의 비율 · 효과 신뢰구간의 폭.
- 등급 상한: M1 의 '강함' 은 위 표의 α/m · 시간 나눔 재현 · 층화 뒤 방향이 모두 있어야 한다. 하나라도 없으면 '보통' 까지다. M3 의 BH-FDR (K-07) · 사전 등록 (A-05) 은 이 조건을 넓힌다. 처음 안의 'M1 · M2 는 무조건 보통 상한' 은 장비가 확실히 고장 난 사례에도 '대체로 동의' 만 말하게 해서 버렸다 — 늘 유보하는 책사는 아첨하는 책사만큼 빨리 무시된다.
- 주장 꼴별 필수 검사: 그룹 차 K-01 – K-07 · K-10 · K-13 · 시간 · 이벤트는 + K-08 · K-14 · split · DOE 는 + K-11 · 맵은 + K-15 · 인과 표현 ("때문에" · "올린다") 은 + K-12. M1 의 필수 검사는 K-01 · K-03 · K-04 · K-05 · K-07 (Bonferroni 판) · K-13 여섯이다. 아직 만들지 않은 검사는 `⊠` 로 보이고 판단 보류의 까닭이 되지 않는 대신 '강함' 을 막는다.
- 코드가 LLM 에 넘기는 판정 (숫자는 지어낸 값):

```json
{"claim": {"id": "h01", "measure": "PARAM_05", "group": "EQP_07·C", "direction": "높다", "scope": "PRD_B", "level": "lot", "confirmed": true},
 "falsifier": "PRD_B 안 lot 평균 차가 0 이거나 반대면 틀림", "looks": 12, "grade": "보통", "confidence": "중간",
 "checks": [{"id": "K-04", "state": "√", "calc": "c021"}, {"id": "K-05", "state": "√", "calc": "c024"}, {"id": "K-07", "state": "×", "calc": "c025", "note": "p 0.03 > 0.05/12"}, {"id": "K-14", "state": "⊠"}],
 "missing_for_strong": ["K-07 α/m", "시간 나눔 재현"], "thresholds": {"effect_sigma": 0.5, "spec_pct": 5, "min_lots": 5}, "effect": {"calc": "c021", "sigma": 0.6, "spec_pct": 2.1},
 "counter": [{"from": "K-14", "text": "PM 이력이 없어 시간 안정성을 못 봤다"}], "next": ["PM 이력 붙이기", "다음 2주 자료로 같은 비교"]}
```

- LLM 의 답은 `{"grade": "<입력 이하>", "lines": [{"text": "…", "refs": ["c021"]}], "counter_from": ["K-14"], "next": ["…"]}` 이다. LLM 은 `grade` 를 올리거나 `checks` 를 바꾸지 못한다. 카드 순서: 주장 재진술 › 가설 · 반증 조건 › 검사표 (`√` 통과 · `×` 실패 · `⊠` 못 돌림 = 할 일 · `‼` 사용자 확인 필요 · `◐` 계산 중 — 기호의 뜻은 DESIGN › 03 그대로) · 문턱 › 등급 · 확신 › 반론 (M3 부터 반론 그림) › 다음에 볼 것.
- 두 번 그린다: 검사표는 계산이 끝나는 대로, LLM 글은 도착하면. LLM 이 늦거나 실패해도 카드는 고정 문장으로 선다. 반론은 실패하거나 못 돌린 검사에서 고른다. 다 통과했으면 반증 조건을 쓴다 — 허수 반론을 지어내지 않는다. 사용자가 책사와 다르게 결론 내려도 막지 않는다. 그 발견에 '사용자 판단 · 책사 반대' 가 붙어 검토판 보고서까지 간다 (배포판은 08). 결정은 사람이 하고, 기록은 남는다.

- 검사는 결정적 코드가 하고 제안 카드로 낸다 (b1 은 고정 문장). LLM 은 왜 바꾸면 설득에 나은지를 한 줄로 말한다 (b2). M1 부터 상자 그림의 기본이 lot 점 + n 이라 G-02 · G-07 의 절반은 기본 그리기가 맡는다. 그림 수정은 `make_chart` 에 `id` 를 주면 된다. M3 부터 반론마다 반론 그림 한 장이 제안 카드로 붙는다 — 책사는 말이 아니라 그림으로도 반대한다.

### 맥락 예산

- 단위는 글자 하나로 쓴다 (토큰과 섞지 않는다). 한 요청 = 고정 규칙 + 도구 정의 (2.4–4.9천 자 [실험]) + 열 목록 (이름 · 형 · 역할만 — 50열 약 1.3천 자 [추정]) + 지금 상태 (필터 · 그림 · 마킹 한 줄씩) + 결과 목록 (최근 계산 번호 20개 · 한 줄씩) + 대화 요약 + 최근 3턴 원문. M1 기본 구성 (도구 6 · 30열 · 결과 20줄) 은 약 8천 자다 [추정: 도구 정의만 실험값] — 가짜 LLM 시험으로 재서 MANUAL 에 표로 적는다.
- 열의 통계 요약은 늘 보내지 않고 `describe_data` 로 필요할 때 부른다. 2천만 줄 `SUMMARIZE` 가 16.7s (threads 2 · 2GB 면 33.8s) [실험] 라 가져올 때 한 번 계산해 둔다. 결과 목록을 늘 다시 넣는 까닭: json 모드는 이전 턴의 도구 결과를 버린다 (Secretary–1 의 대화 기록 방식). 번호와 한 줄 요약이 있어야 LLM 이 `c014` 를 계속 인용한다.
- 한도: KIT-3 에서 모델의 맥락 길이 (Q5) 와 글자 · 토큰 비를 재고, 맥락의 60% 를 글자로 바꿔 정한다. 그 전 기본은 20,000자 (Report–1 의 `budget_chars` 선례). 넘으면 오래된 턴부터 덜어 내고 열 목록은 덜지 않는다 — 덜면 책사가 있는 열을 모르고 '없는 열' 이라고 되묻는다. 그래도 넘으면 부르기 전에 거부하고 줄일 방법을 보인다. 07 METER 에 '보낸 글자 · 행 · 바이트'.

- 지금 고르지 않는 까닭: 사내 PC 의 Python 이 [미확인] 이고, 지루한 SQL 덕에 버전 선택의 비용이 INSTALL 한 줄 · CI 한 줄 · 캐시 이름 하나로 줄었다.
- 연결 정책 [실험]: 확장 자동 설치 · 불러오기 끔 · 가져오기는 그 파일 폴더와 데이터 폴더만 허용한 짧은 수명의 연결 (`allowed_directories` 는 연결 뒤에만 정할 수 있다) · 분석 연결은 `:memory:` + 사본 `ATTACH … (READ_ONLY)` + 세션 작업 파일 `ATTACH` › 허용 폴더 = 데이터 폴더 › `enable_external_access=false` › `lock_configuration=true`. 잠근 뒤에도 데이터 폴더 안의 ATTACH · DETACH · COPY TO 는 되고 밖은 막힌다 (1.2.2 · 1.5.6 [실험]) — SQL 은 식 컴파일러가 낸 것만 돈다.
- 설정: `threads` = 코어 수보다 하나 적게 · `memory_limit` = PC 메모리의 25% [제안] (`memory_limit` 은 RSS 상한이 아니다 [실험]) · `temp_directory` = 데이터 폴더 `tmp\`. `execute()` 만 쓴다 — `con.sql()` 은 오류 뒤 다음 문장이 'transaction aborted' 로 실패했다 [실험].

### 사본 수명 주기

- 같은 프로세스에서 사본을 읽기 쓰기로 연 연결이 살아 있으면 `ATTACH … (READ_ONLY)` 가 'Unique file handle conflict' 로 실패하고, 읽기 전용으로 붙어 있는 동안에는 읽기 쓰기 연결이 같은 오류로 실패한다 (1.5.6 [실험]). 그래서 '뒤에서 요약 만들기 · 읽기 전용 분석 · 실체화 · 깨지면 다시 만들기' 넷을 순서로 푼다.
  1. 가져오기 연결이 원본 표 · 열 요약 · lot 요약 표 · (100만 줄 넘을 때) 1% 표본 표를 모두 `.tmp.duckdb` 에 쓰고 닫은 뒤 바꿔치기한다. 그 전까지 화면은 가져오기 연결의 커서로 읽는다.
  2. 분석 연결이 사본을 READ_ONLY 로 붙인다. 붙은 뒤 사본은 바뀌지 않는다.
  3. 실체화한 계산 열 · 마킹 키 목록 · TEMP TABLE 은 사본이 아니라 `:memory:` (`memory_limit` 에 셈) 나 세션마다 만드는 `tmp\work-<id>.duckdb` 에 둔다 — 잠근 연결에서도 붙고 쓴다 [실험].
  4. 다시 만들기는 모든 커서 `interrupt()` › 분석 연결 닫기 › 새 사본을 `.tmp` 로 › 바꿔치기 (5회 · 200ms 재시도) › 새 분석 연결. Windows 는 열린 파일 위로 바꿔치기가 실패하고 백신이 막 닫은 큰 파일을 잡고 있을 수 있다 [미확인].
- 단일 실행 잠금 파일 (`probe-1.lock`) 로 두 프로세스가 같은 사본을 열지 못하게 한다. Linux 에서는 붙어 있는 파일 위 바꿔치기가 성공해 [실험] Linux 시험으로는 못 잡는다 — windows-latest 시험이 지킨다 (13).

### 가져오기 · 계산 열

- 인코딩: 첫 1MB 를 UTF-8 로 풀어 보고 BOM 으로 UTF-8 · UTF-16 을 알아본다. 첫 1MB 로 고른 UTF-8 은 잠정이다 — 앞 20만 줄이 ASCII 이고 뒤에 CP949 한 줄이 있으면 `count(*)` 는 지나가고 그 열을 읽는 순간 'Invalid unicode … Line 200002' 로 실패한다 (1.5.6 [실험]). 3GB 면 몇 분 적재한 뒤에야 실패한다.
- 그래서 적재와 나란히 표준 `codecs` 로 파일 전체를 UTF-8 검사하고 (3GB 14–28s [추정]), 어긋나거나 적재가 Invalid unicode 로 실패하면 적재를 끊고 CP949 변환 경로로 처음부터 다시 하며, 다시 한 까닭과 걸린 시간을 보인다. CP949 는 표준 `codecs` 증분 디코더로 UTF-8 임시 파일 (110–224MB/s [실험] · 3GB 면 14–28s 추가 [추정]). UTF-16 은 `encoding='utf-16'` 으로 바로 읽는다 (1.2.2 · 1.4.5 · 1.5.6 모두 확장 없이 [실험] · 이 지정이 없으면 실패). `latin-1` 은 머리글이 조용히 깨져 금지.
- 구분자 · 형: 탭은 자동 감지 [실험] · 세미콜론 · `nullstr` · `decimal_separator` 지원 · 기본 표본으로 형 추론 › 표본 밖 형 충돌 (6만 번째 행에만 있는 `ERR`) 이면 그 열만 VARCHAR 로 다시 › '숫자로 바꾸기' 제안 카드 (TRY_CAST 로 빠지는 줄 수를 미리).
- 가져오며 만드는 것: 열 요약 · lot 요약 표 (K-04) · 1% 표본 표 (100만 줄 넘을 때만 · 끌고 있는 동안 미리보기용 · M2 — 질의마다 `USING SAMPLE 200000 ROWS` 는 매번 전체를 훑어 0.90s [실험]). 모두 수명 주기 1 에서 같은 사본에 쓴다.
- 계산 열은 VIEW 가 기본이다 (2천만 줄 OVER 계산 열 VIEW + 그룹 0.209s [실험]). 질의 하나가 300ms 를 넘거나 여러 그림이 쓰면 작업 파일로 '실체화' 를 제안한다.

| 문자 상수 · 열 이름 | `?` 매개변수 · 스키마에 있는 이름만 인용 | — | 문자열 이어 붙이기 |

- 원칙: 엔진의 편의 문법 대신 어느 버전에서도 뜻과 속도가 같은 모양을 낸다. 엔진을 올리는 PR 에서 바뀌는 것이 없게. 같은 값 확인 [실험]: 분위 · 회귀 기울기 · R 제곱 · 피벗 · 언피벗 결과가 두 버전에서 같았다. 부동소수 합의 끝자리만 흔들렸다 (06).
- 함정: 지루한 꼴의 뜻이 창 함수와 같은지는 골든에 기댄다 (NULL 키 · 중복 키 · 빈 묶음). 창 함수 결과와 맞대 보는 시험을 둔다 (13).

### 시각화 명세 · 그리기 · LOD — 서버가 한 벌로

- 한 그림 = JSON 하나. 명세 › 집계 SQL › 결과 (계산 번호) › SVG · PNG. 문서 · 조작 · 보고서 · PPTX 가 같은 명세를 쓴다.

```json
{"id": "v03", "kind": "box", "x": {"col": "CHAMBER"}, "y": {"col": "PARAM_05", "agg": "quantiles"},
 "color": {"mode": "select", "col": "CHAMBER", "value": "C"}, "trellis": null, "overlay": {"lot_points": true, "n": true},
 "lines": [{"kind": "spec"}, {"kind": "mean_ksigma", "k": 3}], "filter": "f07", "mark": "m02",
 "lod": {"raw_max": 5000, "density": 256, "quantile": "approx"}, "rev": 7}
```

- 왜: 그리는 코드가 한 벌이면 화면과 보고서가 한 점도 다르지 않다 — 설득에 쓰려면 이게 필요하다. unittest 골든으로 지키고, Flow–1 의 서버 SVG 선례가 있으며, 저장소에 `<canvas>` 선례와 시험 도구가 없다. 색을 서버의 토큰 표에서만 꺼내 검사기의 사각 (JS 계산 색) 도 생기지 않는다.
- 잰 값 [실험, CPython 3.11]: 점 5천 SVG 3.4–16ms · 234–309KB (gzip 45KB) · 밀도 256×256 PNG 16–17ms · 20KB · 512×512 PNG 인코딩 34ms · 12KB · 웨이퍼 맵 25장 7–9ms · 상자 12개 0.1ms. 3.8 은 더 느릴 것 [추정]. 브라우저 쪽 시간은 [미확인] › M0 KIT-4.
- 크기 구간 (10): 100만 줄 이하는 늘 정확값 · 끌고 있는 동안도 전체 · `근사` 칩 없음. 100만–1천만 줄은 아래 규칙. 1천만 줄 넘으면 표본 · 근사가 기본. 규칙: 점 5천 [제안] 이하면 SVG 점 · 넘으면 밀도 PNG (네이비 명도 8–16단 · 로그 눈금) · 확대하면 그 범위만 다시 구간화 · 상자 이상점은 묶음마다 위아래 200개 · 선은 픽셀 열마다 최소 · 최대 · 갈래가 25칸을 넘으면 페이지.
- 상자 그림 기본 (M1): 상자 (행 분위) 위에 lot 평균 점 (lot 하나 = 점 하나 · 겹치면 옆으로 흩음) + 상자 아래 n_lot · n_wafer. 판정 카드는 그림과 같은 수준 (lot) 을 가리킨다 — 행 분포는 갈라져 보이는데 판정은 '약함' 인 장면을 그림이 먼저 설명한다.
- 반응: 끌고 있는 동안 (슬라이더 · 줌 · M2) 은 1% 표본 표로, 놓으면 전체로 (2천만 줄 구간화 표본 0.014s · 전체 0.244s [실험]). 필터 뒤 표본이 2만 행 아래면 표본 대신 전체로 그린다 — lot 하나 (2.5만 행) 를 거르면 표본은 250행뿐이라 놓은 뒤 그림과 크게 달라 '즉각 반응' 이 오히려 오해를 만든다. 상자는 화면에서 근사 분위 (`근사` 칩), 판정 · 보고서는 정확값을 뒤에서 (2천만 줄 0.41s · 1.09s [실험]). 그림마다 '최신 요청만 산다' — 새 상태가 오면 돌던 질의를 `interrupt()` 로 끊는다 (약 1ms [실험]).
- 브라우저는 데이터를 그리지 않는다. 얇은 JS 겹침 층만 맡는다: 마킹 사각형 · 십자선 · 확대 상자 · 툴팁. 툴팁은 그림의 곁 JSON (표지 번호 › 묶음 키 · 축 변환) 으로 브라우저가 바로 띄우고, 밀도 칸만 멈춘 뒤 120ms 에 `/api/hover` 로 칸 요약을 받는다.
- 내보내기 그림은 늘 라이트 테마 · 2× 정수 배율 (글자 32px 단위) 로 서버가 다시 그린다. 다크 바탕 픽셀 글꼴 그림이 흰 바탕 사내 슬라이드에서 장난감처럼 보이지 않게 하고, Unifont 는 16px 정수배에서만 선명하기 때문이다 (DESIGN › 04). 그림 아래 근거 줄 (08) 을 같은 그림에 찍는다.
- PNG 복사 · PPTX 그림: 밀도 층은 이미 PNG 이고, 벡터 부분은 브라우저가 SVG › 화면 밖 canvas › PNG 로 옮긴다 (글꼴은 SVG 안 data URI) [미확인 › KIT-4 · R4b]. R4b 가 빨강이면 서버가 PNG 전체를 그린다 (글자는 Unifont 비트맵 부분집합). M0 에서 측정으로 가른다 (KIT-4 · Edge · SVG 5천 요소 넣고 그리기 p95): 100ms 이하 › 이대로 · 100–500ms › SVG 점 상한 2천 · 넘으면 PNG · 500ms 초과 › 점 층만 Canvas2D (명세 · 서버 집계는 그대로). M1 에서 사용자 PC 의 갱신 p95 가 1.5s 를 넘고 2주 안에 못 줄이면 같은 길로 간다.

### 마킹 · 필터

- 필터 = 열마다 조건 조각의 AND › `WHERE`. 조건 해시가 집계 · 그림 캐시의 열쇠다 (메모리 LRU). 필터 상태 한 줄 요약이 판정 카드 · 보고서 근거 줄에 붙는다 (K-09).
- 마킹은 그림의 수준에 따라 둘이다.
  - 원시 행 그림 (점 · 밀도 칸 · 웨이퍼 맵 die) 의 사각형 · 범주 · (M2) 올가미는 조건이 정본이다 (올가미 꼭짓점 64개 [추정]). 상세 표가 필요할 때만 rowid 를 뽑는다 (2천만 줄 0.433s [실험]). 연결된 그림은 `count(*) FILTER (WHERE 조건)` 으로 다시 센다 (0.209s [실험]).
  - 집계 그림 (lot · wafer · 범주 수준 — lot 평균 산점도 · 막대 · 상자 위 lot 점) 의 마킹은 마킹하는 순간 키 목록 (lot ID · 범주 값) 으로 굳힌다 (3,200 lot 이면 수십 KB [추정]). 조건으로 두면 뒤에 필터 · 계산 열 · 되돌리기가 바뀔 때 같은 조건이 다른 lot 을 골라, 사용자가 고른 '나쁜 lot 12개' 가 말없이 15개가 된다.
- 필터 · 계산 열이 바뀌어 조건 마킹의 행 수가 달라지면 00 PROBE 의 `MARK` 옆에 '마킹 바뀜' 칩을 띄운다. 계산 열을 되돌릴 때는 그 열을 쓰는 마킹 · 필터 · 그림 목록을 보이고 확정을 받는다. Spotfire 가 마킹한 행을 어떻게 고정하는지는 [미확인].
- 행 정체성은 DuckDB `rowid` — 원본 표는 가져온 뒤 바꾸지 않는다. `row_number()` 열을 만들면 적재가 2배가 된다 (2백만 줄 5.0s › 11.5s [실험]). 필터 패널 다시 세기가 가장 비싸다 (9백만 줄 범주 7열 + 숫자 30열 0.495s [실험]). 보이는 필터만 · 놓은 뒤에만 · 끊을 수 있게 센다. 커서 병렬은 거의 안 줄었다 (페이지 4개 0.285 › 0.251s [실험]) — 줄이는 수단은 병렬이 아니라 표본 · 근사 · 캐시 · 끊기다.

- 그림 아래 근거 줄 (M1): 데이터 (원본 이름 · 기간) · 필터 한 줄 · n (lot / wafer / die) · 집계 수준 · 검정과 효과 (σ · 스펙 %) · 계산 번호. HTML · PDF · PNG · PPTX 에 같은 글자로 찍힌다 — 칩이 기호로만 남는 출력물에서도 상사의 첫 질문 (몇 lot · 언제부터 · 무엇을 걸렀나 · die 로 셌나 lot 으로 셌나) 에 그림이 스스로 답한다.
- 근거 칩: 문장 속 숫자마다 계산 번호 칩 (올리면 명세 · 값 · 데이터 판) · 맞지 않으면 `숫자?` · 근거 없는 줄은 `ERR` (저장을 막음) · 사람이 고친 줄은 `직접` (Report–1 의 개념 · 코드 공유 아님).
- 검토판 / 배포판 (M2): 검토판은 등급 말 (동의합니다 · 책사 반대) 을 그대로 쓴다. 배포판은 등급 말 대신 근거 강도를 중립 문장으로 쓴다 (예: 'lot 수준 +0.6σ · 48 lot · 시간 나눔 재현 없음'). '확인하지 못한 것' 절은 배포판에도 남는다 — 결정은 사용자가 하고, 약점은 숨지 않는다. 사용자가 자기 보고서에서 '도구가 반대한 결론' 을 들고 가는 꼴을 피한다.
- 반론 절은 지울 수 없고 접기만 된다. 접었다는 사실이 부록에 남는다 — 설득용 보고서가 한쪽 말만 하지 않게. 설득은 반론을 먼저 꺼낼 때 강하다. 그림은 보고서를 만들 때 다시 그린다. 카드에는 명세 + 데이터 판만 두고 같은 `probe1_draw` 로 그린다. 데이터 판이 다르면 '원천이 바뀜' 으로 멈추고 묻는다.
- 세션 끝 '오늘의 논의' (M1 v0): 서기 한 번 호출로 요약 다섯 줄 (주장 · 바뀐 판단과 계산 번호 · 사용자 반대 · 남은 질문) › 미리보기 › 확정하면 일지에 (W-05 안). LLM 없는 모드는 일지에서 뽑은 틀 문장. [보관] 을 잊은 날의 논의도 이것으로 남는다.
- STORY 노브 (M4): ① 독자 (팀 · 팀장 · 경영진) ② 분량 (한 장 · 보통 · 자세히) ③ 어조 ④ 양식 — 목차 틀 · 독자별 다듬기는 M4 에 더한다. 대화 원문은 보고서에 넣지 않는다 — 확정한 발견 · 판정 · 요약만 넣는다 (W-05).

### W-05 확정 사건 — 무엇이 언제 디스크에 닿나

| 사건 (모두 사용자가 누른다) | 파일에 쓰는 것 |
|---|---|
| 조작 적용 (손 · 문형 · 제안 카드 Enter) | 파이프라인 · 페이지 · 계산 명세 (3초 모아 쓰기) |
| [잠금] | 주장 꼴 · 시각 · 반증 조건 — 사용자 문장에서 나온 글 |
| [남기기] | 그 판정 카드 (검사표 · 문턱 · 등급 · LLM 문장) |
| [확정] | 발견 카드 · 보고서 초안 |
| [보관] | 미리 본 대화 요약 |
| 세션 끝 미리보기 확정 | '오늘의 논의' 요약 · 체크한 판정 카드 |

- 사용자 문장 · LLM 문장 · 판정 카드 본문은 [잠금] · [남기기] · [확정] · 세션 끝 확정 전에는 메모리에만 둔다. 처음 실행 때 무엇이 저장되는지 보이고, 화면 오른쪽 위 '저장되는 것' 칸이 위 표의 지금 상태를 늘 보인다. 남기지 않은 판정 카드가 있으면 유휴 종료를 미룬다 (Report–1 선례). 검사기가 못 보는 조항이라 이 표가 리뷰의 근거다.
- W-06: 형식 버전 · `.tmp` 에 쓰고 바꿔치기 · 깨지면 `.broken` 으로 두고 새로 · 더 새 `format` 이면 덮어쓰지 않고 읽기 전용 (Report–1 의 JSON 문서 개념). 사본은 다시 만들 수 있으니 깨지면 원본에서 다시 가져온다. 사본 무효화: 원본의 크기 · 수정 시각이 바뀌면 sha256 을 다시 잰다 (2.66GB 2.47s — 쓴 직후 · 데운 캐시 [실험] · 차가운 디스크 · 네트워크 드라이브는 더 길다 [추정]) › 다르면 새 사본을 묻는다. 원본이 옮겨졌으면 분석 문서를 읽기 전용으로 열고 '원본 다시 잇기' 를 띄운다.
- 사본 한도 `cache_max_gb` 기본은 여유 공간의 25% 와 20GB 중 작은 값 [제안] · 오래 안 쓴 것부터 지우자고 제안 · `--status` 에 용량. 크기 [실험]: 2백만 줄 148MB · 9백만 줄 655MB · 2천만 줄 × 20열 395MB. 적재에는 CSV 크기의 3배 안팎의 여유가 있어야 한다 (변환 임시 · 넘침 · 사본 [추정]) — R3 이 디스크 여유를 본다.

## 10 성능 목표와 근거

- 목표는 사용자 PC 기준이고 모두 [제안] 이다 — M0 KIT-2 결과로 고친다. 아래 표의 측정은 모두 Linux 4코어 · 15GB · DuckDB 1.5.6 · 데운 캐시 · 질의는 중앙값 [실험] 이다. 사용자가 실제로 겪는 것은 재부팅 뒤의 첫 적재 · 첫 질의 (디스크 · 백신) 라서, 판정표 문턱은 차가운 첫 회와 질의마다 20회 반복의 p95 (KIT-2) 로 잰다.

- 크기 구간 (페이지 목표 [제안]): 100만 줄 이하 — 늘 정확값 · 끌고 있는 동안도 전체 · `근사` 칩 없음 · 표본 표 · lot 요약 표 안 만듦 · p95 0.2s / 100만–1천만 줄 — 놓으면 전체 · 상자는 화면 근사 · 판정은 정확 · p95 1s / 1천만 줄 넘음 — 끌고 있는 동안 표본 · 근사 기본 · lot · wafer 요약 표 · p95 2s. 3천 줄 데이터에서 '근사' 칩과 굼뜬 반응이 Spotfire 보다 의심스러워 보이지 않게.
- 2천만 줄은 두 벌이다: (가) 2천만 줄 × 20열 · 2.66GB 실제 CSV 를 만들어 적재 · (나) 9백만 줄 × 40열 표를 이어 붙인 표 (분포 복제 · 적재 시간 없음).

- 합성 공정 데이터 생성기 (`tests/synth.py` · 표준 라이브러리 · 씨앗 고정 · 지어낸 이름): CI 에서 3천 줄 · 20만 줄 판을 만든다. 함정을 심는다 — 진짜 효과 ('강함' 이 나와야) · 제품 구성 교란 · 심슨 · 시간 교란 · 유사 반복 (die 행) · 효과 없음 + 장비 50 × 스텝 100 훑기 · 서로 다른 질문 둘을 훑은 세션 (m 이 섞이면 실패) · 단위 섞임 · 필터 편향 · split 별칭 · 계측 장비 겹침 (MET_03) · 가장자리 고리 · 재측정 중복 키 · NULL 키 · CP949 머리글 · 20만 줄 뒤에만 있는 CP949 한 줄 · UTF-16 BOM 탭 파일 · 6만 번째 행에만 있는 형 충돌.
